# История изменений

Версия — **паспорт из чисел**: `1.0 · ядро 21 · файл 3 · мост 1 · модули 1 ·
оболочка 1` (машинно `1.0.21.3.1.1.1`). Релиз, ядро, файл, мост, модули и
оболочка ломаются по отдельности, поэтому и считаются отдельно. Правила роста и
хронология поколений ядра — [`docs/VERSIONS.md`](docs/VERSIONS.md).

До 1.0 версии не считались: набор возможностей менялся свободно, а совместимость
держалась миграциями на месте. Путь до 1.0 восстанавливается по `git log` и
документам `docs/PLAN-0.2.md` … `docs/PLAN-0.5.md`; поколение ядра при этом
посчитано задним числом — таблица в `docs/VERSIONS.md` §4.

## 1.0.21.3.1.1.1 — 2026-10-27

Первая версия с посчитанными версиями слоёв. Ниже — что в неё входит.

### Свет и объём

- Новый вид объекта **«Свет»** (`kind: "light"`): пятно поверх сцены вместо картинки.
  Формы — круг, сектор с углом, прямоугольник, треугольник, весь экран. Радиус,
  яркость, мягкость края, цвет в центре и у края (rgba), наложение обычное или
  аддитивное («свечение»). Отдельного «режима тени» нет: тёмный цвет затеняет,
  светлый подсвечивает.
- Свет — обычный объект сцены: слой, поворот, маска, прозрачность и вся вкладка
  «Поведение» работают как у спрайта. Обычное наложение ложится только на нарисованное
  (`source-atop`), поэтому в OBS на прозрачном фоне не появляется цветной прямоугольник.
- **Карта нормалей** (`normal`) у спрайтов и медиа: картинка или видео, сила объёма
  0…200 %, «карта играет». Объём считает проход освещения на **WebGL2**
  (`src/render/lighting.ts`): сцена уходит текстурой, объекты с нормалями — в буфер
  нормалей, шейдер считает наклон поверхности и добавку от светов (до 8 за кадр).
  Canvas 2D остаётся основным рендером; без WebGL2 объём просто не считается.
- **Мерцание света** в «Поведении»: синус или шум, глубина и частота. Пишется в
  `opacity`, новых параметров в ядре не требует.

### Поведение без кода

- **Следование за мышью**: предел **эллипсом** или **прямоугольником**, сила, мёртвая
  зона, сглаживание положения, переключатели осей и инверсия. Обе формы задаются
  шириной и высотой — полным размером области, поэтому объект ходит на половину.
  Включается именем модуля мыши; без модуля формулы не пишутся вовсе.
- **Инспектор переехал в правую панель вкладкой «Параметры».** Раньше он жил
  под сценой и делил с ней высоту: сцена получала около половины обзора. Теперь
  центр занимает только сцена, а поза, размер, слой, картинка, маска и пивот
  стоят второй вкладкой сразу после «Поведения». Горизонтальный разделитель
  «высота сцены и инспектора» убран, поле `sceneHeight` в раскладке больше не
  используется (старые сохранения читаются без ошибок).
- **Плашки-переключатели больше не растягиваются на всю панель.** Наложение
  света («свечение»), форма волны мерцания и режим пресета («только при» /
  «кроме») стали по размеру кнопок — как выбор формы предела у мыши.
- **Требование к ядру считается только по содержимому сцены.** В строке
  состояния «нужно N» больше не подмешивает поле `needs` из файла: удалили
  фигуру — требование упало сразу, а не после сохранения. Файл, записанный
  более новой сборкой, показывается отдельным пунктом при открытии. Рядом с
  числом появилась причина («нужно 20 — вид объекта «фигура»») и галочка, когда
  ядра хватает: «ядро 21 · нужно 20 ✓» читается как «всё совместимо».
- **Вкладка «Поведение» наполняется модулями.** Секции и строки появляются, только
  когда в пресете есть их модуль: микрофон даёт речь («Рот», сквош, подпрыгивание,
  «Поворот при речи», импульс физики), модуль моргания — «Глаз», мышь — следование,
  пресеты — условия видимости. Раньше `mic.speak` и `auto.blink` были зашиты в
  генератор: пересозданный микрофон получал имя `loudness`, и поведение молча
  ломалось. Теперь имя модуля хранится в блоке снимком, при нескольких модулях одного
  вида есть выбор, а настройки без модуля остаются в блоке и оживают, когда модуль
  вернут (панель показывает закрываемое предупреждение).
- **Переключатель формы предела стал по размеру кнопок**: раньше плашка
  растягивалась на всю ширину панели, и две кнопки внутри выглядели пустым полем.
- **Доворот за мышью**: мышь по X поворачивает, по Y наклоняет (градусы на край
  области), своё сглаживание. Ограничен пределами сустава из секции «Поворот».
- Если модуль мыши убрали из пресета, панель предупреждает и выключает следование
  одним нажатием — формула на несуществующий вход не остаётся.

### Оверлей и OBS

- Остановка симуляции в OBS больше не «вешает» источник: номер кадра стал сквозным
  (`src/engine/frameSeq.ts`), а оверлей сбрасывает ожидание при смене хоста, поэтому
  новые кадры после «Стопа» снова принимаются.
- «Стоп» перестал греть WebView: в стопе не рисуются холсты и не держится микрофон,
  нагрузка на процессор падает до нуля, а память не растёт (было ~4 ГБ, стало ~0,8 ГБ
  на том же пресете).
- Скрытое окно редактора не рисует сцену: при `document.hidden` отрисовка пропускается
  и возобновляется по `visibilitychange`.

### Версии и совместимость

- `src/version.ts` — единственный источник номеров: релиз, ядро, файл, мост,
  модули, оболочка. Для человека версия пишется подписями
  (`1.0 · ядро 21 · файл 3 · …`), машинно — через точку.
- Поколение ядра посчитано **хронологически**: 30 правок `crates/rig-core`, из них
  21 меняла контракт → `ядро 21`. Каждая правка записана таблицей с коммитом и
  датой; `npm run version:report` сверяет таблицу с историей git.
- Формат пресета поднят до **3** (свет и карты нормалей). Пресеты формата 2 читаются и
  при чтении получают текущее поколение; файл из будущего не открывается, чтобы редактор
  не потерял незнакомые настройки при сохранении.
- Поле `built` в пресете: какая сборка записала файл. В статусной строке — полный кортеж,
  `пресет новее` и `ядро` с подсказкой при расхождении.
- Ядро сообщает своё поколение запросом `{ "op": "version" }` (`CORE_GENERATION` в
  `crates/rig-core/src/lib.rs`). Ответа нет — ядро заведомо старое, редактор об этом
  говорит один раз.
- Мост сверяется по полю `protocol` в `hello`: оверлей, оставшийся от прошлой сборки
  (страница источника в OBS кэшируется), помечается в статусе как `оверлей старой сборки`.
- Шаблоны модулей объявляют поле `format`, а незнакомый вид модуля больше не
  проваливается молча в «Manual»: в строке состояния горит `модули`.
- Строка состояния показывает паспорт: `1.0`, `ядро 21` и «нужно N» для текущей
  сцены; подсказка расписывает слоты, клик копирует машинную запись.
- **Совместимость ядра вместо строгого равенства.** Ядро объявляет два числа:
  поколение (`CORE_GENERATION = 21`) и `ACCEPTS_FROM = 16` — старейшее поколение
  сценариев, которое оно ещё понимает. Граница не выдумана: в 16-м поколении из
  языка убрали `hold`/`relax` и `trigger имя = …`, вместо них появились `in` и
  `event`. Добавление нового границу не двигает, поэтому новая сборка ядра не
  ломает старые сцены.
- **Пресет пишет своё требование к ядру** — поле `needs`. Оно считается по
  содержимому (`src/engine/coreFeatures.ts`): виды объектов, функции и
  параметры, которые реально используются; строки и комментарии кодом не
  считаются, незнакомый вызов поднимает требование до текущего ядра. Правка
  формулы без новых возможностей требования не меняет — сцена из спрайтов
  просит ядро 1 и работает на любом.
- **Плашка `ядро` горит только при расхождении по существу**: сцене нужно ядро
  новее, в сцене есть убранная форма, или ядро новее редактора и уже не понимает
  его язык. Просто «другое поколение» — молчание.
- Из сравнения `built` убраны слоты ядра, моста, модулей и оболочки: в штампе
  это личность записавшего, а не требование файла. «Пресет новее» теперь
  означает ровно одно — формат файла больше нашего.
- **У собранной папки появился паспорт.** `npm run build` пишет рядом с
  `index.html` файл `build.json`: версия, время сборки, коммит. `npm run
  build:check dist` сверяет папку с репозиторием и печатает, какие слои
  разошлись; приложение читает паспорт при запуске и предупреждает, если в
  папке смешаны файлы разных сборок. В `npm run dev` паспорта нет — это норма.
  Без консоли то же делает двойной клик по `check-build.bat` / `./check-build.sh`:
  спрашивает папку, показывает расхождение, при успехе закрывается сам.
- **Несовместимый пресет объясняет себя.** Вместо «это не пресет версии 2»
  редактор открывает диалог «Версии несовместимы»: паспорт файла, паспорт
  редактора и список того, что может не работать — формат, незнакомые виды
  объектов, требование к ядру, убранные формы языка, мост, модули, оболочка.
  Тот же диалог, только как предупреждение, показывается, если файл открылся,
  но записан другой сборкой. Отдельного режима «только для чтения» нет.
- Решены все открытые вопросы версий: релиз остаётся ярлыком (`1.0` не растёт
  от «света и масок» — это поколения ядра), источник обновлений — папка сборки и
  её паспорт, режим «только для чтения» не делаем.

### Автообновление

- **Приложение само проверяет, не вышла ли новая сборка.** Через несколько
  секунд после запуска читается паспорт `dist/build.json` из репозитория
  (`raw.githubusercontent.com`, без релизов и токенов) и сравнивается со своим
  по слоям: релиз, ядро, файл, мост, модули, оболочка. Предлагается только
  сборка, которая не старее ни в одном слое. Рядом с паспортом версии появилась
  кнопка ручной проверки.
- **Совместимость считается до установки.** Диалог показывает, что именно
  может не работать: чего не хватает ядру открытой сцены, что новая сборка
  перестала понимать, что сдвинулось в мосте и формате файла. Кнопок три —
  «Обновить», «Позже», «Пропустить версию» (`yappytuberplus.update.skip`).
- **Пресет не потеряется.** Если сцена не сохранена в файл, «Обновить» сначала
  предлагает сохранить: «Сохранить и обновить» / «Обновить без сохранения» /
  «Отмена».
- **Три способа установки.** Приложение Tauri подменяет свой `.exe` (скачанный
  файл проверяется по отпечатку, замена происходит после выхода процесса, затем
  автозапуск). Собранная папка обновляется локальным агентом
  (`scripts/update-agent.mjs`, `127.0.0.1:17802`, `npm run update:agent`): он
  скачивает все файлы, сверяет каждый `sha256` и только потом пишет на диск и
  обновляет `build.json`. Запуск из исходников получает честную инструкцию:
  перезапустить `start-yappytuber.bat`, лаунчер подтянет версию.
- **В паспорте сборки появился состав папки.** `build.json` теперь содержит
  `files[]` (33 файла с размерами и SHA-256), `acceptsFrom` и — если приложение
  собрано — поле `app`. Папка сборки закоммичена в репозиторий: `npm run build`
  стал ещё и публикацией версии.
- **Публикация — отдельная кнопка.** `npm run build:publish` или двойной клик по
  `publish-build.bat` (`./publish-build.sh`): она не собирает и не тестирует, а
  только отправляет готовую папку. Предохранители: нет `build.json` — стоп;
  папка не совпадает с репозиторием по числам — стоп; в исходниках есть
  незакоммиченные правки — стоп (иначе уехала бы папка из несуществующего кода);
  нет прав на пуш — стоп с причиной. Публиковать нечего — просто закрывается.
- **Пересборка с тем же номером версии тоже видна.** Обе стороны несут `files[]`
  со `sha256`, поэтому при совпавших номерах приложение сравнивает состав папок:
  другие файлы и более поздняя сборка — это `refresh`, диалог «Та же версия, но
  файлы новее» со списком заменяемых файлов. Пропуск версии теперь помнит версию
  вместе с коммитом, чтобы багфикс не потерялся.
- **Проверка папки стала строже.** `check-build` (и `npm run build:check`) теперь
  отвечает на три вопроса: из какого кода собрана папка (7 чисел паспорта), та ли
  это папка (каждый файл из `files[]` сверяется по размеру и `sha256` — пропавший
  или изменённый останавливает проверку, лишний только замечается) и не отстал ли
  код (если `src`/`crates`/`public` менялись после коммита сборки — замечание, не
  отказ). Публикация пользуется той же проверкой, поэтому папка, поправленная в
  обход паспорта, в репозиторий не уедет.
- **Лаунчер больше не уносит вашу сборку в stash.** `dist` лежит в репозитории как
  источник обновлений, и своя собранная папка выглядела для git как «правки файлов
  репозитория» — при следующем запуске она уезжала в `git stash`, а на диске
  оказывалась версия из репозитория. Теперь обновление вынесено в
  `scripts/sync-repo.mjs` (один код на Windows и Linux): папка сборки копируется во
  временную, обновление идёт своим ходом, сборка возвращается на место; в stash
  уходят только правки исходников, и если stash не удался — обновление
  отменяется, а не стирает правки. Есть `--dry-run`; лаунчеры вызывают скрипт
  вместо своей batch/bash-логики.
- Ручки, которые появились для этого: `npm run build:info`, `npm run build:check`,
  `npm run build:publish`, `check-build.bat`/`check-build.sh`,
  `publish-build.bat`/`publish-build.sh` — без консоли.

### Известные ограничения

- Ядро собирается отдельно: после правок в `crates/rig-core` нужен
  `npm run build:wasm`, иначе редактор предупредит про старое ядро. В самом
  репозитории лежит артефакт, собранный раньше последних правок: он не отвечает на
  `{ "op": "version" }`, поэтому поколение ядра в строке состояния показано как `—`,
  а `test:engine` печатает два предупреждения. Лечится `npm run build:wasm` на
  машине с Rust.
- Обновление нативной сборки (`update_stage`/`update_restart` в `src-tauri`)
  написано, но **не собрано**: в песочнице нет Cargo. Первая же
  `npm run tauri build` покажет, если что-то не так; до неё обновление `.exe`
  недоступно, остальные два канала (папка и лаунчер) работают.
- Публикация (`publish-build`) проверена на временных git-репозиториях; на живой
  Windows с входом в GitHub через Credential Manager она ещё не запускалась.
- Проход объёма написан, но в песочнице без браузера не проверялся глазами —
  проверка на реальной машине с WebGL2 остаётся за пользователем.
- Нагрузочный бюджет на 100–200 реальных спрайтах и захват в OBS на «живой» Windows
  по-прежнему не подтверждены замером.
