# История изменений

Версия — **паспорт из чисел**: `1.1 · ядро 23 · файл 6 · мост 1 · модули 1 ·
оболочка 1` (машинно `1.1.23.6.1.1.1`). Релиз, ядро, файл, мост, модули и
оболочка ломаются по отдельности, поэтому и считаются отдельно. Правила роста и
хронология поколений ядра — [`docs/VERSIONS.md`](docs/VERSIONS.md).

До 1.0 версии не считались: набор возможностей менялся свободно, а совместимость
держалась миграциями на месте. Путь до 1.0 восстанавливается по `git log` и
документам `docs/PLAN-0.2.md` … `docs/PLAN-0.5.md`; поколение ядра при этом
посчитано задним числом — таблица в `docs/VERSIONS.md` §4.

## 1.1.23.6.1.1.1 — 2026-10-28

Новый модуль **«Цвет»** и первое место, где цвет перестаёт быть свойством
объекта: теперь его можно взять из палитры, которая живёт во времени и реагирует
на другие входы.

### Модуль «Цвет»

- Новый вид модуля (`kind: "color"`) в палитре шаблонов. Внутри — **каналы**:
  у каждого своя палитра, режим, скорость, яркость, сглаживание и сдвиг по
  времени. Каналов сколько угодно, имя канала попадает в скрипт (`c1`, `neon`…).
- Один канал даёт **пять входов**: `c1_r`, `c1_g`, `c1_b`, `c1_a` и `c1_level`.
  Это обычные числа 0…1, поэтому цвет можно гнать формулой, читать в скрипте и
  складывать с другими входами — ни ядро, ни DSL не менялись.
- **Все режимы сразу**: «Статичный», «Дыхание» (между первыми двумя цветами),
  «Круг» (по всей палитре с плавными переходами), «Последовательность» (строго
  по очереди, каждый цвет стоит своё время), «Волна» (оттенок по кругу),
  «Случайный» (новый цвет через равные промежутки, без «дрожания» на одном
  кадре) и «Реакция» — цвет стоит, а яркость ведёт вход другого модуля.
- **Сглаживание** — инерция перехода между цветами: 0 % — мгновенно, 100 % —
  «догоняет» примерно за полторы секунды. В режиме «Реакция» сглаживается сама
  яркость, поэтому свет от речи не мигает каждым словом.
- Цвет — функция времени, поэтому у модуля **свой тик** (30 раз в секунду): в
  простое кадров нет, а палитра должна идти. Цвета считаются **после чисел** —
  «Реакция» читает вход другого модуля и должна видеть текущий кадр, а не прошлый.

### Цвет объекта из модуля

- Вкладка **«Поведение»**: у каждого объекта появилась секция «Цвет» — строки
  только для тех цветов, которые у него есть (заливка и обводка фигуры, начало и
  край света, цвет и обводка текста, свечение материала). Источник выбирается
  там же: «свой цвет» или «модуль → канал». Так решено сознательно: цвета
  объекта — это его поведение, а не отдельный редактор.
- **Прозрачность по умолчанию своя.** Галка «α» берёт альфу из канала. Без неё
  край света остаётся прозрачным, как и был, — иначе свет превращался бы в
  жёсткий круг при первом же подключении.
- **Пропал канал — объект не гаснет.** Нет модуля или канала с таким именем:
  строка показывает предупреждение, объект остаётся со своим цветом. Строка
  цвета, которую не удалось разобрать, тоже не трогается — лучше свой цвет, чем
  чёрный квадрат.
- Один и тот же канал можно повесить на несколько объектов и на разные их цвета;
  в скрипте `color_1.c1_level` — обычная переменная (например, яркость света от
  речи: `light.level = color_1.c1_level`).

### Оверлей и формат

- Оверлей получает цвета **вместе с кадром**: необязательное поле `colors` в
  сообщении. Старый оверлей без поля работает как раньше, `OVERLAY_PROTOCOL` не
  менялся.
- **Формат файла 6.** Новое поле — `colors` у объекта; пресеты форматов 2, 3, 4
  и 5 читаются как прежде и получают пустые привязки. Поколение ядра не
  менялось (23), WASM пересобирать не нужно.

### Документация и проверки

- `docs/MODULES-DEV.md` §5.2 — как устроен модуль, у которого значение не одно:
  канал как имя (а не индекс), альфа по умолчанию, обязательный список входов для
  «Реакции».
- `docs/PLAN-COLOR.md` — решения и открытые вопросы по цвету и ambient.
- Новый `tests/e2e/color.spec.ts`: разбор и сборка строки цвета, состав цветов у
  каждого вида объекта, подстановка без порчи исходного пресета, своя альфа
  против галки «α», пропавший канал, все режимы на числах, пять входов канала и
  реакция на вход другого модуля, путь цвета до оверлея и секция в «Поведении».

## 1.1.23.5.1.1.1 — 2026-10-28

Огромная новая механика: **материал поверхности**. До этого объект был плоской
картинкой, которую свет только подсвечивал. Теперь у поверхности есть
шероховатость, металл, окклюзия и свечение — с картами и с формулами.

### Материал объекта

- Раздел **«Материал»** во вкладке «Параметры», сразу под картой нормалей:
  шероховатость, металл, окклюзия, свечение, упакованная карта и общая сила
  блика. Без материала объект выглядит ровно как раньше — старые пресеты не
  сдвинулись ни на пиксель.
- Блик считается по **GGX** (Cook-Torrance): чем меньше шероховатость, тем уже и
  ярче блик. Металл красит отражение цветом самого объекта, диэлектрик отражает
  4 %. Тени блика не дают: тёмный свет гасит диффузную часть, но не блестит.
- **Окклюзия** гасит диффузную часть, блик не трогает: швы и складки темнеют, а
  глянец на них остаётся.
- **Свечение** прибавляется к цвету и не зависит от светов: неон светится и в
  темноте. Есть цвет, сила 0…200 % и своя карта.
- **Пресет** — выпадающий список значений: «нет», «Матовый», «Пластик»,
  «Металл», «Кожа», «Неон». Это **список значений, а не режим и не карта**: он
  подставляет числа и на этом заканчивается. Набор полный, поэтому после «Неона»
  «Матовый» гасит свечение, а «Неон» после «Металла» перестаёт быть металлом.
  Если значения сдвинули руками, список сразу показывает «нет»; если вручную
  выставить те же числа — название вернётся само.
- **Пресет не отвязывает карты.** Раньше нажатие набора молча снимало ссылку на
  карту канала (шероховатость читалась из файла — после «Кожи» становилась
  числом). Теперь меняются только значения, а источник канала остаётся выбором
  человека.
- **Отражение (IOR)** — сколько света поверхность отражает «в лоб». Это то, чем
  кожа отличается от пластика при одинаковой шероховатости: 2.8 % против 4 %.
  Одно число в двух шкалах — «Отражение» 20…100 % (как `reflectance` в Filament)
  и IOR 1.0…2.5 (как `KHR_materials_ior` в glTF), — пересчитываются друг в друга
  формулой `F0 = ((n − 1) / (n + 1))²`. У металла не участвует: он отражает
  цветом объекта.
- **Три способа задать канал:** число, канал упакованной карты (`из ORM`) или
  свой файл. Это выбор на каждый канал, а не режим всего материала: шероховатость
  может быть из ORM, окклюзия — числом.
- **Режим «свой файл» включается до выбора файла:** пока файла нет, читается
  число (раньше кнопка «файл» молча возвращалась в «число», и выбрать карту было
  нельзя вообще).
- **«Источник» под каналами** — строка вида `ORM ×2 · свой файл ×1`: видно, что
  читается, без раскрытия трёх строк.
- **Упакованная карта переехала наверх**, к пресету: это свойство всего
  материала, а не одного канала. Порядок полей раздела закреплён тестом:
  сверху общее (пресет, упаковка), ниже каналы, отражение и свечение — иначе
  блок «наверх» однажды попал бы в старую копию, что уже случилось.
  Упаковка по мировым стандартам — **ORM**, где буквы и есть порядок каналов:
  `R` окклюзия, `G` шероховатость, `B` металл (glTF 2.0, Unreal, Godot, экспорт
  Substance). Чужие наборы — RMA, MRA/MRAO, Unity HDRP Mask Map — читаются
  выбором буквы, карту пересобирать не нужно.
- Каналы из строки упакованной карты выбираются буквой `R/G/B/A`; своя карта
  канала тоже поддерживается. Пропавший файл называется в инспекторе, а не
  выключает материал молча.

### Свет и окружение

- У света появилась **высота** — галка «половина радиуса» или своё число в
  пикселях. Без высоты блик плоский: свет лежал в плоскости холста. На само
  пятно высота не влияет, поэтому старые сцены рисуются как раньше.
- **Сила блика у света** 0…200 %: один свет может только затенять, другой —
  блистать.
- **Окружение сцены** — цвет и уровень 0…200 %, по умолчанию 0 («его нет»).
  Окружение работает как отражение: металл видит в нём свой цвет, диэлектрик —
  4 %. Без окружения металл тёмный, и это физика, а не баг: в инспекторе так и
  написано.

### Скрипт

- Новые параметры ядра: **`roughness`, `metallic`, `ao`, `emissive`** (поколение
  **22**) и **`ior`** (поколение **23**). Все, кроме свечения, заменяют значение
  из инспектора, `-1` значит «не задано»; `emissive` **прибавляется** — пульсацию
  пишут как `emissive = sin(time * 6) * 0.5 + 0.5`. Отражение из формулы:
  `ior = 1.4 + smooth(mic.loudness, 120) * 0.1`.
- Требование к ядру считается по содержимому: материал поднимает его до 22,
  только если он действительно включён у объекта или упомянут в формуле.

### Файлы и совместимость

- Формат пресета — **5**: появились `material` у объекта (вместе с `ior`) и
  `environment` у сцены. Старые файлы (2, 3 и 4) читаются: чего в них нет,
  получает прежний вид — материал без `ior` считается «обычным диэлектриком» с
  IOR 1.5.
- **Карты материала — такие же файлы объекта**, как картинка, маска и карта
  нормалей: они загружаются при открытии, встраиваются в сохраняемый файл,
  разбираются из data URL и пишутся в папку `<имя>.assets`. Это то место, где
  карта нормалей уже один раз терялась.

### Пример и проверки

- В `examples/normal-cube/` добавлены `cube-orm.png` (ORM: R окклюзия, G шероховатость,
  B металл), `cube-emissive.png` и лист `cube-materials.png`: матовый,
  пластик, металл и неон под одним светом. Лист считается **той же математикой**,
  что и кадр в редакторе (`scripts/material-math.mjs` и `src/render/material.ts`),
  поэтому он эталон, а не иллюстрация.
- Новый `tests/e2e/material.spec.ts`: числа GGX и Шлика, металл без окружения,
  окклюзия против блика, свечение без светов, совпадение двух реализаций
  математики, буквы упаковки ORM, пересчёт IOR ↔ отражение, полнота наборов и
  переключение канала на файл до выбора файла.
- Новый **`docs/MATERIALS.md`** — руководство «как пользоваться»: диапазоны и
  типичные значения каждого канала, упаковка и чужие форматы, как готовить
  карты, окружение и высота света, формулы в скрипте, рецепты, таблица частых
  ошибок.

### Исправления

- **Шейдер объёма не собирался** — и поэтому не работали ни карта нормалей, ни
  материал: изображение оставалось плоским под любым светом. Причина в тексте
  GLSL: переменные `flat` (длина вектора до света) и `packed` (тексель
  упакованной карты) — **зарезервированные слова** языка, объявлять их нельзя.
  Драйвер отказывался компилировать программу, `giveUp` выключал проход
  навсегда, и `shadeLayer` честно возвращал `false` для каждого объекта. Теперь
  имена по смыслу (`toLightLen`, `packedTexel`), а новый
  `tests/e2e/shaders.spec.ts` сверяет тексты всех четырёх шейдеров со списком
  зарезервированных слов GLSL ES — такая ошибка больше не пройдёт молча.
- **Незагруженный файл канала больше не отменяет проход.** Раньше один
  недокачанный файл канала гасил весь материал и карту нормалей у объекта; на
  экране не было ни эффекта, ни причины. Теперь канал без файла читает
  константу, а карта подхватывается на следующем кадре. Так же и карта
  нормалей: пока файл идёт, материал считается по плоской нормали.
- **Кнопка «Сбросить материал»** под пресетом: все числа возвращаются к
  умолчаниям и отвязываются **все** карты — упакованная ORM, свои карты каналов
  и карта свечения. Пресета «нет» для этого не хватало: «нет» значит «значения
  не совпали с набором», а не «вернуть как было». Материал при сбросе остаётся
  включённым.

## 1.0.21.3.1.1.1 — 2026-10-27

Первая версия с посчитанными версиями слоёв. Ниже — что в неё входит.

### Свет и объём

- Новый вид объекта **«Свет»** (`kind: "light"`): пятно поверх сцены вместо картинки.
  Формы — круг, сектор с углом, прямоугольник, треугольник, весь экран. Радиус,
  яркость, мягкость края, цвет в центре и у края (rgba), наложение обычное или
  аддитивное («свечение»). Отдельного «режима тени» нет: тёмный цвет затеняет,
  светлый подсвечивает.
- Свет — обычный объект сцены: слой, поворот, маска, прозрачность и вся вкладка
  «Поведение» работают как у спрайта. Обычное наложение ложится только на нарисованное
  (`source-atop`), поэтому в OBS на прозрачном фоне не появляется цветной прямоугольник.
- **Карта нормалей** (`normal`) у спрайтов и медиа: картинка или видео, сила объёма
  0…200 %, «карта играет». Объём считает проход освещения на **WebGL2**
  (`src/render/lighting.ts`): сцена уходит текстурой, объекты с нормалями — в буфер
  нормалей, шейдер считает наклон поверхности и добавку от светов (до 8 за кадр).
  Canvas 2D остаётся основным рендером; без WebGL2 объём просто не считается.
- **Мерцание света** в «Поведении»: синус или шум, глубина и частота. Пишется в
  `opacity`, новых параметров в ядре не требует.

### Поведение без кода

- **Следование за мышью**: предел **эллипсом** или **прямоугольником**, сила, мёртвая
  зона, сглаживание положения, переключатели осей и инверсия. Обе формы задаются
  шириной и высотой — полным размером области, поэтому объект ходит на половину.
  Включается именем модуля мыши; без модуля формулы не пишутся вовсе.
- **Объект не пропадает при силе объёма больше 0 и не уезжает от камеры.**
  Разметка проходов теперь такая: карта нормалей растягивается на весь буфер
  (её читают по рамке), объём рисуется во вьюпорт там, где рамка лежит на
  холсте (буфер считает строки снизу), обратно рамка копируется один к одному.
  Раньше объект сначала подменялся прозрачностью, а после первой правки —
  подменялся своим отражением: уезжал тем сильнее, чем дальше от центра камеры.
  Связка закреплена арифметическим тестом: строка объекта обязана вернуться на
  своё место.
- **Карта нормалей не теряется при сохранении.** Она не попадала ни в список
  файлов пресета, ни в сохранение, ни в папку `<имя>.assets` — после переноса
  или пересохранения объект оставался видимым, а объём выключался. Теперь карта
  и маска входят в файлы объекта везде: загрузка при открытии, встраивание в
  файл, папка рядом с пресетом. Пропавший файл называется в инспекторе, а не
  выключает объём молча.
- **Тестовый кубик с нормалями.** В `examples/normal-cube/` лежат картинка,
  карта нормалей и лист-дебаг (ожидаемый свет сверху и слева, вид DirectX-карты).
  Нормали посчитаны поворотом куба, а не нарисованы на глаз, поэтому пример
  годится как эталон: `npm run example:normals` пересобирает файлы, тест
  `normal-example.spec.ts` сверяет их с математикой. Заодно зафиксирована
  конвенция карты — OpenGL, зелёный вверх.
- **Чёрная зона карты нормалей — «здесь пусто».** Тёмные и прозрачные пиксели
  карты больше не считаются направлением поверхности: они не дают объёма и не
  перекрывают карты других объектов. Порог безопасен по арифметике самой карты:
  у единичной нормали максимум компоненты не меньше `1/√3`, после кодирования в
  байты любая настоящая нормаль ярче 0.79, а заливка «пусто» темнее 0.25.
- **Объём не просвечивает сквозь верхние слои.** Объём теперь считается по
  объекту в его собственном слое и ложится на сцену до того, как нарисовано то,
  что лежит выше: верхний объект перекрывает объём нижнего как обычная картинка,
  а объект без карты нормалей больше не становится окном в чужой объём. Раньше
  буфер нормалей был общим на весь холст, и объём нижнего объекта закрашивал
  пиксели, занятые верхними. Работа идёт в рамке объекта, так что кадр не стал
  дороже всего холста.
- **Карта нормалей держится за объект.** Объём от нормалей больше не «плавает»
  по экрану: буфер нормалей теперь лежит сверху вниз, как холст, поэтому объём
  стоит ровно на своём объекте при любой позиции и масштабе камеры. Раньше он
  зеркалился по вертикали относительно середины холста — по X совпадал, по Y был
  перевёрнут и уезжал вместе с камерой.
- **Инспектор переехал в правую панель вкладкой «Параметры».** Раньше он жил
  под сценой и делил с ней высоту: сцена получала около половины обзора. Теперь
  центр занимает только сцена, а поза, размер, слой, картинка, маска и пивот
  стоят второй вкладкой сразу после «Поведения». Горизонтальный разделитель
  «высота сцены и инспектора» убран, поле `sceneHeight` в раскладке больше не
  используется (старые сохранения читаются без ошибок).
- **Плашки-переключатели больше не растягиваются на всю панель.** Наложение
  света («свечение»), форма волны мерцания и режим пресета («только при» /
  «кроме») стали по размеру кнопок — как выбор формы предела у мыши.
- **Требование к ядру считается только по содержимому сцены.** В строке
  состояния «нужно N» больше не подмешивает поле `needs` из файла: удалили
  фигуру — требование упало сразу, а не после сохранения. Файл, записанный
  более новой сборкой, показывается отдельным пунктом при открытии. Рядом с
  числом появилась причина («нужно 20 — вид объекта «фигура»») и галочка, когда
  ядра хватает: «ядро 21 · нужно 20 ✓» читается как «всё совместимо».
- **Вкладка «Поведение» наполняется модулями.** Секции и строки появляются, только
  когда в пресете есть их модуль: микрофон даёт речь («Рот», сквош, подпрыгивание,
  «Поворот при речи», импульс физики), модуль моргания — «Глаз», мышь — следование,
  пресеты — условия видимости. Раньше `mic.speak` и `auto.blink` были зашиты в
  генератор: пересозданный микрофон получал имя `loudness`, и поведение молча
  ломалось. Теперь имя модуля хранится в блоке снимком, при нескольких модулях одного
  вида есть выбор, а настройки без модуля остаются в блоке и оживают, когда модуль
  вернут (панель показывает закрываемое предупреждение).
- **Переключатель формы предела стал по размеру кнопок**: раньше плашка
  растягивалась на всю ширину панели, и две кнопки внутри выглядели пустым полем.
- **Доворот за мышью**: мышь по X поворачивает, по Y наклоняет (градусы на край
  области), своё сглаживание. Ограничен пределами сустава из секции «Поворот».
- Если модуль мыши убрали из пресета, панель предупреждает и выключает следование
  одним нажатием — формула на несуществующий вход не остаётся.

### Оверлей и OBS

- Остановка симуляции в OBS больше не «вешает» источник: номер кадра стал сквозным
  (`src/engine/frameSeq.ts`), а оверлей сбрасывает ожидание при смене хоста, поэтому
  новые кадры после «Стопа» снова принимаются.
- «Стоп» перестал греть WebView: в стопе не рисуются холсты и не держится микрофон,
  нагрузка на процессор падает до нуля, а память не растёт (было ~4 ГБ, стало ~0,8 ГБ
  на том же пресете).
- Скрытое окно редактора не рисует сцену: при `document.hidden` отрисовка пропускается
  и возобновляется по `visibilitychange`.

### Версии и совместимость

- `src/version.ts` — единственный источник номеров: релиз, ядро, файл, мост,
  модули, оболочка. Для человека версия пишется подписями
  (`1.0 · ядро 21 · файл 3 · …`), машинно — через точку.
- Поколение ядра посчитано **хронологически**: 30 правок `crates/rig-core`, из них
  21 меняла контракт → `ядро 21`. Каждая правка записана таблицей с коммитом и
  датой; `npm run version:report` сверяет таблицу с историей git.
- Формат пресета поднят до **3** (свет и карты нормалей). Пресеты формата 2 читаются и
  при чтении получают текущее поколение; файл из будущего не открывается, чтобы редактор
  не потерял незнакомые настройки при сохранении.
- Поле `built` в пресете: какая сборка записала файл. В статусной строке — полный кортеж,
  `пресет новее` и `ядро` с подсказкой при расхождении.
- Ядро сообщает своё поколение запросом `{ "op": "version" }` (`CORE_GENERATION` в
  `crates/rig-core/src/lib.rs`). Ответа нет — ядро заведомо старое, редактор об этом
  говорит один раз.
- Мост сверяется по полю `protocol` в `hello`: оверлей, оставшийся от прошлой сборки
  (страница источника в OBS кэшируется), помечается в статусе как `оверлей старой сборки`.
- Шаблоны модулей объявляют поле `format`, а незнакомый вид модуля больше не
  проваливается молча в «Manual»: в строке состояния горит `модули`.
- Строка состояния показывает паспорт: `1.0`, `ядро 21` и «нужно N» для текущей
  сцены; подсказка расписывает слоты, клик копирует машинную запись.
- **Совместимость ядра вместо строгого равенства.** Ядро объявляет два числа:
  поколение (`CORE_GENERATION = 21`) и `ACCEPTS_FROM = 16` — старейшее поколение
  сценариев, которое оно ещё понимает. Граница не выдумана: в 16-м поколении из
  языка убрали `hold`/`relax` и `trigger имя = …`, вместо них появились `in` и
  `event`. Добавление нового границу не двигает, поэтому новая сборка ядра не
  ломает старые сцены.
- **Пресет пишет своё требование к ядру** — поле `needs`. Оно считается по
  содержимому (`src/engine/coreFeatures.ts`): виды объектов, функции и
  параметры, которые реально используются; строки и комментарии кодом не
  считаются, незнакомый вызов поднимает требование до текущего ядра. Правка
  формулы без новых возможностей требования не меняет — сцена из спрайтов
  просит ядро 1 и работает на любом.
- **Плашка `ядро` горит только при расхождении по существу**: сцене нужно ядро
  новее, в сцене есть убранная форма, или ядро новее редактора и уже не понимает
  его язык. Просто «другое поколение» — молчание.
- Из сравнения `built` убраны слоты ядра, моста, модулей и оболочки: в штампе
  это личность записавшего, а не требование файла. «Пресет новее» теперь
  означает ровно одно — формат файла больше нашего.
- **У собранной папки появился паспорт.** `npm run build` пишет рядом с
  `index.html` файл `build.json`: версия, время сборки, коммит. `npm run
  build:check dist` сверяет папку с репозиторием и печатает, какие слои
  разошлись; приложение читает паспорт при запуске и предупреждает, если в
  папке смешаны файлы разных сборок. В `npm run dev` паспорта нет — это норма.
  Без консоли то же делает двойной клик по `check-build.bat` / `./check-build.sh`:
  спрашивает папку, показывает расхождение, при успехе закрывается сам.
- **Несовместимый пресет объясняет себя.** Вместо «это не пресет версии 2»
  редактор открывает диалог «Версии несовместимы»: паспорт файла, паспорт
  редактора и список того, что может не работать — формат, незнакомые виды
  объектов, требование к ядру, убранные формы языка, мост, модули, оболочка.
  Тот же диалог, только как предупреждение, показывается, если файл открылся,
  но записан другой сборкой. Отдельного режима «только для чтения» нет.
- Решены все открытые вопросы версий: релиз остаётся ярлыком (`1.0` не растёт
  от «света и масок» — это поколения ядра), источник обновлений — папка сборки и
  её паспорт, режим «только для чтения» не делаем.

### Автообновление

- **Приложение само проверяет, не вышла ли новая сборка.** Через несколько
  секунд после запуска читается паспорт `dist/build.json` из репозитория
  (`raw.githubusercontent.com`, без релизов и токенов) и сравнивается со своим
  по слоям: релиз, ядро, файл, мост, модули, оболочка. Предлагается только
  сборка, которая не старее ни в одном слое. Рядом с паспортом версии появилась
  кнопка ручной проверки.
- **Совместимость считается до установки.** Диалог показывает, что именно
  может не работать: чего не хватает ядру открытой сцены, что новая сборка
  перестала понимать, что сдвинулось в мосте и формате файла. Кнопок три —
  «Обновить», «Позже», «Пропустить версию» (`yappytuberplus.update.skip`).
- **Пресет не потеряется.** Если сцена не сохранена в файл, «Обновить» сначала
  предлагает сохранить: «Сохранить и обновить» / «Обновить без сохранения» /
  «Отмена».
- **Три способа установки.** Приложение Tauri подменяет свой `.exe` (скачанный
  файл проверяется по отпечатку, замена происходит после выхода процесса, затем
  автозапуск). Собранная папка обновляется локальным агентом
  (`scripts/update-agent.mjs`, `127.0.0.1:17802`, `npm run update:agent`): он
  скачивает все файлы, сверяет каждый `sha256` и только потом пишет на диск и
  обновляет `build.json`. Запуск из исходников получает честную инструкцию:
  перезапустить `start-yappytuber.bat`, лаунчер подтянет версию.
- **В паспорте сборки появился состав папки.** `build.json` теперь содержит
  `files[]` (33 файла с размерами и SHA-256), `acceptsFrom` и — если приложение
  собрано — поле `app`. Папка сборки закоммичена в репозиторий: `npm run build`
  стал ещё и публикацией версии.
- **Публикация — отдельная кнопка.** `npm run build:publish` или двойной клик по
  `publish-build.bat` (`./publish-build.sh`): она не собирает и не тестирует, а
  только отправляет готовую папку. Предохранители: нет `build.json` — стоп;
  папка не совпадает с репозиторием по числам — стоп; в исходниках есть
  незакоммиченные правки — стоп (иначе уехала бы папка из несуществующего кода);
  нет прав на пуш — стоп с причиной. Публиковать нечего — просто закрывается.
- **Пересборка с тем же номером версии тоже видна.** Обе стороны несут `files[]`
  со `sha256`, поэтому при совпавших номерах приложение сравнивает состав папок:
  другие файлы и более поздняя сборка — это `refresh`, диалог «Та же версия, но
  файлы новее» со списком заменяемых файлов. Пропуск версии теперь помнит версию
  вместе с коммитом, чтобы багфикс не потерялся.
- **Проверка папки стала строже.** `check-build` (и `npm run build:check`) теперь
  отвечает на три вопроса: из какого кода собрана папка (7 чисел паспорта), та ли
  это папка (каждый файл из `files[]` сверяется по размеру и `sha256` — пропавший
  или изменённый останавливает проверку, лишний только замечается) и не отстал ли
  код (если `src`/`crates`/`public` менялись после коммита сборки — замечание, не
  отказ). Публикация пользуется той же проверкой, поэтому папка, поправленная в
  обход паспорта, в репозиторий не уедет.
- **Лаунчер больше не уносит вашу сборку в stash.** `dist` лежит в репозитории как
  источник обновлений, и своя собранная папка выглядела для git как «правки файлов
  репозитория» — при следующем запуске она уезжала в `git stash`, а на диске
  оказывалась версия из репозитория. Теперь обновление вынесено в
  `scripts/sync-repo.mjs` (один код на Windows и Linux): папка сборки копируется во
  временную, обновление идёт своим ходом, сборка возвращается на место; в stash
  уходят только правки исходников, и если stash не удался — обновление
  отменяется, а не стирает правки. Есть `--dry-run`; лаунчеры вызывают скрипт
  вместо своей batch/bash-логики.
- Ручки, которые появились для этого: `npm run build:info`, `npm run build:check`,
  `npm run build:publish`, `check-build.bat`/`check-build.sh`,
  `publish-build.bat`/`publish-build.sh` — без консоли.

### Известные ограничения

- Ядро собирается отдельно: после правок в `crates/rig-core` нужен
  `npm run build:wasm`, иначе редактор предупредит про старое ядро. В самом
  репозитории лежит артефакт, собранный раньше последних правок: он не отвечает на
  `{ "op": "version" }`, поэтому поколение ядра в строке состояния показано как `—`,
  а `test:engine` печатает два предупреждения. Лечится `npm run build:wasm` на
  машине с Rust.
- Обновление нативной сборки (`update_stage`/`update_restart` в `src-tauri`)
  написано, но **не собрано**: в песочнице нет Cargo. Первая же
  `npm run tauri build` покажет, если что-то не так; до неё обновление `.exe`
  недоступно, остальные два канала (папка и лаунчер) работают.
- Публикация (`publish-build`) проверена на временных git-репозиториях; на живой
  Windows с входом в GitHub через Credential Manager она ещё не запускалась.
- Проход объёма написан, но в песочнице без браузера не проверялся глазами —
  проверка на реальной машине с WebGL2 остаётся за пользователем.
- Нагрузочный бюджет на 100–200 реальных спрайтах и захват в OBS на «живой» Windows
  по-прежнему не подтверждены замером.
