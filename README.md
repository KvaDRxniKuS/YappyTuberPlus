# YappyTuberPlus

Производительный редактор PNG-ригов: между PNGTuber и Live2D. Проект собирается целиком в этой папке.

## Статус: рабочий MVP 0.1 + OBS-оверлей

Уже есть интерактивный редактор с демо-персонажем, Rust-движок формул, WebAssembly-версия для браузерного предпросмотра, нативная оболочка Tauri 2 и прозрачный оверлей для OBS с единым драйвером кадров.

**Версия — паспорт из чисел:**

```
1.1 · ядро 22 · файл 4 · мост 1 · модули 1 · оболочка 1        (машинно: 1.1.22.4.1.1.1)
```

| Слот | Что означает | Что ломается, если отстал |
|---|---|---|
| `1.1` | релиз: то, что видит пользователь и установщик | ничего, это веха |
| `ядро 22` | функции DSL, параметры кадра, виды объектов | старое ядро молча вернёт `0` на новой формуле |
| `файл 4` | формат пресета и папки файлов рядом | старый редактор потеряет новые поля при сохранении |
| `мост 1` | протокол редактор ↔ оверлей | кадры не дойдут: в OBS картинка замерзает |
| `модули 1` | контракт шаблонов из папки `modules` | незнакомый вид модуля станет «Manual» |
| `оболочка 1` | приложение Tauri: окна, клавиши, планировщик | сборка не умеет часть того, что ждёт пресет |

Ядро — единственный слой, который не обновляется вместе с редактором:
`rig_core.wasm` собирается отдельно, поэтому редактор спрашивает его поколение и
говорит, если пора пересобрать.

Совпадать числа не обязаны. Ядро объявляет не только своё поколение, но и
`ACCEPTS_FROM` — старейшее поколение сценариев, которое оно ещё понимает, — а
пресет записывает `needs`: что нужно конкретной сцене. Сцена из спрайтов с
`smooth` просит ядро 1 и работает на любом; сцена со светом просит 21, и старая
сборка честно скажет, чего ей не хватает. Плашка `ядро` горит только при
настоящем расхождении.

Собранная папка несёт свой паспорт — `build.json` рядом с `index.html`
(версия, время, коммит, состав папки с хешами): `npm run build:check dist` сверяет
её с репозиторием, а приложение читает при запуске и замечает смешанные файлы
разных сборок. Эта же папка, закоммиченная в репозиторий, — источник обновлений:
приложение сверяет с ней свой паспорт и, если сборка новее, предлагает обновиться
со списком того, что может не работать, и тремя кнопками — «Обновить», «Позже»,
«Пропустить версию». Ставится тем способом, каким продукт запущен: подменой
`.exe` в нативной сборке, локальным агентом в собранной папке, инструкцией
лаунчера при запуске из исходников. Выпуск новой папки — отдельный шаг:
`npm run build` собирает, `check-build` проверяет, `publish-build.bat` отправляет
(двойной клик, без консоли). Полная хронология поколений ядра (21 поколение,
30 правок, все коммиты) — [`docs/VERSIONS.md`](docs/VERSIONS.md), проверка —
`npm run version:report`. История версий — [`CHANGELOG.md`](CHANGELOG.md).

Основной дизайн-документ: [`docs/DESIGN.md`](docs/DESIGN.md).  
Исходная ревизия без изменений: [`docs/reference/original-rig-rev4.md`](docs/reference/original-rig-rev4.md).

## Что работает

### Редактор

- Импорт любого файла (картинка, GIF/APNG, видео, звук): тип объекта определяется по файлу, все
  объекты встают в центр холста (пачка файлов больше не разъезжается каскадом). Байты лежат в
  хранилище приложения, в пресете — ссылка `asset:<id>`; при сохранении рядом с пресетом
  появляется папка `<имя>.assets` с теми же файлами, а «Экспорт» по-прежнему даёт один файл.
- Замена картинки у существующего спрайта (вкладка «Параметры» → «Картинка»): «Заменить» сохраняет
  размеры и точку привязки, «Заменить и подогнать размер» берёт натуральный размер новой
  картинки и пересчитывает пивот так, чтобы точка привязки осталась на месте. Скрипт, дети,
  пивот и поведение при этом не теряются — раньше приходилось удалять спрайт и импортировать
  заново.
- Дерево спрайтов и групп, выбор, видимость, дублирование, удаление и drag&drop перепривязка.
- Новый объект встаёт в иерархию по выделению: один выделенный — новый становится его ребёнком;
  несколько — новый становится их родителем и **встаёт внутрь их общего родителя** (если все
  выделенные лежат в одной группе), а не в корень сцены.
- Перепривязка не затирает пользовательские формулы; циклы родителей запрещены.
- Canvas-сцена с зумом, панорамированием, сеткой, пивотами и выбором верхнего спрайта.
- Прямое перемещение спрайта мышью с изменением `base.x/base.y`; всё его поддерево двигается согласованно.
- Пивот ставится без «дёрганья» картинки: инструментом «Пивот» (`P`) кликом по сцене или числами в
  инспекторе. Пивот — это `base.x/base.y`, поэтому база переезжает на новую точку, а картинка и
  дети остаются на месте (у группы, у которой картинки нет, не двигаются её дети — это и есть
  «поставить центр вращения здесь»). Поля «Pivot X/Y» у группы показывают долю точки в габаритах
  группы. Формулы живут только в
  скрипте объекта на вкладке «Объект» — инспектор их не дублирует. Шаг стрелок у каждого числа
  свой и вводится руками: чип с числом **между кнопками** `−`/`+` (например, `1` для угла или
  `5` для позиции), значение запоминается для всех объектов.
- CodeMirror 6: подсветка, автодополнение, подсказки по аргументам функций, история и автоприменение через 420 мс.
- Настраиваемые ширина дерева и правой панели; сцена занимает весь центр по высоте,
  а параметры объекта — вкладка **«Параметры»** в правой панели (раньше инспектор стоял
  под сценой и отнимал у неё половину обзора). Раскладка сохраняется отдельно от пресета.
- Undo/Redo для операций редактирования.

### Движок

- Собственный безопасный DSL на Rust, без JavaScript `eval`.
- Парсер, AST, приоритет операторов, тернарный оператор, векторы и доступ `.x/.y`.
- Глобальные переменные и вычисление зависимостей независимо от порядка строк.
- `parent`, `inherit`, `offset`, `follow`, многоуровневая иерархия и защита от циклов.
- Математические, векторные, случайные и stateful-функции, включая `smooth`, `spring`, `noise`, `shake` и `autoblink`.
- Санитизация `NaN`/`Infinity`, округление `visible`, сортировка слоёв и ограничение до 256 объектов.
- Один `rig-core` используется в браузере через WASM и нативно через Tauri.

### Поведение без кода: пресет как в PNGTuber

Порядок вкладок правой панели — от простого к сложному: **Поведение · Параметры ·
Фигура · Входы · Модули · Объект · Глобальные**. Скрипты уехали в конец: каждый день
правят поведение и модули, а в код заходят реже. **«Параметры»** — это инспектор: поза,
размер, слой, картинка, маска и пивот; он стоит вторым, потому что нужен так же часто,
как поведение, и больше не делит высоту со сценой. Вкладка **«Фигура»** появляется
только у объекта-фигуры — там её контуры, точки и сглаживание, а «Параметры» оставили
себе позу и пивот.

Первая вкладка — **«Поведение»**. Это набор ползунков для выбранного объекта: новичку его
хватает, а код всё равно остаётся доступен.

| Настройка | Что делает | Во что превращается |
|---|---|---|
| Сглаживание | фильтр на **итоговое** движение по оси: наследство родителя, покачивание и подпрыгивание вместе (0 — без фильтра) | `y = smooth(inherit + follow(offset, parent).y - mic.speak * 60 + …, 130)` |
| Пружина | сила = резкость: чем больше, тем резче тянет и сильнее качается; гасит её сглаживание | `y = spring(…, 5.5, 0.47)` |
| Сглаживание поворота | фильтр на **итоговый** угол: наследуемый угол родителя и собственный доворот вместе; с физикой работает как трение | `rotation = smooth(inherit + spring(mic.speak * 12, …), 90)` |
| Пружина поворота | пружина на итоговом угле — реакция объекта целиком, а не только следование за родителем | `rotation = spring(inherit + mic.speak * 12, 3.1, 0.45)` |
| Размер X/Y | скаляры к базовому размеру спрайта: править высоту и ширину можно прямо в поведении, не заходя в инспектор; умножаются на «Масштаб» из инспектора и работают вместе со сквошем | `sizeX = 1.2` / `sizeY = inherit * 0.8` |
| Сквош + скорости | сжатие по одной оси и растяжение по другой от громкости речи, −1…+1 (минус меняет оси местами); отдельно скорость деформации и возврата | `sizeY = inherit * (1 + smooth(mic.speak * 0.8, …))` |
| Подпрыгивание при речи | подъём вверх на `mic.speak × сила`, пиксели; «Скорость подпрыгивания» задаёт резкость отдельно от фильтра позиции | `y = … - smooth(mic.speak, 120) * 60` |
| · один раз | галочка «Прыгать один раз»: импульс из быстрого фронта и медленного спада — прыжок гаснет, даже если речь продолжается, а в тишине взводится снова | `y = … - max(smooth(mic.speak, 120) - smooth(mic.speak, 700), 0) * 60` |
| Поворот при речи | угол 0…180° и направление: `вправо`, `влево`, `случайно` (плавный шум, сторона меняется сама), `поочерёдно` (перекидывание раз в 1.2 с). Если предел с одной стороны равен нулю, доворот идёт только в разрешённую | `rotation = spring(mic.speak * 30 * sign(cos(time * 5.236)), 2.4, 0.35)` |
| · в диапазоне | угол — это максимум, фактический поворот выбирается случайно от 0 до него на каждую «фразу» (~0.7 с) | `mic.speak * rnd(floor(time * 1.5) + seed, 0, 30)` |
| Предел влево / вправо | диапазон сустава **вокруг положения покоя**: ноль с одной стороны — честный запрет в эту сторону, оба нуля — предела нет. С физикой ограничивают свободное качание, толчок при этом не бывает сильнее предела | `inherit + limit(угол, -5, 40)` |
| Покачивание X/Y | плавная синусоида с заданными частотой и амплитудой; у каждой оси своя галочка «Случайно» — она делает качание неповторяющимся, но частоту не меняет: дрейфуют фаза и амплитуда | `+ sin(time * 2 * pi * 1.2 + 2.827) * 10` / `+ sin(time * 2 * pi * 1.2 + 2.827 + noise(seed, 0.35) * 2.6) * 10 * (0.72 + 0.28 * abs(noise(seed2, 0.45)))` |
| Покачивание угла | то же для поворота, со своим переключателем случайности: хвосту нужен неповторяющийся ход, маятнику — ровная синусоида | `+ sin(time * 2 * pi * 0.9 + 1.885) * 12` |
| Видимость · рот | `×` — не трогать, `открыт` — виден при речи, `закрыт` — в тишине | `visible = (mic.talking > 0 or mic.speak > 0.05) ? 1 : 0` |
| Видимость · глаз | `открыт` — когда глаза открыты, `закрыт` — на моргании | `visible = 1 - auto.blink` / `visible = auto.blink` |
| Следование за мышью | объект тянется к курсору и не уходит дальше предела: **эллипс** (вектор укорачивается до его края) или **прямоугольник** (свой предел X и Y). Ширина и высота — полный размер области, поэтому объект ходит на половину. Мёртвая зона гасит дрожание рядом с центром, середина области — положение покоя | `x = 0 + (smooth(… * min(1, 1 / max(sqrt(…), 0.0001)), 120))` |
| Доворот за мышью | мышь по X поворачивает, по Y наклоняет: градусы на край области. Ограничен **пределами сустава** из секции «Поворот» и сглаживается отдельно от позиции | `rotation = 0 + limit(0 + ((mouse.x - 0.5) * 2) * 30 - (0), -20, 40)` |
| Мерцание (у света) | синус (ровное дыхание лампы) или шум (как у свечи), глубина и частота; пишется в `opacity`, поэтому складывается с видимостью по рту и пресетам | `opacity = 1 - 0.4 * (0.5 - 0.5 * sin(time * 15.708))` |
| Физика поворота | мотор: пружина тянет «тяжёлую» сторону (дальнюю от пивота) к углу — 0° вниз, 90° вправо, 180° вверх. **«Сила»** — резкость (частота 1.8…8 Гц), **«Плавность»** — вязкость (затухание 0.02…0.70): при 0 мотор звонкий и качается долго, при 1 гаснет за пару качков. Пивот — плечо, его сдвигают к краю | `rotation = spring(<угол> + импульс, 4.28, 0.29)` |
| · импульс | «Поворот при речи» — это **толчок**, а не постоянная сила: быстрый фронт минус медленный спад, мотор получает удар и качается сам, пока его не остановит затухание, сглаживание или предел (толчок не бывает сильнее предела) | `rotation = spring(0 + max(smooth(mic.speak, 60) - smooth(mic.speak, 260), 0) * 30, 6.0, 0.02)` |
| · координаты | **мировая** — спрайт держит угол в мире и противостоит повороту тела (подвеска, серьга, прядь): тело крутится, спрайт на месте; **родительская** — угол задан внутри тела, тело подхватывает спрайт (рука на плече) | `spring(<угол> - inherit, …)` / `spring(inherit + <угол>, …)` |

Как это устроено:

- при мультивыделении панель правит поведение **сразу у всех выделенных**: значения показаны по
  последнему выбранному, а каждому объекту пишется только тронутое поле — его собственные
  настройки (прыжок, сквош, покачивание) остаются. Сброс ✕ очищает блоки у всего выделения, и
  всё это один шаг истории;
- ползунки **пишут формулы в скрипт объекта** — в начало, в блок между комментариями
  `── поведение … ──`. На вкладке «Объект» видно ровно то, что считается; блок можно удалить и
  писать руками, тогда вкладка просто покажет нули;
- настройки лежат в том же блоке JSON-строкой `// @behaviour {…}`, поэтому вкладка и код не
  расходятся и настройки едут вместе с объектом в пресете;
- когда блок берёт на себя `x`, `y`, `rotation`, `sizeX`, `sizeY` или `visible`, одноимённые
  присваивания из остатка скрипта убираются (внутри `on … { }` не трогаются) — иначе ядро
  ругалось бы на двойное присваивание. Всё это один шаг истории: Ctrl+Z возвращает и код;
- кнопка **✕** в шапке сбрасывает поведение и удаляет блок;
- если заданы и рот, и глаз, условия перемножаются: слой виден, когда верно и то, и другое;
- фильтр (сглаживание и пружина) стоит **после сборки цели**, поэтому работает и у объекта без
  родителя: он реагирует на подпрыгивание, доворот и покачивание так же, как на трансформацию
  родителя. Угол фильтруется так же целиком; предел после фильтра ограничивает только отклонение
  от родителя, поэтому сустав остаётся честным;
- «Поворот при речи» с физикой — это толчок, без физики — постоянное давление; покачивание от
  него не зависит и настраивается отдельно, у каждой оси (включая поворот) своя случайность;
- любое число в ползунке можно вписать руками: клик по значению справа превращает его в поле
  ввода (точка или запятая — как удобно);
- **секции живут по модулям.** Микрофон даёт речь («Рот», сквош, подпрыгивание, «Поворот при
  речи», импульс физики), модуль моргания — «Глаз», мышь — следование, пресеты — свои условия.
  Нет модуля — нет и полей: ползунок, который ничего не двигает, только путает. Формулы в
  скрипт при этом не пишутся вовсе, иначе ядро получило бы ссылку на несуществующий вход;
  числа остаются в блоке `@behaviour` и оживают, когда модуль вернут, а панель показывает
  предупреждение, которое можно закрыть;
- имя модуля хранится **снимком** в блоке, а не зашито в формулу: пересозданный микрофон
  получает имя `loudness`, и формулы едут за ним. Если модулей одного типа несколько, в секции
  появляется выбор, какой слушать;
- **следование за мышью** включается именем модуля мыши: без него входов `mouse.x`/`mouse.y`
  в скрипте нет, поэтому ползунки не пишут формулы вовсе. Смещение считается от середины
  области (`0.5`), поэтому центр — это покой; край области всегда даёт полный предел, а
  мёртвая зона лишь вырезает середину хода. Эллипс укорачивает вектор до своей границы,
  прямоугольник ставит `limit` на каждую ось — так можно разрешить движение только вбок.
  Ширина и высота — **полный размер** области, то есть ход в каждую сторону равен половине.
  Доворот за мышью входит в общее отклонение от покоя, поэтому его ограничивают те же
  «Предел влево/вправо», что и покачивание.

**Про физику.** `phys rotation` (мировой разворот тяжёлой стороны) уже есть — он живёт в блоке
поведения. `phys squash` (сжатие по направлению абсолютного движения) и `phys move` (гравитация
для падающих объектов) пока не реализованы: им нужны мировые скорости и собственное состояние
на объект, а это уже ядро, а не формулы. Направление реализации описано в `docs/DESIGN.md` §5.6.

### Скрипты: параметры, чужие объекты, события

Скрипт — это обычные присваивания и блоки событий. Присваивания выполняются каждый кадр:
в скрипте объекта слева стоит параметр этого объекта, в `globals.rig` — глобальная
переменная. Слева можно назвать и чужой объект: тогда параметр задаётся ему.

```text
x = 200                 # свой параметр или глобальная переменная
head.rotation = 15      # чужому объекту: объект.параметр
speed = 3
```

Параметры объекта: `x`, `y`, `rotation` (или `rot`), `sizeX`, `sizeY`, `skewX`, `skewY`,
`opacity`, `visible`, `layer`. Варианты с подчёркиванием (`size_x`, `skew_y`) — те же имена.
У медиа-объекта есть ещё три: `play` (1 — играет, 0 — пауза), `speed` (множитель скорости) и
`volume` (множитель громкости). У текстового объекта есть `text` — строка: `text = "привет"`.
Это единственный параметр не-число, поэтому ему можно присвоить строку, число или результат
строковых функций.

Событие объявляет автор сцены: **условие** живёт в `event`, **действия** — в `on`.
Никаких готовых «событий модуля» нет — модуль отдаёт числа, а условие из них пишется
выражением. Подробно — в [docs/EVENTS.md](docs/EVENTS.md).

```text
event click() { mouse.left.up }              # имя и условие; тело — одно выражение
on click { a = !a }                          # обработчик: что сделать

event speak (loud = mic.loudness ; 5000) {   # переменные и пауза в скобках
  mic.talking > 0.2 in 500                   # речь держится дольше 0,5 с
}
on speak { mouth.open = loud > 0.5 }         # loud — снимок на момент срабатывания

on start { a = 0 }                           # первый кадр после запуска и после «Стоп»
call click()                                 # запустить обработчик сразу
```

| Что | Значение |
|---|---|
| `event имя (переменные ; пауза) { условие }` | объявление события; скобки не обязательны |
| `переменные` | `имя = выражение` через запятую: в условии живой алиас, в `on` — снимок |
| `пауза` (`cd`, мс) | через сколько снова сработать, пока условие истинно; `0` — каждый кадр |
| `on имя { … }` | обработчик события; один на событие в своей области |
| `on start { … }` | первый кадр после запуска и после «Стоп» |
| `call имя(аргументы)` | выполнить обработчик сразу, пауза не мешает; глубина — 8 |

Время выражается **оператором**, а не отдельным видом события:

| Запись | Значение |
|---|---|
| `<условие> in 500` | условие непрерывно истинно уже 500 мс (`in 250ms`, `in 0.5s`) |
| `!(mic.talking > 0.2) in 600` | тишина дольше 0,6 с — отрицание вместо `relax` |
| `(a > 1 && b > 2) in 100` | скобки берут по времени всё условие целиком |

`in` связывает крепче `&&`/`||` и слабее сравнений, поэтому `a > 1 && b > 2 in 100` — это
`a > 1 && (b > 2 in 100)`. Два `in` подряд разрешены.

У каждого входа в выражении есть поля:

| Поле | Значение |
|---|---|
| `<вход>` | число входа в этом кадре |
| `.up` | 1, если значение **выше**, чем в прошлом кадре |
| `.down` | 1, если значение **ниже**, чем в прошлом кадре |
| `.change` | 1, если значение отличается от прошлого кадра |
| `.count(5)` `.sum(5)` `.avg(5)` | активность за последние 5 секунд: сколько событий, их вес, средний вес |
| `.min` `.max` `.step` `.label` `.kind` | паспорт входа |

`.up`/`.down` — направление уровня, как в электронике: нажатие кнопки — это рост (`.up`),
отпускание — спад (`.down`). Активность есть у любого входа: внешние источники присылают вес
события (награда — свою стоимость в битах), а клавиши, кнопки и состояния считаются подъёмом
значения с нуля. Отсюда `mouse.left.count(5)` — «сколько нажатий за 5 секунд»,
`twitch.chat.count(5)` — «сколько сообщений». У аналоговых входов счётчик почти всегда ноль:
для громкости нужен порог (`mic.db > 20`), а не количество. Прежние `trigger`,
`on модуль.вход.тип` и `hold`/`relax` удалены: старый скрипт получает ошибку с подсказкой
новой записи.

Правила, на которые можно опираться:

- тело блока — обычные присваивания, в том числе чужим объектам;
- **своя переменная в теле — это прошлый кадр**: `a = !a` читает `a` из предыдущего кадра,
  поэтому переключатель работает одной строкой; явно то же самое пишется как `state.a`;
- порядок кадра: сначала события, затем записи чужим объектам, затем формулы. Поэтому
  `head.x = …` в обычном присваивании выполняется каждый кадр и параметр принадлежит этой
  записи, а та же строка в теле события задаёт параметр только на кадр срабатывания;
- переменная, которую меняет только событие, видна в формулах по имени — это глобальная
  переменная без выражения;
- событие — это условие из любых входов, поэтому годится любой вход:
  `event click() { mouse.back.up }`, `event long() { board.space > 0.5 in 1000 }`;
- **Стоп** и перезапуск обнуляют состояние событий и снова делают кадр первым для `on start`.

Прошлый кадр доступен явно: `state.a` — глобальная переменная, `state.x` — параметр своего
объекта. Чужой объект читается по имени (`рот.x`, `рот.parent.y`); одна ступень `parent` —
родитель названного объекта. Конфликт имён решается в пользу своих параметров, затем
глобальных переменных, затем объектов.

Ошибка в скрипте не останавливает сцену: скрипт с ошибкой просто не участвует в кадре, а
сообщение с номером строки и столбца попадает в диагностику под сценой и подчёркивается в
редакторе. У каждой строки диагностики, где назван объект и строка, есть кнопка
`head.rig:3` — клик открывает нужный скрипт и встаёт на строку; имя в кавычках при этом
подсвечивается во всех местах, как при переходе из ошибки. В ядре событие — объявление условия (`event`) и обработчик (`on`): рантайм держит
для каждого условия состояние `in`, момент прошлого срабатывания и взвод после ложного кадра.
Рекурсия `call` и повтор имени в одной области — ошибки сборки: они видны сразу, а не в кадре.

### Редактор скрипта: подсказки по аргументам

- Подсказка живёт **в самом редакторе**: всплывает у курсора и не занимает строку снизу.
- После `on ` подсказываются `start` и объявленные события этой области; путь к входу
  (`on mic.db.down`) объясняет, что условие теперь пишется в `event`.
- После `event ` предлагаются готовые скелеты: `click`, `speak`, `chat` — с условием и
  обработчиком сразу.
- После `call ` — те же имена событий, но с вызовом.
- Внутри `<вход>.` подсказываются поля: `.up`, `.down`, `.change`, `.count(5)`, `.sum(5)`,
  `.avg(5)`.
- После `in ` предлагаются значения времени: `100`, `250`, `500`, `1000`, `0.5s`, `1s`.
- После `объект.` подсказываются параметры этого объекта — так пишется запись чужому объекту.
- Ошибка подчёркивается прямо в тексте, а её сообщение видно под редактором. Если у ошибки
  есть **второе объявление** — чужое имя события, глобальное или из скрипта объекта, —
  подсветка ставится на обе строки: своя красным, вторая жёлтым. Пока конфликт не исправлен,
  **все вхождения спорного имени** подсвечены фоном — от `event` до `on` и `call`: видно, что
  ещё сломается. Если вторая строка в другом скрипте, справа в строке ошибки появляется кнопка
  `globals.rig:1` (или `head.rig:7`): клик переключает область, ставит каретку на эту строку и
  на пару секунд подсвечивает все вхождения имени уже в чужом скрипте.
- Каждая функция в автодополнении показана с сигнатурой: `spring(target, frequencyHz, damping)`,
  а во второй строке — что она делает.
- Курсор внутри вызова показывает строку с ожидаемыми аргументами и подсвечивает текущий:
  `spring(target, frequencyHz, damping) — аргумент 3 из 3: damping`.
- После `state.` подсказываются глобальные переменные и параметры объекта — это значение
  прошлого кадра.
- **Шпаргалка и функции** (кнопка под редактором) открывается по клику и меняет высоту
  перетаскиванием за верхний край; высота запоминается. Внутри — готовые блоки событий,
  строки-напоминания и все функции с сигнатурами.
- **Блоки перетаскиваются в скрипт.** Блок события из шпаргалки (`on start { … }`,
  `event click() { mouse.left.up }` с обработчиком, `event speak (loud = mic.loudness ; 5000)`
  с переменными и паузой) и функция из списка переносятся мышью прямо в текст — блок встаёт на
  месте курсора отдельной строкой, каретка сразу внутри `{ }`. Клик делает то же самое, если
  перетаскивать неудобно.
- **События в шпаргалке:** `on start`, нажатие (`.up`), переменные события с паузой `cd`,
  длительность `in`, тишина через `!`, активность `.count(5)`, вес событий `.sum(10)`, `call`,
  команды строкой и запись чужому объекту — всё с готовыми примерами, а не только названиями.
- **Имя занятого события не дублируется:** второй блок того же входа получает
  `event twitch_chat_2() { … }` вместе с подпиской — кнопка дописывает скрипт, а не ломает
  его ошибкой «событие уже объявлено».
- **Избранные команды:** звёздочка стоит внутри «таблетки» функции, справа от вызова, — видно,
  к чему она относится. Клик закрепляет функцию строкой «★ Избранные» под редактором; закладки
  живут в браузере, а не в пресете, и переживают перезапуск.
- В заголовке события модуль и вход подсвечены как свойства, а тип (`down`, `hold`, …) — своим
  цветом; после `{` подсветка заголовка заканчивается.

### Медиа и текстовые объекты

Медиа — **отдельный объект сцены**, а не свойство спрайта: у него те же `x`/`y`/`rotation`,
пивот, родитель и скрипт, а вместо картинки — файл воспроизведения.

Кнопка **Файл** в панели структуры одна: тип объекта определяется по самому файлу, поэтому
кнопок «добавить видео», «добавить звук», «добавить анимацию» нет. Файлы можно и просто
бросить на сцену.

| Файл | Что появится |
|---|---|
| PNG, JPG/JPEG, статичный WEBP, AVIF, BMP | спрайт |
| GIF, APNG, анимированный WEBP/AVIF | медиа-объект `image` (с воспроизведением) |
| MP4, MOV, M4V, WEBM, MKV, AVI | медиа-объект `video` |
| MP3, WAV, OGG/OPUS, M4A, AAC, FLAC | медиа-объект `audio` |

Тип определяется **по содержимому файла**, а не по расширению: редактор смотрит сигнатуры байт
(PNG/JPEG/GIF/RIFF/`ftyp`/EBML/Ogg/FLAC/MP3), и только если они ничего не сказали — имя и MIME.
Поэтому видео не может случайно стать спрайтом с ошибкой декодирования; неподдерживаемый файл
просто не принимается с сообщением, а остальные файлы пачки импортируются.

Размер берётся у файла; у звука — плоская плашка, по которой его видно и можно выделить.
Группа остаётся отдельной кнопкой: это не файл, а структура. Замена картинки у спрайта
принимает только картинки — видео и звук добавляются кнопкой «Файл» и становятся медиа-объектом.

Зачем: дождь, фейерверки и фоновые шумы приходят готовыми файлами — генераторы эффектов не
нужны, а звук реагирует на события.

| Команда в скрипте | Что делает |
|---|---|
| `play()` | начать с начала; если уже играет — сработает политика повтора |
| `resume()` | продолжить с текущего места |
| `pause()` | пауза без перемотки |
| `stop()` | пауза и возврат в начало |
| `seek(2.5)` | перемотка на 2,5 с (для звука и видео); кадр задаётся формулой: `seek(120 / 24)` |
| `rate(1.5)` | скорость до следующей команды |
| `volume(0.4)` | громкость до следующей команды |
| `text("привет")` / `text(mic.db)` | показать текст в текстовом объекте: строка, число или любое выражение |

Команды медиа пишутся **только внутри блока события** и действуют на свой объект. Чужой объект
называется первым аргументом-строкой: `play("дождь")`, `seek("дождь", 12)`,
`text("label", "привет")`. Текст, кроме команды, можно задавать переменной `text` — и тогда
работает и на верхнем уровне скрипта, и внутри события (см. «Текстовый объект»).

```text
// globals.rig: событие из Twitch
event message() { twitch.chat.up }

// скрипт медиа-объекта «дождь»
on start { play() }
on message { play() }
```

**Правило повтора.** В инспекторе у медиа есть поле «При повторной активации» — оно решает,
что делать, когда событие сработало, а звук ещё играет:

| Значение | Поведение |
|---|---|
| Прервать и начать заново | звук обрывается и стартует с нуля |
| Плавно убрать и начать заново | затухание за указанное время, затем новый источник |
| Наложить второй источник | новый источник поверх старого, не больше заданного числа копий |
| Доиграть до конца | текущий звук доигрывается, новый не начинается |

**Параметры вместо команд.** `play`, `speed`, `volume` — обычные формулы, они считаются
каждый кадр и перебивают одноразовую команду. Поэтому громкость можно вести за голосом
(`volume = mic.loudness`), а воспроизведение включать по речи (`play = mic.talking`).
Скачок `play` из 0 в 1 — это запуск по политике повтора, обратный скачок — пауза.

**Текстовый объект.** Кнопка **Текст** создаёт объект с шаблоном. В шаблоне пишутся
подстановки из текстового канала модулей:

```text
{twitch.chat.user}: {twitch.chat.message}
```

Первая часть пути — имя модуля, последняя — поле: `message` (или `text`) даёт текст
сообщения, `user` (или `author`) — автора. Середина пути (`chat`) разрешена и ни на что не
влияет. Шаблон показывает **последнее** сообщение; в числовые формулы текст не попадает —
там по-прежнему только числа.

**История сообщений в скрипте.** Тот же чат читается строкой прямо в выражении:

```text
text = twitch.chat.message            // последнее сообщение (то же, что message())
text = twitch.chat.message(-1)        // предыдущее, (-2) — то, что было до него
text = twitch.chat.user(-1)           // автор предыдущего сообщения
text = upper(twitch.chat.message(0))  // со строковыми функциями работает как обычно
```

Сколько последних строк помнить — настройка модуля («Хранить сообщений», 1…100): столько же
строк видно в блоке «Последние сообщения» во «Входах», столько доступно и в скрипте. Рядом
«Хранить, с» — срок хранения сообщения в секундах (по умолчанию 300, `0` — без предела по
времени): в тихом чате старые строки пропадают сами. Там же путь к тексту, путь к автору и
переключатель «Автор в панели». Смещение глубже истории даёт пустую строку, а не ошибку: текст
просто исчезает.

**Любые параметры входа в скрипте.** У каждого входа есть паспорт: подпись, границы, шаг и вид.
Он читается так же, как значение:

```text
text = twitch.chat.label + ": " + text(twitch.chat) + " / " + text(twitch.chat.max)
y = -100 * (mic.db - mic.db.min) / (mic.db.max - mic.db.min)   // доля от предела входа
```

`min`, `max`, `step` — числа; `label` (подпись из панели) и `kind` (`level`/`db`/`flag`) —
строки. Так доля от предела считается без второй копии числа в скрипте: предел меняется в
настройках модуля — формула видит новое значение.

**Текст — переменная объекта.** Шаблон это только значение по умолчанию; скрипт может задать
текст сам, строкой:

```text
text = "привет"                       // база: видна сразу, без on start
text = "db " + text(mic.db)           // число в текст и склейка
text = mic.db > 0.5 ? "громко" : "тихо"   // текст из условия
```

Строка справа может быть литералом в кавычках, числом (оно станет текстом), результатом
`text(…)`, `fixed(…, 2)`, `upper`/`lower`/`len`, склейки `+` или тернарного оператора. Сравнение
`==` и `!=` сравнивает текст как текст: `text = mic.db > 0.5 ? "громко" : "тихо"` работает.
Если написать это на верхнем уровне скрипта, строка пересчитывается каждый кадр — это формула,
как `x = …`. Если в обработчике (`on speak { text = "пока" }`), значение
**переопределяет** базу до остановки: «Стоп» возвращает базовый текст, база при этом не
меняется.

Команда `text(…)` делает то же самое (переопределение) и понимает любое выражение —
`on speak { text(mic.db) }` покажет число; `text("")` снимает переопределение и
возвращает базу или шаблон. Подстановки чата работают и в скриптовой строке
(`text = "{twitch.chat.user}"`). Одинарные кавычки экранируют подстановку:
`text = "'{twitch.chat.user}'"` покажет `{twitch.chat.user}` буквально.

«Стоп» сразу показывает базовый текст: стоп-кадр считает формулы `text = …` и снимает
переопределение из события. Если базы в скрипте нет, виден шаблон из инспектора — объект
не мигает пустотой.

Оформление текста — в инспекторе и во вкладке **«Поведение»** (у текстового объекта там своя
секция «Текст»): шрифт, размер, цвет, выравнивание, полужирный, курсив, обводка, межстрочный
интервал. Там же — источник строки: свой текст или ссылка `{модуль.message}`; кнопка
«Показать ссылку текстом» сама ставит кавычки `'{…}'`, если ссылку нужно показать, а не
прочитать. Ширина рамки задаёт перенос по словам, высота — рамку для выделения. Пивот,
масштаб, поворот, перекос и слой работают как у спрайта.

Что важно знать:

- файл лежит в хранилище webview (IndexedDB), а в пресете — ссылка, поэтому автосохранение не
  упирается в квоту браузера даже с видео;
- «Сохранить» пишет короткий JSON и рядом папку `<имя>.assets` с файлами: пресет и папка
  переносятся вместе, а открытие читает файлы из папки по мере надобности (видео на сотни
  мегабайт не попадает в память целиком). Папка принадлежит приложению: свои файлы туда класть
  не нужно — при следующем сохранении лишние удаляются;
- **«Экспорт JSON»** — один самодостаточный файл: файлы встраиваются в него data URL. Его можно
  отдать другому человеку без папки; при открытии файлы снова разложатся в хранилище;
- кнопка **«Файлы объектов»** (иконка диска в верхней панели) показывает, что накопилось в
  хранилище, сколько это занимает и что из этого уже не нужно сцене; «Убрать неиспользуемые»
  удаляет только файлы, на которые не ссылаются ни сцена, ни шаги истории отмены, а одинаковые
  файлы хранятся один раз;
- звук играют и редактор, и оверлей: если оба окна слышны, приглушите ненужное в системном
  микшере;
- у GIF/WEBP перемотки нет — это картинка, `play`/`seek` для неё ничего не делают;
- невидимый объект молчит: глаз в структуре и `visible` из скрипта останавливают звук, а
  когда объект снова виден, воспроизведение продолжается с того же места.

### Фигуры и маски

Кнопка **Фигура** в структуре создаёт объект `kind: "shape"` — обычный объект сцены, у
которого вместо картинки набор контуров:

| Контур | Как задаётся |
|---|---|
| прямоугольник | поля X, Y, ширина, высота |
| эллипс | тот же прямоугольник, вписанный овал |
| перо | точки на сцене: клик ставит точку, готовая точка тянется мышью |

Настройки контуров живут не в инспекторе, а во вкладке **«Фигура»** — она появляется, когда
выбран объект-фигура. Инспектор оставил себе позу и пивот.

Перо работает так:

- **обводка** контура видна, пока фигура выделена и пока вы правите перо; снимите выделение
  — подсказка исчезает, и на сцене остаётся только сама фигура;
- клик **между двумя ближайшими** точками вставляет новую между ними (контур не прыгает
  через всю фигуру), клик по готовой точке начинает перетаскивание;
- клик по **первой точке** замыкает контур;
- **Alt+клик** по точке переключает её тип: угол ⇄ кривая;
- у каждой точки своя **сила сглаживания** 0…100 % во вкладке «Фигура»: 0 — ломаная, 100 —
  полная кривая. Сила действует со стороны своей точки: сглаженная точка уходит в дугу, а
  соседний угол остаётся углом, поэтому одиночная кривая точка между углами тоже даёт дугу.
  Контур можно **замкнуть**;
- перетаскивание точки плавное: движения мыши склеиваются в одну правку на кадр, а Ctrl+Z
  отменяет весь жест целиком, а не по шагу на каждое движение.

Контуры живут в координатах рамки объекта, поэтому фигура двигается, масштабируется,
вращается и анимируется скриптом так же, как спрайт. Фигура рисуется заливкой и обводкой, а
галочка «Рисовать фигуру в сцене» позволяет её спрятать, оставив маску рабочей.

**Маска** — свойство любого объекта, кроме группы: раздел «Маска» в инспекторе. Внутри
контура объект виден, снаружи — нет.

| Источник | Что берётся |
|---|---|
| Нет | маска выключена, объект виден целиком |
| Набор точек | многоугольник в координатах объекта: `10,20; 120,20; 120,140` |
| Фигура | контуры выбранного объекта-фигуры, с его текущей позой и скриптом |
| Внутренний файл | файл, который уже есть в проекте: картинка, анимация или видео |
| Внешний файл | файл с диска (в проект не копируется, остаётся ссылкой) |

Списки фигур и файлов проекта ищутся по имени — «кот» находит «Кот_улыбка.png». Видео-маска
берёт текущий кадр, поэтому прозрачный ролик даёт живое «окно»; анимированные GIF и WebP
двигаются сами.

Дополнительно: «Инвертировать» показывает то, что снаружи контура, «Мягкий край» размывает
границу в пикселях. Настройки маски пишутся в скрипт объекта блоком «маска», рядом с ним
стоит формула `mask = 1`: ноль показывает объект целиком, дробь проявляет маску плавно, а
само значение можно двигать из скрипта. Если фигуру удалить, маска снимается и объект снова виден целиком —
битой ссылки в пресете не остаётся. Картинка-маска хранится в файлах объектов вместе с
остальными (data URL в пресет не попадает).

### Деформация крайних точек

Раздел **«Деформация»** в инспекторе спрайта (и медиа-картинки) даёт простую
перспективу: картинка гнётся четырьмя углами, без сеток и текстурных атласов.

| Что | Смысл |
|---|---|
| «Гнуть крайние точки» | включает деформацию: без галочки объект рисуется как раньше |
| Зона деформации | прямоугольник внутри картинки (доли картинки, проценты в полях) плюс поворот: остальное остаётся ровным |
| Углы | смещение каждого угла в процентах размера зоны, −100…+100 |

Деформация правится двумя инструментами — они стоят отдельной группой на панели сцены:

| Инструмент | Клавиша | Что тянет |
|---|---|---|
| **Зона деформации** | `T` | прямоугольник картинки, его стороны и поворот (Shift — шаг 15°) |
| **Углы деформации** | `R` | четыре угла картинки и ничего больше |

Разделение не косметическое: раньше углы и рамка жили в одном режиме, их прямоугольники
пересекались, и приходилось прицеливаться, чтобы не задеть чужую ручку. Первое
перетаскивание включает галочку «Гнуть крайние точки» само.

Углы можно анимировать: `warpTLx`, `warpTLy`, `warpTRx`, `warpTRy`, `warpBRx`, `warpBRy`,
`warpBLx`, `warpBLy` — обычные параметры скрипта, как `x` или `rotation`. Значение параметра
**добавляется** к числу из инспектора: инспектор задаёт форму, скрипт её раскачивает. Клики и рамки
выделения считаются по деформированному четырёхугольнику, а не по старому прямоугольнику.

### Свет, тени и объём

Кнопка **Свет** в структуре создаёт объект `kind: "light"` — обычный объект сцены, у
которого вместо картинки пятно света. Слой, поворот, маска, прозрачность и вся вкладка
«Поведение» у него такие же, как у спрайта, поэтому «свет только когда говорю» и мерцание —
это обычные формулы, а не отдельный набор настроек.

| Настройка | Что делает |
|---|---|
| Форма | круг, сектор (угол в градусах), прямоугольник, треугольник, весь экран (виньетка) |
| Радиус | размер пятна в пикселях; рамка объекта равна диаметру, поэтому выделение и пивот совпадают с пятном |
| Яркость | 0…200 % — множитель прозрачности обоих цветов |
| Мягкость края | 0…100 %: где именно градиент начинает гаснуть |
| Цвет в центре / у края | обычный rgba. Обычно цвет → прозрачность, тогда край растворяется |
| Наложение | **обычное** (тёмный цвет = тень, светлый = подсветка) или **свечение** (складывается со сценой) |

Отдельного «режима тени» нет и не нужно: **цвет и есть режим**. Тёмный rgba затеняет,
светлый подсвечивает. Обычное наложение ложится только на нарисованное (`source-atop`),
поэтому в OBS на прозрачном фоне не появляется цветной прямоугольник вокруг тени — пятно
освещает объекты, а не пустое место.

**Высота света** — галка «половина радиуса» или своё число в пикселях, плюс **сила блика**
0…200 %. Высота двигает только блики: пятно от неё не меняется, поэтому свет можно «поднять»
над сценой, не перекраивая её. Старые сцены рисуются как раньше.

**Карта нормалей** (`normal`) есть у спрайтов и медиа: файл-картинка **или видео**, сила
объёма 0…200 % и признак «карта играет». Нормали — это направление поверхности в каждой
точке; по ним свет сцены считает, как наклон спрайта повёрнут к лампе, и получается объём.
Видео-карта даёт живой объём: вода, ткань, мимика.

Объём считает отдельный проход освещения на **WebGL2** (`src/render/lighting.ts`). Canvas 2D
не умеет считать наклон поверхности, поэтому объект с картой нормалей рисуется в свой слой,
слой уходит текстурой в WebGL2: шейдер для каждой точки считает наклон и добавку света от
светильников сцены (до 8 за кадр), а затем слой ложится на сцену. Пятна, градиенты, маски и
порядок слоёв остаются за Canvas 2D — WebGL только затемняет и подсвечивает нарисованное.
Отсюда три следствия:

- свет никогда не красит пустое место и не спорит с разметкой редактора, а прозрачный фон
  OBS остаётся прозрачным;
- объём принадлежит объекту: он считается до того, как нарисовано то, что лежит выше, и это
  выше перекрывает его как обычно. Объект без карты нормалей — обычная преграда, а не окно в
  чужой объём. Работа идёт в рамке объекта, поэтому цена зависит от его размера;
- чёрная зона карты — это «здесь пусто», а не направление: она не даёт объёма и не
  перекрывает карты других объектов. Так же читаются прозрачные пиксели карты. Порог
  безопасен: любая настоящая нормаль ярче 0.79, потому что у единичного вектора максимум
  компоненты больше `1/√3`;

Карта читается в конвенции **OpenGL: зелёный канал — вверх** (`G > 128` там, где поверхность
наклонена к верху картинки). Так её отдают Blender и Substance Painter. Проверить объём
можно готовым примером — `examples/normal-cube/` (картинка, карта и лист-дебаг с ожидаемым
светом сверху и слева); пересобирается он командой `npm run example:normals`.
- нет WebGL2, шейдер не собрался или карта ещё грузится — объём просто не считается, объект
  рисуется как раньше. Проход общий для редактора и оверлея, поэтому в OBS объём тот же.

### Материал поверхности

Раздел **«Материал»** в «Параметрах» превращает картинку в поверхность: у неё есть
шероховатость, металл, окклюзия и свечение. Считается по **GGX** (Cook-Torrance) — той же
модели, что в играх и кино, поэтому металл выглядит металлом, а не «серым с блеском».

| Настройка | Что делает |
|---|---|
| Готовые наборы | «Матовый», «Пластик», «Металл», «Кожа», «Неон» — значения одной кнопкой |
| Шероховатость | 0…1: ширина блика. Меньше — глаже, блик ярче и уже |
| Металл | 0…1: отражает ли поверхность цветом объекта (у диэлектрика отражение своих 4 %) |
| Окклюзия | 0…1: гасит диффузную часть и окружение, блик не трогает — швы темнеют, глянец остаётся |
| Свечение | цвет и сила 0…200 %: прибавляется в конце и не зависит от светов |
| Сила блика | 0…200 % на весь материал: «этот объект блистать не должен» |
| Упакованная карта | одна картинка на три канала (по умолчанию **ORM**: `R` шероховатость, `G` металл, `B` окклюзия) |

Каждый из трёх каналов задаётся **тремя способами**: числом, своим файлом или буквой
упакованной карты. Упаковка ORM — стандарт видеоигр (так пишут glTF и Substance); чужие
наборы MRA/RMA отличаются порядком букв, поэтому буква выбирается в инспекторе, а не
зашита в формат. Карта свечения — отдельный файл, её в ORM обычно не пакуют.

**Окружение сцены** — цвет и уровень 0…200 %, по умолчанию 0, то есть «его нет». Окружение
работает как отражение: у металла красится его цветом, у диэлектрика даёт свои 4 %.
Поэтому металл без окружения тёмный — это физика, а не баг: поднимите уровень, и он
«поймает» комнату.

Правила, ради которых всё так устроено:

- **объект без материала выглядит точно как раньше** — старые пресеты не сдвинулись;
- **тёмный свет блика не даёт**: тень гасит диффузную часть, но не блестит;
- **блик не вылезает за пятно**: он умножается на покрытие света;
- **энергия ограничена мягко** (кламп 8): без ограничения металл под двумя лампами давал бы
  белую дыру, с жёстким клампом в 1 — серый пластик;
- **свечение не зависит от светов**: неон светится и в темноте.

Из скрипта материал правится параметрами ядра **22**: `roughness`, `metallic`, `ao`
**заменяют** значение инспектора (`-1` значит «не задано»), а `emissive` **прибавляется**:
`emissive = sin(time * 6) * 0.5 + 0.5` — пульсация, а не замена цвета.

Пример — `examples/normal-cube/`: `cube-orm.png` (R шероховатость, G металл, B окклюзия),
`cube-emissive.png` и лист `cube-materials.png` — матовый, пластик, металл и неон под одним
светом. Лист считается **той же математикой**, что и кадр в редакторе, поэтому он эталон,
а не иллюстрация.

### Пресеты одежды и эмоций

Модуль **«Пресеты»** — вариант образа без единой строчки кода: перечислили подписи
(«Летний костюм», «Зима»), и модуль сам завёл переменную, константы, события из наград и
условия видимости.

- галочка **«Искать среди наград»** связывает пресет с наградой канала: для пресета `summer`
  ищется вход `twitch.redeem_summer`;
- **модули наград** и **префиксы наград** задают, где и по какому шаблону искать (по
  умолчанию `twitch` и `redeem`);
- во вкладке **«Поведение»** у объекта отмечают пресеты, при которых он виден: «только при»
  или «кроме»;
- кружок у пресета в карточке модуля — предпросмотр в редакторе, эфир он не трогает.

В скрипте остаётся читаемое `preset == summer`; значение `-1` значит «пресет не выбран».
Подробности — [`docs/MODULES.md`](docs/MODULES.md), устройство — [`docs/DESIGN.md`](docs/DESIGN.md) §9 и §11.3.

### Хвост и лента (вручную)

Отдельной кнопки для цепочек нет: хвост — это обычная иерархия и по одной формуле на сегмент.
Вложите сегменты друг в друга (перетаскиванием в дереве) и впишите каждому:

```text
rotation = spring(inherit + 4 + noise(42, 0.3) * 2.5, 2.02, 0.33)
```

`inherit` — значение родителя в этом кадре, `spring` тянется за ним и отстаёт, поэтому волна
бежит от корня к кончику. Чем дальше сегмент, тем ниже частота и выше затухание (например,
`3.2, 0.22` → `2.4, 0.3` → `1.8, 0.4`): кончик догоняет мягче и не дребезжит. `noise` в цели
даёт покачивание в покое. Пивот ставьте на стык — сегмент будет вращаться вокруг соединения,
а не вокруг своего центра.

### Кадры, входы и файлы

- Явный лимит FPS `1–240`, быстрые значения и режим по частоте экрана.
- Фактический FPS, пауза и покадровый шаг; изменение лимита не пересоздает движок.
- Все входы — из **модулей**: `mic.talking`, `mic_left.db`, `viseme.a`, `viseme.o_umlaut`, `manual.blink`;
  встроенных имён вроде `speak` в ядре больше нет.
- Любой вход модуля годится для условия: `event click() { mouse.left.up }`,
  `event long() { board.space > 0.5 in 400 }`, `event viseme() { viseme.a > 0.4 }`.
- Несколько экземпляров одного модуля: два Loudness слушают два разных микрофона,
  у каждого свой источник, устройство, усиление и порог речи.
- Автосохранение в localStorage (короткая строка со ссылками на файлы), явное сохранение,
  импорт и экспорт JSON-пресета версии 2 (самодостаточный файл: файлы внутри).
- Демонстрационный риг из отдельных PNG-спрайтов: два рта в одной точке — открытый при речи и
  закрытая улыбка при молчании (по `mic.talking` и `mic.speak` из модуля Loudness).
- Спрайты демо генерируются воспроизводимо: `node scripts/generate-demo-sprites.mjs`.

### Модули и входы

- **Mouse** читает курсор в пикселях **экрана**, а область отсчёта выбирается у экземпляра:
  монитор (по умолчанию, с выбором какого именно), окно приложения или холст сцены.
  `x`/`y` — доли 0…1 внутри области, `px`/`py` — физические пиксели внутри неё (то же
  разрешение, что видно в настройках экрана: 3440×1440, а не «2752×1152»), `dx`/`dy` — сдвиг
  за кадр **в пикселях** (раньше были доли сцены). Колесо — **целые щелчки**: тачпад копит
  мелкие дельты до целого, остаток переходит в следующий кадр.
- Экземпляры модулей: **Loudness** (микрофон или отладочный ползунок), **AutoBlink**
  (моргание по таймеру), **Manual** (вход 0/1, число с границами или **состояния**
  для режимов персонажа — «покой / идёт / бежит» с флагом и событием на каждое), **Viseme**
  (похожесть звука на записанные эталоны, свои звуки, варианты записи, контраст,
  нормализация суммы), **Keyboard** / **Key** / **Mouse** (клавиши и курсор как входы:
  в нативном окне ловятся глобально, без перехвата клавиш), **Внешний источник**
  (мост из сети: WebSocket в окне, HTTP-опрос, SSE, OSC по UDP и Twitch — нативное
  идёт мимо CORS; таблица «поле JSON → вход» делает входы без кода — пульсомер, игра,
  бот, чат, команды, награды и bits канала; у Twitch рядом с полем Client ID стоит
  ссылка на консоль разработчика — она открывается в браузере, а не в окне студии),
  **Пульсометр** (готовый модуль под мост `pulse-bridge.bat`: пульс и удар, без
  железа — тренажёр);
  имя экземпляра — префикс входа, поэтому `mic.talking` и `mic_left.talking` живут рядом.
- Шаблоны модулей — JSON в `public/modules/` (`index.json` + `<id>.json`): входы и поля
  настроек описываются данными, поведение выбирает поле `kind`. Новый шаблон — новый файл.
- Панель модулей: поиск по включённым сверху, палитра «Добавить модуль» снизу, у каждого
  входа свой флажок (выключенный вход не уходит в кадр).
- Сброс настроек экземпляра — в карточке модуля (с подтверждением: пропадают записи визем и
  калибровки). Из «Входов» есть переход к модулю (↗): вкладка «Модули» открывается на нужной
  карточке и подсвечивает её.
- Микрофоны через Web Audio: выбор устройства для каждого экземпляра, общий поток на
  устройство, усиление, порог речи, индикатор уровня и отключаемое шумоподавление.
- Отдельной кнопки «включить микрофон» нет: звук поднимается сам, когда в модели есть
  включённый микрофонный модуль; `AudioContext` дополнительно будится первым нажатием,
  иначе WebView2 оставляет его в `suspended` и анализатор молчит.
- **Состояния (enum):** `manual.value` — номер выбранного состояния, имя состояния читается
  в скрипте как константа (`manual.value == walk`), а `manual.walk` — флаг: условие
  `event walk() { manual.walk.up }` срабатывает при входе в состояние; сравнения `near`,
  `between`, `is` возвращают 0/1.
- Модули хранятся в пресете; при открытии чужого набора спрашиваем
  **применить / оставить как есть / отключить все**. Старые пресеты переносятся
  автоматически (`talking` → `mic.talking`, `signal.blink`/`manual.blink` → `auto.blink`).

Подробности: [`docs/MODULES.md`](docs/MODULES.md). Для своих модулей и видов входов —
[`docs/MODULES-DEV.md`](docs/MODULES-DEV.md).

### OBS-оверлей

- Отдельное прозрачное окно Tauri без рамки, тени и значка на панели задач; в браузере — второе окно для проверки.
- Оверлей только рисует: движок, входы и stateful-формулы остаются в редакторе, поэтому кадры не продвигаются дважды.
- Передача сцены один раз, затем только небольшие патчи базовой позы, конфигурации и готовые кадры.
- **Размер окна берётся из холста:** окно оверлея и окно захвата по умолчанию совпадают с
  `preset.canvas`, поэтому риг виден 1:1 и не нужно подбирать размеры руками. Правка холста
  тянет окно за собой; отдельные «Ширина/Высота» включаются галочкой «По размеру холста» (тогда
  картинка вписывается в окно по режиму вписывания — окно может быть больше или меньше холста).
- Настройки в пресете: режим вписывания (`contain`/`cover`/`stretch`/`pixel`), прозрачный/цветной/хромакей-фон, поверх всех окон, пропуск кликов, служебная рамка.
- Транспорты: `BroadcastChannel` в одном браузере, события Tauri между нативными окнами и WebSocket для источника браузера в OBS.
- **Кадры считает приложение, а не окно:** в нативной сборке поток кадров живёт в Rust
  (`src-tauri/src/schedule.rs`), поэтому свёрнутый редактор больше не замораживает оверлей.
  Окно присылает входы и получает готовые кадры событием `rig://frame`; в браузере всё как
  раньше — `requestAnimationFrame`.
- **Встроенный сервер оверлея:** `http://127.0.0.1:17800/overlay.html` отдаёт страницу и
  релей `/overlay-ws` сам, поэтому источнику браузера в OBS не нужен отдельный процесс Node.
  Адрес сервера — **только для OBS**: кнопка «Открыть оверлей» поднимает окно на своей странице
  приложения, потому что у чужого origin нет доступа к IPC Tauri и окно осталось бы без кадров.
- **Нагрузка на процессор.** Окна не крутят постоянный `requestAnimationFrame`: кадр рисуется
  по сигналу движка (новый кадр) или по правке настроек, а в простое не делается ничего.
  В режиме «Экран» Rust тикает с частотой монитора (измеряется при запуске, 30…240 Гц), поэтому
  кадров не больше, чем показывает экран, — вдвое меньше работы, чем при фиксированных 120 Гц.
- Общий Canvas 2D-рендер с редактором, статус подключения, счётчик FPS и дедупликация кадров.
- **Данные приложения** — профиль WebView2 (`%LOCALAPPDATA%\com.yappytuberplus.studio`) и папка
  пресетов (`%APPDATA%\com.yappytuberplus.studio\presets`). Картинки, видео и звук лежат в
  хранилище webview (IndexedDB профиля) и в папке `<имя>.assets` рядом с сохранённым пресетом,
  а в пресете и в localStorage — только ссылки `asset:<id>`, поэтому автосохранение сессии и
  приносит «старые» аватары из прошлых запусков (в том числе из `npm run tauri dev` —
  идентификатор общий), а экспорт остаётся одним самодостаточным файлом.
  Подробности и сброс: [`docs/DATA.md`](docs/DATA.md), скрипт `reset-yappytuber-data.bat`.
- **Окно захвата** (`overlay.html?capture=1`) — второе окно для Discord, Game Bar и «Записи экрана»:
  без рамки, но видно в списке окон; размер и фон общие с оверлеем, прозрачность в нативном окне
  сохраняется и уходит в запись с альфа-каналом (как Spout2/PNGTuber).

Подробности и настройка захвата: [`docs/OVERLAY.md`](docs/OVERLAY.md).

## Быстрый запуск одним файлом

Не нужно ничего вводить в консоль:

- **Windows** — двойной клик по `start-yappytuber.bat`;
- **Linux/macOS** — `./start-yappytuber.sh`.

Файл сам скачивает крайние обновления, при необходимости предлагает поставить Git и
Node.js через `winget`, выполняет `npm ci`, собирает WASM-ядро (если есть Rust) и
открывает редактор в браузере. Своя папка сборки `dist` при обновлении не
пропадает: лаунчер сохраняет её и возвращает на место, в `git stash` уходят только
правки исходников. Подходит и для папки, скачанной ZIP-архивом: скрипт
включает автообновление на месте (`git init` + приведение файлов к ветке), не трогая
новые файлы и сохраняя правки репозитория в `git stash`. Подробности и параметры —
[`docs/LAUNCHER.md`](docs/LAUNCHER.md).

```bat
start-yappytuber.bat --no-open      :: без автооткрытия браузера
start-yappytuber.bat --no-bridge    :: без моста для OBS
start-yappytuber.bat --no-serve     :: только обновить и собрать
start-yappytuber.bat --no-update    :: без локального агента обновлений
start-yappytuber.bat --tauri        :: нативное окно Tauri
```

## Запуск редактора вручную

Требования: Node.js 20+, Rust stable и target `wasm32-unknown-unknown`.

```bash
npm install
rustup target add wasm32-unknown-unknown
npm run build:wasm
npm run dev
```

Vite слушает `0.0.0.0:5173`. Без установленного Rust сборка `build:wasm` использует уже
собранный `public/rig_core.wasm` и предупреждает об этом.

Для источника браузера в OBS в приложении ничего не нужно: сервер оверлея поднимается сам
(`http://127.0.0.1:17800/overlay.html`, ссылка есть в диалоге оверлея). Отдельный мост нужен
только при разработке в браузере:

```bash
npm run overlay:bridge
```

Production-сборка:

```bash
npm run build
npm run preview
```

## Tauri / Windows

В `src-tauri` находится нативная команда `rig_call`, подключённая к тому же `RuntimeStore`. Конфигурация рассчитана на Windows и NSIS.

> **`"dragDropEnabled": false` в окне `main` — не опечатка.** По умолчанию Tauri
> перехватывает drag&drop у WebView2 ради файловых событий, и тогда **внутристраничное**
> перетаскивание (строки структуры, блоки скрипта, файлы на сцену) на Windows не работает
> вовсе: `dragstart`/`drop` до страницы не доходят. С этой настройкой события идут в
> страницу, а файлы из проводника сцена принимает своим `drop` (`onDropFiles`). Если
> вернуть `true`, перестанет работать перетаскивание объектов в структуре.

```bash
npm run tauri dev      # нативное окно, фронтенд из Vite
npm run tauri build    # .exe и установщик NSIS, фронтенд внутри
```

Для Windows-сборки нужны Rust (`stable-x86_64-pc-windows-msvc`), MSVC Build Tools,
Node.js и WebView2; ядро собирается с target `wasm32-unknown-unknown`.
Готовые файлы: `src-tauri/target/release/yappytuberplus.exe` и
`src-tauri/target/release/bundle/nsis/YappyTuberPlus_<версия>_x64-setup.exe`.

Без консоли и без ручной установки компонентов:

1. **`install-build-tools.bat`** — ставит Node.js LTS, Rust, Visual Studio Build Tools (C++)
   и WebView2, если их нет (нужен интернет и подтверждение UAC);
2. **`build-yappytuber.bat`** — собирает `.exe` и установщик. При успехе окно закрывается
   само и открывает папку с результатом (установщик выделен); при ошибке окно остаётся,
   чтобы прочитать текст. Ключи: `--no-bundle` — только `.exe`, `--fast` — без пересборки
   WASM-ядра, `--no-open` — не открывать папку.

Если ставить ничего не хочется, установщик соберёт GitHub: один раз добавьте
workflow из [`docs/BUILD.md`](docs/BUILD.md), затем **Actions** → **Сборка Windows** →
**Run workflow** — готовый файл появится в артефактах.

Пошагово, с требованиями и разбором ошибок — [`docs/BUILD.md`](docs/BUILD.md).
Устройство событий и времени в скрипте — [`docs/EVENTS.md`](docs/EVENTS.md).
В текущей Linux-среде нативная часть проверена через `cargo check`; Windows-установщик
здесь не создавался.

## Импорт из PNGTuber Plus (`.save`)

`.save` — это JSON, где каждый объект сцены — слой-костюм: `imageData` (PNG в base64),
`pos`/`offset` (в старой версии всегда `Vector2(0, 0)`), `parentId`, `zindex` и флаги показа
`showBlink` / `showTalk`. Хвоста и другой физики в самом файле нет — только картинки и правила
их показа.

Перевод в пресет YappyTuberPlus:

| Поле `.save` | Куда переходит |
|---|---|
| `imageData` | сохранить как PNG рядом со своим пресетом и указать путь в `image` |
| `pos` + полный холст 1200×600 | `base.x/y` = центр холста, `pivot` = `0.5, 0.5`, `width/height` = размер PNG |
| `showTalk = 0` | слой виден всегда |
| `showTalk = 1` | `visible = mic.talking > 0 ? 0 : 1` (вариант «молчит») |
| `showTalk = 2` | `visible = mic.talking > 0 ? 1 : 0` (вариант «говорит») |
| `showBlink = 0` | слой виден всегда |
| `showBlink = 1` | `visible = 1 - auto.blink` (виден, когда глаза открыты) |
| `showBlink = 2` | `visible = auto.blink` (виден на моргании) |
| `stretchAmount`, `drag`, `rotDrag`, `rLimitMin/Max`, `xAmp/xFrq/yAmp/yFrq`, `ignoreBounce` | прямого аналога нет: это «пружина/растяжение» PNGTuber. У нас то же самое пишется формулами: `sizeY = spring(…)`, `noise`, `shake` |

Картинки из чужого `.save` — это личные аватары: в репозиторий они не попадают. Конвертация
делается локально, файлы кладите в свою папку (`public/assets/...` для своего форка или рядом с
пресетом), а альтернативные кадры лиц оставляйте выключенными (`visible = 0`) — нужный
включается вместо основного.

## Что ещё не входит в этот MVP

- Нативный Rust-аудиозахват; сейчас микрофон реализован браузерным способом, и именно
  WebView задаёт задержку входов.
- Плагины, виземы от внешней модели, кадровая анимация и IK.
- **Чат и команды Twitch** (текст сообщений, `!команда`, награды по именам) — основа
  интеграции уже есть, остальное записано в [`docs/BACKLOG.md`](docs/BACKLOG.md).
- Своя папка для файлов всех пресетов и синхронизация между устройствами: сейчас файлы
  объектов лежат рядом с пресетом (`<имя>.assets/`), переносится пара «файл пресета + папка».
- Подтверждённый нагрузочный бюджет на 100–200 спрайтах и Windows/OBS-прототипы
  (прозрачное окно и захват в OBS на реальной Windows-машине ещё не проверялись).

Планировщик кадров и сервер оверлея уже перенесены в приложение (см. «OBS-оверлей»).
Следующий логический этап — нативный аудиозахват в Rust, затем нагрузочная оптимизация
на реальных пресетах.
