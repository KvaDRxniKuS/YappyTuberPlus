# YappyTuberPlus

Производительный редактор PNG-ригов: между PNGTuber и Live2D. Проект собирается целиком в этой папке.

## Статус: рабочий MVP 0.1 + OBS-оверлей

Уже есть интерактивный редактор с демо-персонажем, Rust-движок формул, WebAssembly-версия для браузерного предпросмотра, нативная оболочка Tauri 2 и прозрачный оверлей для OBS с единым драйвером кадров.

Основной дизайн-документ: [`docs/DESIGN.md`](docs/DESIGN.md).  
Исходная ревизия без изменений: [`docs/reference/original-rig-rev4.md`](docs/reference/original-rig-rev4.md).

## Что работает

### Редактор

- Импорт одного или нескольких PNG/WebP; изображения сохраняются внутри пресета как data URL
  и встают в центр холста (пачка файлов больше не разъезжается каскадом).
- Дерево спрайтов и групп, выбор, видимость, дублирование, удаление и drag&drop перепривязка.
- Новый объект встаёт в иерархию по выделению: один выделенный — новый становится его ребёнком;
  несколько — новый становится их родителем и **встаёт внутрь их общего родителя** (если все
  выделенные лежат в одной группе), а не в корень сцены.
- Перепривязка не затирает пользовательские формулы; циклы родителей запрещены.
- Canvas-сцена с зумом, панорамированием, сеткой, пивотами и выбором верхнего спрайта.
- Прямое перемещение спрайта мышью с изменением `base.x/base.y`; всё его поддерево двигается согласованно.
- Инспектор базовой позы, масштаба, слоя, прозрачности и UV-пивота (пивот есть и у группы: у
  спрайта он сдвигает картинку относительно точки привязки, у группы задаёт «тяжёлую» сторону
  физики, а дети в любом случае ходят вокруг позиции группы). Формулы живут только в
  скрипте объекта на вкладке «Объект» — инспектор их не дублирует. Шаг стрелок у каждого числа
  свой и вводится руками: чип с числом **между кнопками** `−`/`+` (например, `1` для угла или
  `5` для позиции), значение запоминается для всех объектов.
- CodeMirror 6: подсветка, автодополнение, подсказки по аргументам функций, история и автоприменение через 420 мс.
- Настраиваемые размеры дерева, сцены, инспектора, скрипта и панели значений. Раскладка сохраняется отдельно от пресета.
- Undo/Redo для операций редактирования.

### Движок

- Собственный безопасный DSL на Rust, без JavaScript `eval`.
- Парсер, AST, приоритет операторов, тернарный оператор, векторы и доступ `.x/.y`.
- Глобальные переменные и вычисление зависимостей независимо от порядка строк.
- `parent`, `inherit`, `offset`, `follow`, многоуровневая иерархия и защита от циклов.
- Математические, векторные, случайные и stateful-функции, включая `smooth`, `spring`, `noise`, `shake` и `autoblink`.
- Санитизация `NaN`/`Infinity`, округление `visible`, сортировка слоёв и ограничение до 256 объектов.
- Один `rig-core` используется в браузере через WASM и нативно через Tauri.

### Поведение без кода: пресет как в PNGTuber

Первая вкладка правой панели — **«Поведение»** (левее «Объекта»). Это набор ползунков для
выбранного объекта: новичку его хватает, а код всё равно остаётся доступен.

| Настройка | Что делает | Во что превращается |
|---|---|---|
| Сглаживание | фильтр на **итоговое** движение по оси: наследство родителя, покачивание и подпрыгивание вместе (0 — без фильтра) | `y = smooth(inherit + follow(offset, parent).y - mic.speak * 60 + …, 130)` |
| Пружина | сила = резкость: чем больше, тем резче тянет и сильнее качается; гасит её сглаживание | `y = spring(…, 5.5, 0.47)` |
| Сглаживание поворота | фильтр на **итоговый** угол: наследуемый угол родителя и собственный доворот вместе; с физикой работает как трение | `rotation = smooth(inherit + spring(mic.speak * 12, …), 90)` |
| Пружина поворота | пружина на итоговом угле — реакция объекта целиком, а не только следование за родителем | `rotation = spring(inherit + mic.speak * 12, 3.1, 0.45)` |
| Размер X/Y | скаляры к базовому размеру спрайта: править высоту и ширину можно прямо в поведении, не заходя в инспектор; умножаются на «Масштаб» из инспектора и работают вместе со сквошем | `sizeX = 1.2` / `sizeY = inherit * 0.8` |
| Сквош + скорости | сжатие по одной оси и растяжение по другой от громкости речи, −1…+1 (минус меняет оси местами); отдельно скорость деформации и возврата | `sizeY = inherit * (1 + smooth(mic.speak * 0.8, …))` |
| Подпрыгивание при речи | подъём вверх на `mic.speak × сила`, пиксели; «Скорость подпрыгивания» задаёт резкость отдельно от фильтра позиции | `y = … - smooth(mic.speak, 120) * 60` |
| · один раз | галочка «Прыгать один раз»: импульс из быстрого фронта и медленного спада — прыжок гаснет, даже если речь продолжается, а в тишине взводится снова | `y = … - max(smooth(mic.speak, 120) - smooth(mic.speak, 700), 0) * 60` |
| Поворот при речи | угол 0…180° и направление: `вправо`, `влево`, `случайно` (плавный шум, сторона меняется сама), `поочерёдно` (перекидывание раз в 1.2 с). Если предел с одной стороны равен нулю, доворот идёт только в разрешённую | `rotation = spring(mic.speak * 30 * sign(cos(time * 5.236)), 2.4, 0.35)` |
| · в диапазоне | угол — это максимум, фактический поворот выбирается случайно от 0 до него на каждую «фразу» (~0.7 с) | `mic.speak * rnd(floor(time * 1.5) + seed, 0, 30)` |
| Предел влево / вправо | диапазон сустава **вокруг положения покоя**: ноль с одной стороны — честный запрет в эту сторону, оба нуля — предела нет. С физикой ограничивают свободное качание, толчок при этом не бывает сильнее предела | `inherit + limit(угол, -5, 40)` |
| Покачивание X/Y | плавная детерминированная синусоида с частотой и амплитудой; у каждой оси своя галочка «Случайно» — она меняет синусоиду на шум | `+ sin(time * 2 * pi * 1.2 + 2.827) * 10` / `+ noise(seed, 1.6) * 10` |
| Покачивание угла | то же для поворота, со своим переключателем случайности: хвосту нужен шум, маятнику — синусоида | `+ sin(time * 2 * pi * 0.9 + 1.885) * 12` |
| Видимость · рот | `×` — не трогать, `открыт` — виден при речи, `закрыт` — в тишине | `visible = (mic.talking > 0 or mic.speak > 0.05) ? 1 : 0` |
| Видимость · глаз | `открыт` — когда глаза открыты, `закрыт` — на моргании | `visible = 1 - auto.blink` / `visible = auto.blink` |
| Физика поворота | мотор: пружина тянет «тяжёлую» сторону (дальнюю от пивота) к углу — 0° вниз, 90° вправо, 180° вверх. **«Сила»** — резкость (частота 1.8…8 Гц), **«Плавность»** — вязкость (затухание 0.02…0.70): при 0 мотор звонкий и качается долго, при 1 гаснет за пару качков. Пивот — плечо, его сдвигают к краю | `rotation = spring(<угол> + импульс, 4.28, 0.29)` |
| · импульс | «Поворот при речи» — это **толчок**, а не постоянная сила: быстрый фронт минус медленный спад, мотор получает удар и качается сам, пока его не остановит затухание, сглаживание или предел (толчок не бывает сильнее предела) | `rotation = spring(0 + max(smooth(mic.speak, 60) - smooth(mic.speak, 260), 0) * 30, 6.0, 0.02)` |
| · координаты | **мировая** — спрайт держит угол в мире и противостоит повороту тела (подвеска, серьга, прядь): тело крутится, спрайт на месте; **родительская** — угол задан внутри тела, тело подхватывает спрайт (рука на плече) | `spring(<угол> - inherit, …)` / `spring(inherit + <угол>, …)` |

Как это устроено:

- при мультивыделении панель правит поведение **сразу у всех выделенных**: значения показаны по
  последнему выбранному, а каждому объекту пишется только тронутое поле — его собственные
  настройки (прыжок, сквош, покачивание) остаются. Сброс ✕ очищает блоки у всего выделения, и
  всё это один шаг истории;
- ползунки **пишут формулы в скрипт объекта** — в начало, в блок между комментариями
  `── поведение … ──`. На вкладке «Объект» видно ровно то, что считается; блок можно удалить и
  писать руками, тогда вкладка просто покажет нули;
- настройки лежат в том же блоке JSON-строкой `// @behaviour {…}`, поэтому вкладка и код не
  расходятся и настройки едут вместе с объектом в пресете;
- когда блок берёт на себя `x`, `y`, `rotation`, `sizeX`, `sizeY` или `visible`, одноимённые
  присваивания из остатка скрипта убираются (внутри `on … { }` не трогаются) — иначе ядро
  ругалось бы на двойное присваивание. Всё это один шаг истории: Ctrl+Z возвращает и код;
- кнопка **✕** в шапке сбрасывает поведение и удаляет блок;
- если заданы и рот, и глаз, условия перемножаются: слой виден, когда верно и то, и другое;
- фильтр (сглаживание и пружина) стоит **после сборки цели**, поэтому работает и у объекта без
  родителя: он реагирует на подпрыгивание, доворот и покачивание так же, как на трансформацию
  родителя. Угол фильтруется так же целиком; предел после фильтра ограничивает только отклонение
  от родителя, поэтому сустав остаётся честным;
- «Поворот при речи» с физикой — это толчок, без физики — постоянное давление; покачивание от
  него не зависит и настраивается отдельно, у каждой оси (включая поворот) своя случайность;
- любое число в ползунке можно вписать руками: клик по значению справа превращает его в поле
  ввода (точка или запятая — как удобно).

**Про физику.** `phys rotation` (мировой разворот тяжёлой стороны) уже есть — он живёт в блоке
поведения. `phys squash` (сжатие по направлению абсолютного движения) и `phys move` (гравитация
для падающих объектов) пока не реализованы: им нужны мировые скорости и собственное состояние
на объект, а это уже ядро, а не формулы. Направление реализации описано в `docs/DESIGN.md` §5.6.

### Скрипты: параметры, чужие объекты, события

Скрипт — это обычные присваивания и блоки событий. Присваивания выполняются каждый кадр:
в скрипте объекта слева стоит параметр этого объекта, в `globals.rig` — глобальная
переменная. Слева можно назвать и чужой объект: тогда параметр задаётся ему.

```text
x = 200                 # свой параметр или глобальная переменная
head.rotation = 15      # чужому объекту: объект.параметр
speed = 3
```

Параметры объекта: `x`, `y`, `rotation` (или `rot`), `sizeX`, `sizeY`, `skewX`, `skewY`,
`opacity`, `visible`, `layer`. Варианты с подчёркиванием (`size_x`, `skew_y`) — те же имена.

Событие — блок `on <условие> { … }`; тело пишет автор сцены, жёсткого набора действий нет.

| Условие | Когда срабатывает |
|---|---|
| `on start { … }` | первый кадр после запуска и после «Стоп» |
| `on <модуль>.<вход>.<тип> { … }` | прямо на вход модуля: `mouse.left.down` |
| `on <имя> { … }` | на именованное событие, объявленное через `trigger` |

```text
trigger kick = mouse.left.down      # объявляется только в globals.rig
trigger breath = mic.talking.relax(0.6)

on kick { a = !a }
on mouse.right.up { a = 0 }
on start { a = 0 }
```

Имя из `trigger` одно на всю сцену, поэтому подписаться на него может и глобальный скрипт,
и скрипт любого объекта. Префикс `event.` необязателен: `on event.mouse.left.down` — то же
самое, что `on mouse.left.down`.

| Тип | Когда срабатывает |
|---|---|
| `down` | значение перешло из 0 в 1: нажатие, начало речи |
| `up` | значение вернулось в 0: отпускание |
| `change` | значение изменилось с прошлого кадра (аналоговые входы вроде `mouse.x`) |
| `hold(0.5)` | вход держится дольше 0,5 с — один раз за удержание |
| `relax(0.5)` | вход отпущен дольше 0,5 с — один раз за отпускание |

Порог «включено» у всех типов один — `0.5` значения входа; второго аргумента у `hold`/`relax`
нет. Удержание всегда срабатывает **кадром позже** фронта: `hold(0)` — это не `down`, а «на
следующем кадре после нажатия», и точно так же `relax(0)` — кадром позже `up`.

Правила, на которые можно опираться:

- тело блока — обычные присваивания, в том числе чужим объектам;
- **своя переменная в теле — это прошлый кадр**: `a = !a` читает `a` из предыдущего кадра,
  поэтому переключатель работает одной строкой; явно то же самое пишется как `state.a`;
- порядок кадра: сначала события, затем записи чужим объектам, затем формулы. Поэтому
  `head.x = …` в обычном присваивании выполняется каждый кадр и параметр принадлежит этой
  записи, а та же строка в теле события задаёт параметр только на кадр срабатывания;
- переменная, которую меняет только событие, видна в формулах по имени — это глобальная
  переменная без выражения;
- события считаются по значениям входов модулей, поэтому годится любой вход:
  `mouse.back.down`, `board.space.up`, `mic.talking.hold(1)`;
- **Стоп** и перезапуск обнуляют состояние событий и снова делают кадр первым для `on start`.

Прошлый кадр доступен явно: `state.a` — глобальная переменная, `state.x` — параметр своего
объекта. Чужой объект читается по имени (`рот.x`, `рот.parent.y`); одна ступень `parent` —
родитель названного объекта. Конфликт имён решается в пользу своих параметров, затем
глобальных переменных, затем объектов.

Ошибка в скрипте не останавливает сцену: скрипт с ошибкой просто не участвует в кадре, а
сообщение с номером строки и столбца попадает в диагностику под сценой и подчёркивается в
редакторе. В ядре событие — отдельная инструкция (`EventBlock`), а не формула: рантайм
держит для него прошлое значение, таймер удержания и защёлку.

### Редактор скрипта: подсказки по аргументам

- `on ` подсказывает условия: `start`, имена из `trigger` и входы модулей; выбранный вход
  подсказывает типы (`down`, `up`, `change`, `hold(0.5)`, `relax(0.5)`) и сразу раскрывает
  тело блока.
- `trigger ` подсказывает готовое объявление `trigger имя = модуль.вход.тип`.
- После `объект.` подсказываются параметры этого объекта — так пишется запись чужому объекту.
- Ошибка разбора подчёркивается прямо в тексте, а её сообщение видно под редактором.
- Каждая функция в автодополнении показана с сигнатурой: `spring(target, frequencyHz, damping)`,
  а во второй строке — что она делает.
- Курсор внутри вызова показывает строку с ожидаемыми аргументами и подсвечивает текущий:
  `spring(target, frequencyHz, damping) — аргумент 3 из 3: damping`.
- После `state.` подсказываются глобальные переменные и параметры объекта — это значение
  прошлого кадра.
- Под редактором — список всех функций с сигнатурами; клик вставляет вызов и ставит каретку
  в скобки. Необязательные аргументы помечены `?`.
- **Избранные команды:** звёздочка у функции в списке закрепляет её строкой «★ Избранные» под
  редактором — вызов вставляется одним кликом, без раскрытия списка. Закладки живут в браузере,
  а не в пресете, и переживают перезапуск.
- В заголовке события модуль и вход подсвечены как свойства, а тип (`down`, `hold`, …) — своим
  цветом; после `{` подсветка заголовка заканчивается.

### Цепочки: хвост, лента, усы

Хвост — это не отдельная физика, а цепочка родителей и один скрипт на сегмент. Кнопка
**«Цепочка · пружина»** в панели структуры связывает выделенные объекты в порядке выделения
(первый — корень, дальше к кончику) и пишет каждому сегменту такой скрипт:

```text
x = inherit + follow(offset, parent).x
y = inherit + follow(offset, parent).y
rotation = spring(inherit + 4 + noise(42, 0.3) * 2.5, 2.02, 0.33)
sizeX = inherit
sizeY = inherit
layer = inherit
```

Что за этим стоит:

- `inherit` — значение родителя в этом кадре, `follow(offset, parent)` — насколько сегмент
  съехал из-за поворота и масштаба родителя. Вместе это обычная иерархия, только формулой.
- `spring` — пружина: она тянется за углом родителя и **отстаёт**. Отставание и есть волна,
  которая бежит от корня к кончику; `noise` в цели даёт покачивание в покое.
- По цепочке частота падает, а затухание растёт: кончик догоняет мягче и не дребезжит.

Как подбирать:

| Частота | Затухание | Ощущение |
|---|---|---|
| 3–5 Гц | 0.1–0.2 | упругий, «резиновый» хвост |
| 1.5–2.5 Гц | 0.25–0.4 | обычный машущий хвост |
| 0.8–1.2 Гц | 0.4–0.6 | тяжёлый, ленивый |

- **Изгиб покоя** задаёт закрутку: `4` — дуга в одну сторону, `-4` — в другую.
- **Шарнир** переставляет пивот на верхнюю кромку и сдвигает базу так, чтобы спрайт остался
  на месте: сегменты вращаются вокруг стыка, а не вокруг своего центра.
- Корень без родителя не переписывается — его движение это движение персонажа, а не хвоста.
  Чтобы качался и он, вложите его в группу и свяжите заново.
- Цепочку можно собрать и руками: вложите объекты друг в друга (перетаскиванием в дереве) и
  вставьте в каждый строку `rotation = spring(inherit + 4, 2.2, 0.3)`. Кнопка просто делает
  это за вас и сразу выставляет шарниры.
- Хвост из пяти сегментов — это пять скриптов, а не пять физических тел: ядро считает каждую
  пружину как обычную stateful-функцию, лишних кадров это не стоит.

### Кадры, входы и файлы

- Явный лимит FPS `1–240`, быстрые значения и режим по частоте экрана.
- Фактический FPS, пауза и покадровый шаг; изменение лимита не пересоздает движок.
- Все входы — из **модулей**: `mic.talking`, `mic_left.db`, `viseme.a`, `viseme.o_umlaut`, `manual.blink`;
  встроенных имён вроде `speak` в ядре больше нет.
- Любой вход модуля годится для события: `event.mouse.left.down`, `event.board.space.down`,
  `event.mouse.back.hold(0.4)`, `event.viseme.a.up`.
- Несколько экземпляров одного модуля: два Loudness слушают два разных микрофона,
  у каждого свой источник, устройство, усиление и порог речи.
- Автосохранение в localStorage, явное сохранение, импорт и экспорт JSON-пресета версии 2.
- Демонстрационный риг из отдельных PNG-спрайтов: два рта в одной точке — открытый при речи и
  закрытая улыбка при молчании (по `mic.talking` и `mic.speak` из модуля Loudness).
- Спрайты демо генерируются воспроизводимо: `node scripts/generate-demo-sprites.mjs`.

### Модули и входы

- Экземпляры модулей: **Loudness** (микрофон или отладочный ползунок), **AutoBlink**
  (моргание по таймеру), **Manual** (вход 0/1 или число с границами), **Viseme**
  (похожесть звука на записанные эталоны, свои звуки, варианты записи, контраст,
  нормализация суммы), **Keyboard** / **Key** / **Mouse** (клавиши и курсор как входы:
  в нативном окне ловятся глобально, без перехвата клавиш);
  имя экземпляра — префикс входа, поэтому `mic.talking` и `mic_left.talking` живут рядом.
- Шаблоны модулей — JSON в `public/modules/` (`index.json` + `<id>.json`): входы и поля
  настроек описываются данными, поведение выбирает поле `kind`. Новый шаблон — новый файл.
- Панель модулей: поиск по включённым сверху, палитра «Добавить модуль» снизу, у каждого
  входа свой флажок (выключенный вход не уходит в кадр).
- Микрофоны через Web Audio: выбор устройства для каждого экземпляра, общий поток на
  устройство, усиление, порог речи, индикатор уровня и отключаемое шумоподавление.
- Отдельной кнопки «включить микрофон» нет: звук поднимается сам, когда в модели есть
  включённый микрофонный модуль; `AudioContext` дополнительно будится первым нажатием,
  иначе WebView2 оставляет его в `suspended` и анализатор молчит.
- Модули хранятся в пресете; при открытии чужого набора спрашиваем
  **применить / оставить как есть / отключить все**. Старые пресеты переносятся
  автоматически (`talking` → `mic.talking`, `signal.blink`/`manual.blink` → `auto.blink`).

Подробности: [`docs/MODULES.md`](docs/MODULES.md).

### OBS-оверлей

- Отдельное прозрачное окно Tauri без рамки, тени и значка на панели задач; в браузере — второе окно для проверки.
- Оверлей только рисует: движок, входы и stateful-формулы остаются в редакторе, поэтому кадры не продвигаются дважды.
- Передача сцены один раз, затем только небольшие патчи базовой позы, конфигурации и готовые кадры.
- Настройки в пресете: размер, режим вписывания (`contain`/`cover`/`stretch`/`pixel`), прозрачный/цветной/хромакей-фон, поверх всех окон, пропуск кликов, служебная рамка.
- Транспорты: `BroadcastChannel` в одном браузере, события Tauri между нативными окнами и WebSocket-мост для источника браузера в OBS.
- Общий Canvas 2D-рендер с редактором, статус подключения, счётчик FPS и дедупликация кадров.
- **Окно захвата** (`overlay.html?capture=1`) — второе окно для Discord, Game Bar и «Записи экрана»:
  без рамки, но видно в списке окон; размер и фон общие с оверлеем, прозрачность в нативном окне
  сохраняется и уходит в запись с альфа-каналом (как Spout2/PNGTuber).

Подробности и настройка захвата: [`docs/OVERLAY.md`](docs/OVERLAY.md).

## Быстрый запуск одним файлом

Не нужно ничего вводить в консоль:

- **Windows** — двойной клик по `start-yappytuber.bat`;
- **Linux/macOS** — `./start-yappytuber.sh`.

Файл сам скачивает крайние обновления, при необходимости предлагает поставить Git и
Node.js через `winget`, выполняет `npm ci`, собирает WASM-ядро (если есть Rust) и
открывает редактор в браузере. Подходит и для папки, скачанной ZIP-архивом: скрипт
включает автообновление на месте (`git init` + приведение файлов к ветке), не трогая
новые файлы и сохраняя правки репозитория в `git stash`. Подробности и параметры —
[`docs/LAUNCHER.md`](docs/LAUNCHER.md).

```bat
start-yappytuber.bat --no-open      :: без автооткрытия браузера
start-yappytuber.bat --no-bridge    :: без моста для OBS
start-yappytuber.bat --no-serve     :: только обновить и собрать
start-yappytuber.bat --tauri        :: нативное окно Tauri
```

## Запуск редактора вручную

Требования: Node.js 20+, Rust stable и target `wasm32-unknown-unknown`.

```bash
npm install
rustup target add wasm32-unknown-unknown
npm run build:wasm
npm run dev
```

Vite слушает `0.0.0.0:5173`. Без установленного Rust сборка `build:wasm` использует уже
собранный `public/rig_core.wasm` и предупреждает об этом.

Для источника браузера в OBS (необязательно) во втором терминале:

```bash
npm run overlay:bridge
```

Production-сборка:

```bash
npm run build
npm run preview
```

## Tauri / Windows

В `src-tauri` находится нативная команда `rig_call`, подключённая к тому же `RuntimeStore`. Конфигурация рассчитана на Windows и NSIS.

```bash
npm run tauri dev      # нативное окно, фронтенд из Vite
npm run tauri build    # .exe и установщик NSIS, фронтенд внутри
```

Для Windows-сборки нужны Rust (`stable-x86_64-pc-windows-msvc`), MSVC Build Tools,
Node.js и WebView2; ядро собирается с target `wasm32-unknown-unknown`.
Готовые файлы: `src-tauri/target/release/yappytuberplus.exe` и
`src-tauri/target/release/bundle/nsis/YappyTuberPlus_<версия>_x64-setup.exe`.

Без консоли и без ручной установки компонентов:

1. **`install-build-tools.bat`** — ставит Node.js LTS, Rust, Visual Studio Build Tools (C++)
   и WebView2, если их нет (нужен интернет и подтверждение UAC);
2. **`build-yappytuber.bat`** — собирает `.exe` и установщик и открывает папку с результатом
   (`--no-bundle` — только `.exe`, `--fast` — без пересборки WASM-ядра).

Если ставить ничего не хочется, установщик соберёт GitHub: **Actions** →
**Сборка Windows** → **Run workflow**, готовый файл появится в артефактах.

Пошагово, с требованиями и разбором ошибок — [`docs/BUILD.md`](docs/BUILD.md).
В текущей Linux-среде нативная часть проверена через `cargo check`; Windows-установщик
здесь не создавался.

## Импорт из PNGTuber Plus (`.save`)

`.save` — это JSON, где каждый объект сцены — слой-костюм: `imageData` (PNG в base64),
`pos`/`offset` (в старой версии всегда `Vector2(0, 0)`), `parentId`, `zindex` и флаги показа
`showBlink` / `showTalk`. Хвоста и другой физики в самом файле нет — только картинки и правила
их показа.

Перевод в пресет YappyTuberPlus:

| Поле `.save` | Куда переходит |
|---|---|
| `imageData` | сохранить как PNG рядом со своим пресетом и указать путь в `image` |
| `pos` + полный холст 1200×600 | `base.x/y` = центр холста, `pivot` = `0.5, 0.5`, `width/height` = размер PNG |
| `showTalk = 0` | слой виден всегда |
| `showTalk = 1` | `visible = mic.talking > 0 ? 0 : 1` (вариант «молчит») |
| `showTalk = 2` | `visible = mic.talking > 0 ? 1 : 0` (вариант «говорит») |
| `showBlink = 0` | слой виден всегда |
| `showBlink = 1` | `visible = 1 - auto.blink` (виден, когда глаза открыты) |
| `showBlink = 2` | `visible = auto.blink` (виден на моргании) |
| `stretchAmount`, `drag`, `rotDrag`, `rLimitMin/Max`, `xAmp/xFrq/yAmp/yFrq`, `ignoreBounce` | прямого аналога нет: это «пружина/растяжение» PNGTuber. У нас то же самое пишется формулами: `sizeY = spring(…)`, `noise`, `shake` |

Картинки из чужого `.save` — это личные аватары: в репозиторий они не попадают. Конвертация
делается локально, файлы кладите в свою папку (`public/assets/...` для своего форка или рядом с
пресетом), а альтернативные кадры лиц оставляйте выключенными (`visible = 0`) — нужный
включается вместо основного.

## Что ещё не входит в этот MVP

- Планировщик кадров в Rust: сейчас кадры продвигает видимое окно редактора, поэтому
  в браузере скрытая вкладка останавливает поток в оверлей. Нативная сборка с Rust
  runtime и `rig_latest_frame` снимет это ограничение.
- Встроенный в Tauri сервер для источника браузера: пока используется отдельный
  `npm run overlay:bridge`.
- Нативный Rust-аудиозахват; сейчас микрофон реализован браузерным способом.
- Плагины, виземы от внешней модели, кадровая анимация и IK.
- Окончательный перенос ассетов из data URL в файловое хранилище приложения.
- Подтверждённый нагрузочный бюджет на 100–200 спрайтах и Windows/OBS-прототипы
  (прозрачное окно и захват в OBS на реальной Windows-машине ещё не проверялись).

Следующий логический этап — перенос планировщика и аудио в Rust, затем нагрузочная
оптимизация на реальных пресетах.
