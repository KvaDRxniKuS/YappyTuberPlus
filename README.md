# YappyTuberPlus

Производительный редактор PNG-ригов: между PNGTuber и Live2D. Проект собирается целиком в этой папке.

## Статус: рабочий MVP 0.1 + OBS-оверлей

Уже есть интерактивный редактор с демо-персонажем, Rust-движок формул, WebAssembly-версия для браузерного предпросмотра, нативная оболочка Tauri 2 и прозрачный оверлей для OBS с единым драйвером кадров.

Основной дизайн-документ: [`docs/DESIGN.md`](docs/DESIGN.md).  
Исходная ревизия без изменений: [`reference/original-rig-rev4.md`](reference/original-rig-rev4.md).

## Что работает

### Редактор

- Импорт одного или нескольких PNG/WebP; изображения сохраняются внутри пресета как data URL.
- Дерево спрайтов и групп, выбор, видимость, дублирование, удаление и drag&drop перепривязка.
- Перепривязка не затирает пользовательские формулы; циклы родителей запрещены.
- Canvas-сцена с зумом, панорамированием, сеткой, пивотами и выбором верхнего спрайта.
- Прямое перемещение спрайта мышью с изменением `base.x/base.y`; всё его поддерево двигается согласованно.
- Инспектор базовой позы, масштаба, слоя, прозрачности, UV-пивота и быстрых формул.
- CodeMirror 6: подсветка, автодополнение, история и автоприменение через 420 мс.
- Настраиваемые размеры дерева, сцены, инспектора, скрипта и панели значений. Раскладка сохраняется отдельно от пресета.
- Undo/Redo для операций редактирования.

### Движок

- Собственный безопасный DSL на Rust, без JavaScript `eval`.
- Парсер, AST, приоритет операторов, тернарный оператор, векторы и доступ `.x/.y`.
- Глобальные переменные и вычисление зависимостей независимо от порядка строк.
- `parent`, `inherit`, `offset`, `follow`, многоуровневая иерархия и защита от циклов.
- Математические, векторные, случайные и stateful-функции, включая `smooth`, `spring`, `noise`, `shake` и `autoblink`.
- Санитизация `NaN`/`Infinity`, округление `visible`, сортировка слоёв и ограничение до 256 объектов.
- Один `rig-core` используется в браузере через WASM и нативно через Tauri.

### Кадры, входы и файлы

- Явный лимит FPS `1–240`, быстрые значения и режим по частоте экрана.
- Фактический FPS, пауза и покадровый шаг; изменение лимита не пересоздает движок.
- Тестовые `speak`, `loudness`, `talking`, виземы и ручное моргание.
- Микрофон через Web Audio в браузерном MVP: RMS, пик, dB и сглаженный уровень речи.
- Автосохранение в localStorage, явное сохранение, импорт и экспорт JSON-пресета версии 2.
- Демонстрационный риг из отдельных PNG-спрайтов.

### OBS-оверлей

- Отдельное прозрачное окно Tauri без рамки, тени и значка на панели задач; в браузере — второе окно для проверки.
- Оверлей только рисует: движок, входы и stateful-формулы остаются в редакторе, поэтому кадры не продвигаются дважды.
- Передача сцены один раз, затем только небольшие патчи базовой позы, конфигурации и готовые кадры.
- Настройки в пресете: размер, режим вписывания (`contain`/`cover`/`stretch`/`pixel`), прозрачный/цветной/хромакей-фон, поверх всех окон, пропуск кликов, служебная рамка.
- Транспорты: `BroadcastChannel` в одном браузере, события Tauri между нативными окнами и WebSocket-мост для источника браузера в OBS.
- Общий Canvas 2D-рендер с редактором, статус подключения, счётчик FPS и дедупликация кадров.

Подробности и настройка захвата: [`docs/OVERLAY.md`](docs/OVERLAY.md).

## Запуск редактора

Требования: Node.js 20+, Rust stable и target `wasm32-unknown-unknown`.

```bash
npm install
rustup target add wasm32-unknown-unknown
npm run build:wasm
npm run dev
```

Vite слушает `0.0.0.0:5173`. Без установленного Rust сборка `build:wasm` использует уже
собранный `public/rig_core.wasm` и предупреждает об этом.

Для источника браузера в OBS (необязательно) во втором терминале:

```bash
npm run overlay:bridge
```

Production-сборка:

```bash
npm run build
npm run preview
```

## Tauri / Windows

В `src-tauri` находится нативная команда `rig_call`, подключённая к тому же `RuntimeStore`. Конфигурация рассчитана на Windows и NSIS.

```bash
npm run tauri dev
npm run tauri build
```

Для Windows-сборки нужны Rust, Node.js, WebView2 и стандартные инструменты сборки Tauri/MSVC. В текущей Linux-среде нативная часть проверена через `cargo check`; Windows-установщик здесь не создавался.

## Проверки

```bash
cargo test -p rig-core
cargo clippy -p rig-core -- -D warnings
npm run test:engine     # контракт Rust/WASM напрямую в Node
npm run test:e2e        # включает headless-проверки оверлея и рендера
```

Для первого запуска браузерных тестов:

```bash
npx playwright install chromium
```

Текущий набор: **10 Rust-тестов**, **10 проверок движка в Node** (`test:engine`),
**8 headless-проверок** Playwright (протокол оверлея, heartbeat, дедупликация кадров, таймауты,
view transform и рендер через записывающий контекст) и **11 браузерных проверок**.
Проверяются запуск WASM, реальный лимит 30 FPS, resize панели, перемещение поддерева на
сцене, сохранение формул при перепривязке, редактирование скрипта через инспектор,
пауза/шаг, импорт PNG, передача сцены и кадров в окно оверлея и сохранение его настроек.

## Управление

| Действие | Управление |
|---|---|
| Перемещение спрайта | Левая кнопка + drag на сцене |
| Перемещение по одной оси | `Shift` + drag |
| Панорамирование | `Space` + drag, средняя кнопка или инструмент «Рука» |
| Зум | Колесо мыши |
| Инструмент перемещения / пивота | `V` / `P` |
| Пауза | `K` |
| Undo / Redo | `Ctrl+Z` / `Ctrl+Shift+Z` |
| Сохранить | `Ctrl+S` |
| Размер панели | Перетаскивание разделителя |
| Размер по умолчанию | Двойной клик по разделителю |
| Диалог оверлея | Кнопка «Оверлей» на верхней панели или в строке состояния |

## Что ещё не входит в этот MVP

- Планировщик кадров в Rust: сейчас кадры продвигает видимое окно редактора, поэтому
  в браузере скрытая вкладка останавливает поток в оверлей. Нативная сборка с Rust
  runtime и `rig_latest_frame` снимет это ограничение.
- Встроенный в Tauri сервер для источника браузера: пока используется отдельный
  `npm run overlay:bridge`.
- Нативный Rust-аудиозахват; сейчас микрофон реализован браузерным способом.
- Плагины, виземы от внешней модели, кадровая анимация и IK.
- Окончательный перенос ассетов из data URL в файловое хранилище приложения.
- Подтверждённый нагрузочный бюджет на 100–200 спрайтах и Windows/OBS-прототипы
  (прозрачное окно и захват в OBS на реальной Windows-машине ещё не проверялись).

Следующий логический этап — перенос планировщика и аудио в Rust, затем нагрузочная
оптимизация на реальных пресетах.
