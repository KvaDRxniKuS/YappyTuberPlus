# Где приложение хранит данные

Идентификатор приложения — `com.yappytuberplus.studio` (`identifier` в
`src-tauri/tauri.conf.json`). От него зависят все пути, поэтому **сборка из
исходников и установленное приложение делят одни и те же папки**: профиль
WebView2 и папку пресетов. Именно поэтому после установки может «приехать»
старый аватар из прошлых запусков `npm run tauri dev`.

## Две папки

| Что | Windows | Linux / macOS |
|---|---|---|
| Автосохранение сессии (профиль WebView2) | `%LOCALAPPDATA%\com.yappytuberplus.studio\EBWebView` | Linux: `~/.local/share/com.yappytuberplus.studio/EBWebView`<br>macOS: `~/Library/Application Support/com.yappytuberplus.studio/EBWebView` |
| Файлы объектов сцены (IndexedDB профиля) | `…\EBWebView\Default\IndexedDB\https_*.indexeddb.leveldb` | там же, внутри `EBWebView/Default/IndexedDB` |
| Файлы, сохранённые кнопкой «Сохранить» | `%APPDATA%\com.yappytuberplus.studio\presets` | там же, рядом с профилем |
| Файлы объектов рядом с пресетом | `…\presets\<имя>.assets\` | там же, рядом с `.yappy.json` |

Картинки, GIF, видео и звук приложение хранит **отдельно от пресета** — в
IndexedDB профиля webview (база `yappytuberplus.assets`). Файл разделён на две
записи: `assets` — байты (`id`, `blob`), `meta` — паспорт (`id`, имя файла, MIME,
размер, время, отпечаток `hash`). Список файлов и подсчёт объёма читают только
паспорта, поэтому видео на сотни мегабайт не попадает в память ради строчки
«12 файлов · 240 МБ». В пресете и в автосохранении
вместо байтов остаётся короткая ссылка `asset:<id>`, поэтому:

- в **автосохранении** — `…\EBWebView\Default\Local Storage\leveldb`, ключ
  `yappytuberplus.preset.v2`, там только ссылки;
- в **файле** — `presets\<имя>.yappy.json`: там тоже только ссылки `asset:<id>`,
  поэтому сам JSON весит килобайты;
- рядом с файлом — папка `presets\<имя>.assets\`: в ней лежат сами картинки,
  видео и звук плюс `index.json` с паспортами (id, имя, тип, размер, файл).
  Имена файлов — `<id>.<расширение>`. Пресет и папку переносят вместе.
  **Файлы объекта — это все виды:** картинка, медиа, картинка-маска, карта
  нормалей и карты материала (упакованная ORM, три канала, карта свечения). Карта
  нормалей раньше не попадала ни в список файлов пресета, ни в сохранение, ни в
  папку `.assets`: после переноса или пересохранения объект оставался видимым, а
  объём молча выключался. С картами материала случилось бы то же самое, поэтому
  они проходят те же четыре места (`sourcesOf`, `inlineAssets`, `extractAssets`,
  `writeSidecar`), и тест перечисляет карты поимённо. Ссылка на пропавший файл
  не переписывается — в инспекторе появляется «Файл карты не найден».

Запись делает Rust (`src-tauri/src/lib.rs`, команды `preset_write_assets`,
`preset_clean_assets`, `preset_read_asset`, `preset_asset_index`): `<имя>` — это
имя файла пресета без `.yappy.json`, например `риг.yappy.json` → `риг.yappy.assets`.
Порядок сохранения — сначала файлы, потом JSON, потом уборка лишнего, поэтому
прерванное сохранение не оставляет сцену без картинок. Папка принадлежит
приложению: свои файлы в неё класть не нужно, при следующем сохранении лишние
удаляются.

При открытии пресета файлы читаются **лениво**: `preset_asset_index` отдаёт
паспорта, а `preset_read_asset` вызывается только когда объект действительно
нужно нарисовать, и прочитанное сразу ложится в IndexedDB. Так видео на сотни
мегабайт не попадает в память целиком. data URL внутри старого JSON при
открытии, наоборот, распаковываются в IndexedDB — это делает
`src/engine/assets.ts` (`extractAssets` / `inlineAssets`).

**«Экспорт JSON»** встраивает файлы обратно в data URL: получается один
самодостаточный файл, который можно отдать другому человеку без папки.

## Что лежит в автосохранении

Приложение записывает в `localStorage` webview (это и есть папка
`EBWebView\Default\Local Storage\leveldb`, формат LevelDB — открывать его
блокнотом бессмысленно):

| Ключ | Что это |
|---|---|
| `yappytuberplus.preset.v2` | последний пресет целиком; вместо файлов — ссылки `asset:<id>` |
| `yappytuberplus.layout.v1` | раскладка панелей: ширины, высоты, свёрнутость |
| `yappytuberplus.favorites.v1` | избранные модули |
| `yappytuberplus.preset.path.v1` | путь последнего открытого файла пресета: по нему на старте находится папка `<имя>.assets` (в самом пресете только ссылки) |
| `yappytuberplus.cheatsheet.height.v1` | высота открытой шпаргалки в редакторе скрипта, по умолчанию `190` |
| `yappytuber.inspector-steps` | шаги стрелок в инспекторе (ключ без `plus` — так исторически сложилось) |
| `yappytuberplus.update.skip` | версия, которую попросили больше не предлагать: `1.0.22.3.1.1.1@abc1234` (версия + коммит, чтобы пропуск не скрыл багфикс с тем же номером) |

При старте `loadPreset()` (`src/App.tsx`) сначала берёт
`yappytuberplus.preset.v2` и только если его нет — демо-персонажа. Так и
появляется «откуда-то взявшийся» старый аватар: он лежит в этом автосохранении,
а не в установщике и не в репозитории.

## Как это почистить

Двойной клик по **`reset-yappytuber-data.bat`** (Windows) или
`./reset-yappytuber-data.sh` (Linux/macOS): скрипт покажет оба пути и спросит,
что удалять.

| Ключ | Что делает |
|---|---|
| `--profile` | удаляет профиль WebView2: автосохранение пресета, картинки, раскладку. Приложение стартует с демо-персонажа |
| `--presets` | удаляет `*.yappy.json` и папки `*.assets` из папки пресетов |
| `--all` | и то, и другое |

Перед удалением закройте приложение: WebView2 держит профиль открытым, и
часть файлов останется. Скрипт это проверяет и сам предупреждает.

Вручную то же самое: удалить папку `…\com.yappytuberplus.studio\EBWebView` при
закрытом приложении.

## Заменить испорченную картинку, не потеряв риг

Раньше единственным способом было «удалить спрайт и импортировать заново», а
вместе со спрайтом пропадали скрипт, дети, пивот и поведение. Теперь в
инспекторе есть блок **«Картинка»**:

- **«Заменить»** — меняется только `image`, размеры и точка привязки остаются
  прежними (подходит, когда новая картинка того же размера);
- **«Заменить и подогнать размер»** — `width/height` берутся из новой картинки,
  а пивот пересчитывается так, чтобы прежняя точка привязки осталась на том же
  месте картинки.

Идентификатор объекта, скрипты, иерархия и настройки поведения при этом не
меняются, поэтому формулы и «Поведение» продолжают работать.

## Файлы объектов сцены

Файлы никогда не попадают в `localStorage` и не сериализуются на каждую правку:

| Место | Что там |
|---|---|
| IndexedDB `yappytuberplus.assets`, хранилище `assets` | сами байты: `blob` |
| IndexedDB `yappytuberplus.assets`, хранилище `meta` | паспорт: имя, MIME, размер, время, отпечаток |
| Пресет в памяти, автосохранение | ссылка `asset:<id>` |
| Файл пресета на диске | data URL (файлы встроены, пресет самодостаточен) |

Что из этого следует:

- **Автосохранение больше не упирается в квоту** — строка пресета весит килобайты даже с
  видео. Сообщение «превышена квота браузера» может появиться только на действительно
  гигантском тексте/скрипте.
- **Оверлей и окно захвата** берут файлы из того же IndexedDB (общий origin), а источник
  браузера в OBS открывается со встроенного сервера — другого origin, поэтому файл
  запрашивается по протоколу оверлея (`asset-request` → `asset`) и кэшируется у страницы.
- **Уборка**: на старте приложения файлы, на которые не ссылается загруженный пресет,
  удаляются (история отмены в этот момент пуста). Внутри сессии автоматической уборки нет:
  файл, который понадобится после `Ctrl+Z`, не должен исчезнуть. Разобрать накопленное
  можно кнопкой **«Файлы объектов»** в верхней панели (иконка диска): там видно имя,
  тип, размер и состояние каждого файла, а «Убрать неиспользуемые» удаляет только тех,
  на кого не ссылаются ни сцена, **ни шаги истории отмены**.
- **Повторный импорт**: одинаковые файлы хранятся один раз — отпечаток содержимого
  (SHA-256 для файлов до 32 МБ, для крупных — размер + тип + имя) уже есть, ссылка
  возвращается прежняя. Поэтому «заменить картинку» на ту же самую ничего не дублирует.
- **Пропавший файл**: если ссылка есть, а файла в хранилище нет (профиль чистили, пресет
  пришёл с другой машины без встроенных data URL), сохранение не подменяет картинку
  пустотой: в сообщении после «Сохранить» перечисляются объекты, чьи файлы не нашлись.
- **Перенос на другую машину** — только файлом пресета (или `.json`-экспортом): ссылки
  `asset:<id>` между машинами не работают, а встроенные data URL работают всегда.
- **Браузер разработки** (не Tauri) ведёт себя так же: хранилище принадлежит origin Vite, и
  очистка данных сайта стирает файлы — они придут из пресета при следующем открытии.

Если IndexedDB недоступна (приватный режим, испорченный профиль), импорт кладёт файл в
пресет как data URL, и всё работает по-старому — просто автосохранение снова тяжёлое.

## Медиа и текст в пресете

У медиа-объекта `media.src` — та же ссылка `asset:<id>`; на диск видео уходит вместе с
пресетом, поэтому файл может весить как содержимое. Держите медиа короткими и при
необходимости выносите тяжёлое видео в OBS отдельным слоем.

Текст живёт в пресете шаблоном (`text.template`), а сообщения чата — нет: они приходят из
модуля и попадают только в кадр. Поэтому пресет с текстовым объектом остаётся маленьким.

## Пометки версий в файлах

Файлы помнят, кто их записал, — чтобы расхождение было видно, а не выяснялось по
испорченной картинке. Полный паспорт версии и правила роста слотов —
[`docs/VERSIONS.md`](VERSIONS.md).

| Где | Поле | Что значит |
|---|---|---|
| Пресет, верхний уровень | `version: 3` | поколение формата пресета. Ядро читает `2` (старое дозаполняется) и `3`; файл новее редактора не открывается — вместо него сообщение `пресет новее` |
| Пресет, верхний уровень | `built: "1.0.21.3.1.1.1"` | какая сборка записала файл. Только для человека и диагностики: на совместимость не влияет и в историю отмены не попадает |
| Пресет, верхний уровень | `needs: 21` | минимальное поколение ядра, при котором сцена посчитается. Считается по содержимому при сохранении: виды объектов, функции и параметры, которые реально используются |
| Шаблон модуля (`public/modules/*.json`) | `format: 1` | контракт шаблона. Модуль без поля считается формата `1`; незнакомое поколение показывается плашкой `модули`, а незнакомый вид — как «Manual» |
| Answer ядра на `Version` | `core: 21`, `acceptsFrom: 16` | поколение собранного `rig_core.wasm` и старейшее поколение сценариев, которое он ещё понимает. Отстало до `needs` — строка состояния говорит пересобрать (`npm run build:wasm`) |
| Оверлей, `hello` | `protocol: 1` | сборка страницы в OBS. Чужой `protocol` → `оверлей старой сборки` |

Практические следствия:

- **`built` — не версия пресета.** Он пишется при сохранении в файл на диске и не
  появляется в состоянии редактора, поэтому открытие и повторное сохранение не
  меняют историю отмены. `needs` считается там же, в момент записи: в памяти
  сцены его нет, поэтому правка формулы требования не «замораживает».
- **`built` и `needs` отвечают на разные вопросы.** `built` — чем файл записан
  (для поддержки), `needs` — что сцене нужно от ядра. Редактор с ядром 21
  спокойно открывает сцену с `needs: 4`: старое поведение никуда не делось.
- **Старые файлы без `needs`** читаются как обычно: требование тогда считается
  по фактической сцене, а не по файлу.
- **Старый файл открывается молча**, но после сохранения становится текущего
  формата: обратной миграции нет.
- **`version` у пресета и `format` у модуля — разные поля** с разными числами:
  первое про файл сцены, второе про шаблон источника.
- **`format` у модуля важнее, чем его содержимое**: модуль незнакомого поколения
  лучше показать с пометкой, чем разобрать наполовину.
- **Номера слоёв не связаны между собой**: редактор текущего релиза с ядром
  предыдущего поколения — рабочее состояние, просто с ограниченным DSL.

## Чего в этих папках нет

- Ассетов демо-персонажа: они лежат в `public/assets/demo/` и попадают внутрь
  сборки (`dist`), а не в профиль.
- Кэша оверлея: окно оверлея — та же страница приложения, состояние рига оно не
  хранит.
- Логов: приложение не пишет лог-файлов; диагностика видна в строке статуса.
- Паспорта сборки: `build.json` лежит рядом с программой (в `dist` или внутри
  установщика), а не в профиле пользователя. Приложение его только читает;
  меняет его сборка (`npm run build`) или агент обновления, когда заменяет файлы
  папки целиком (`scripts/update-agent.mjs`).
- Скачанного обновления: агент кладёт файлы сразу в папку сборки, минуя профиль.
  Пока все файлы не проверены по `sha256`, на диск ничего не пишется; недокачанное
  обновление остаётся в памяти и пропадает вместе с запросом.
