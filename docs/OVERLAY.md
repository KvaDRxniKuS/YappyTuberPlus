# OBS-оверлей

Прозрачное окно с ригом для OBS. Оверлей **только рисует готовые кадры**: движок,
глобальные переменные и stateful-функции считает редактор. Одна симуляция — один
источник продвижения кадров, поэтому `spring`, `smooth` и `autoblink` не шагают дважды,
а пауза в редакторе совпадает с картинкой в OBS.

Реализация соответствует §13 дизайн-документа: оверлей не вычисляет формулы и не
содержит собственного таймера кадров.

## Быстрый старт

Для установленной версии откройте приложение **YappyTuberPlus.exe**. В исходной
папке проекта Windows запустите двойным щелчком `app-start.bat`, Linux/macOS —
`app-start.sh`: лаунчер сам поднимет редактор и мост, а при недостающих файлах
предложит запустить `app-update`.

1. Откройте Rig Studio → кнопка **Оверлей** на верхней панели (или «Оверлей» в
   строке состояния).
2. Скопируйте **Ссылку для OBS** и добавьте в OBS источник **Браузер** — это
   основной способ, в том числе для больших ассетов.
3. Включите **Служебную рамку**, если нужна диагностика статуса, FPS, холста и
   неполученных файлов. Переключатель добавляет `guide=1` к ссылке.
4. Кнопка **Открыть оверлей** нужна для предпросмотра или резервного захвата
   нативного окна; она не заменяет Browser Source.

Оверлей подключается к редактору автоматически: он присылает `hello`, получает сцену,
базовую позу и поток кадров. В диалоге видно число подключённых оверлеев и транспорт.

**Версия моста.** И редактор, и оверлей называют в `hello`/`announce` число
`protocol` (`OVERLAY_PROTOCOL` в `src/overlay/protocol.ts`) — это слот «мост» в
версии проекта (`docs/VERSIONS.md`). Сверять его обязательно: страница источника
в OBS кэшируется браузером, поэтому после обновления редактора там может
остаться оверлей прошлой сборки. При расхождении редактор подсказывает, что делать:
страницу источника нужно перезагрузить (или открыть оверлей заново). Без этой
сверки расхождение выглядело бы как «кадры перестали обновляться» через час
после обновления.

Файлы объектов (картинки, GIF, видео, звук) в сцене — ссылки `asset:<id>` на хранилище
webview. Нативное окно читает байты из IndexedDB/папки пресета. OBS Browser Source работает
на другом origin, поэтому запрашивает ассет у редактора: `asset-request` → `asset-start` →
`asset-chunk`. Файл передаётся фрагментами по 48 КиБ, не больше восьми одновременно; каждый
подтверждается `asset-ack`, а неподтверждённый повторяется. Размер файла сверяется перед
сборкой Blob. В служебной рамке видны количество недостающих файлов и причина ошибки.
Так передаются и большие картинки/видео: одно гигантское JSON/base64-сообщение не создаётся.

**Размер окна — из холста.** Окно оверлея и окно захвата по умолчанию равны `preset.canvas`,
поэтому риг виден 1:1, а правка размера холста (клик по подписи размера на сцене) сразу
меняет размер окон. Галочка **По размеру холста** в диалоге возвращает ручные поля «Ширина»
и «Высота»: тогда окно живёт своей жизнью, а картинка вписывается в него по режиму вписывания.

**Почему кнопка открывает окно на своей странице.** Нативное окно оверлея загружает страницу
приложения: только у своего origin есть доступ к IPC Tauri, то есть к кадрам и настройкам
окна. Ссылка вида `http://127.0.0.1:17800/overlay.html` нужна **только источнику браузера в
OBS** — в нативное окно её подставлять нельзя, оно осталось бы пустым.

## Способы захвата в OBS

### Источник браузера: основной рекомендуемый способ

Источник браузера в OBS работает в отдельном процессе и не видит `BroadcastChannel`
обычного браузера, поэтому нужен локальный релей. В приложении (Tauri) он встроен:
сервер поднимается вместе с окном редактора, отдельный процесс Node не нужен.

| Адрес | Что отдаёт |
|---|---|
| `http://127.0.0.1:17800/overlay.html` | страница оверлея из веб-сборки приложения |
| `ws://127.0.0.1:17800/overlay-ws` | релей сообщений (тот же протокол, что у моста) |
| `http://127.0.0.1:17800/health` | JSON: жив ли сервер, где веб-сборка, сколько клиентов |

В OBS: **Источник браузера** → ссылка из диалога оверлея (кнопка «Ссылка для OBS»).
Ширина и высота — как в настройках окна оверлея, галочка «Прозрачность» даёт альфа-канал
без хромакея.

Настройки сервера — переменные окружения приложения:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `YTP_OVERLAY_PORT` | `17800` | порт; занят — сервер не поднимется, остальные окна работают |
| `YTP_OVERLAY_HOST` | `127.0.0.1` | адрес; `0.0.0.0` нужен только для OBS на другой машине |
| `YTP_OVERLAY_WEB` | ресурсы приложения | папка с `overlay.html` и ассетами сборки |

Веб-сборка попадает в установщик как ресурс (`bundle.resources` в `tauri.conf.json`),
поэтому ссылка работает без Node и без папки проекта. Если сборки рядом не оказалось,
сервер отдаёт страницу-подсказку и продолжает работать как релей.


### Захват окна (резервный способ для Windows-сборки)

1. Откройте собранное приложение **YappyTuberPlus.exe**.
2. Откройте оверлей из диалога.
3. В OBS добавьте источник **Захват окна** → `YappyTuberPlus Overlay`.
4. Включите «Пропускать клики», если окно мешает работе.

Окно создаётся с `transparent: true`, без декораций, тени и значка на панели задач.
Прозрачность обеспечивает Windows/WebView2, поэтому фон в OBS остаётся прозрачным.

### Окно захвата (для Discord, Game Bar и записи экрана)

Если «Захват окна» с прозрачного оверлея не работает (окно скрыто с панели задач,
всегда сверху, без рамки) — используйте **окно захвата**: в диалоге оверлея кнопка
**Открыть окно захвата**.

| | Оверлей | Окно захвата |
|---|---|---|
| Фон | прозрачный / цвет / хромакей | те же настройки |
| Размер | из холста пресета (`preset.canvas`) | тот же размер |
| Рамка, тень | нет | нет, но окно есть в списке окон |
| Поверх всех окон | да (настройка) | нет |
| Пропуск кликов | да (настройка) | нет: окно можно тянуть и закрыть |
| Цель | источник браузера, игра поверх | «Захват окна» в OBS, Discord, Game Bar |

В нативном окне прозрачность сохраняется: при включённой опции «Прозрачность» (Allow
transparency) в источнике «Захват окна» риг записывается с альфа-каналом — так же, как
работают Spout2 в VTube Studio и PNGTuber. В браузере прозрачных окон не бывает, поэтому
в превью окна захвата подставляется тёмный фон `#0f1215`.

Отдельное окно можно перетаскивать за верхнюю полосу: она проявляется при наведении и не
мешает записи. Адрес страницы — `overlay.html?capture=1`; отдельной сборки нет, это та же
отрисовка оверлея.

### Мост для разработки в браузере

В браузерной разработке отдельного сервера приложения нет. Двойной щелчок по
`app-start.bat` (Windows) или `app-start.sh` (Linux/macOS) сам запускает Vite и
мост; отдельные окна терминала не нужны. Мост и встроенный сервер только
пересылают JSON между окнами и не считают риг — поэтому правило «один активный
драйвер» действует в обоих случаях.

### Кадры считает приложение, а не окно

Раньше поток кадров продвигало видимое окно редактора: `requestAnimationFrame`
останавливается в свёрнутом окне, и оверлей замирал вместе с ним. Теперь в приложении
кадры считает отдельный поток Rust (`src-tauri/src/schedule.rs`):

- окно присылает входы (`rig_schedule_inputs`) — микрофон, клавиатуру, мышь, события;
- поток тикает движок с частотой пресета и отдаёт кадр событием `rig://frame`;
- окно готовит кадр (`prepareFrame`) и раздаёт его оверлеям по обычному протоколу;
- пауза останавливает поток и сбрасывает время, чтобы `dt` не стал длиной паузы.

В браузере всё как раньше: кадры идут на `requestAnimationFrame`.

## Настройки

Хранятся в пресете (`overlay` в `RigPreset` версии 2), поэтому переезжают вместе с
экспортом JSON. Раскладка редактора, как и раньше, в пресет не попадает.

| Параметр | Значение |
|---|---|
| Ширина, высота | размер окна оверлея, 120–7680 × 120–4320 |
| Вписывание | `contain` (вписать), `cover` (заполнить), `stretch` (растянуть), `pixel` (1:1) |
| Фон | `transparent`, `color`, `chroma` (для хромакея) |
| Поверх всех окон | `alwaysOnTop` в Tauri |
| Пропускать клики | `setIgnoreCursorEvents` в Tauri |
| Служебная рамка | HUD, границы холста, статус, FPS и причины неполученных ассетов; для эфира выключается |
| Управление окном | Временные кнопки перемещения, изменения размера и закрытия; выключено по умолчанию |

Настройки окна захвата отдельные **не** хранятся: у него тот же размер, вписывание и фон,
что и у оверлея, поэтому в пресете остаётся одна секция `overlay`. При включённом управлении
ручное изменение размера нативного оверлея записывает ширину и высоту в эту секцию. Закрытие
основного окна редактора закрывает его окна оверлея и захвата.

## Транспорты и параметры URL

Оверлей выбирает транспорты автоматически:

- **BroadcastChannel** — редактор и оверлей в одном браузере (вкладка, второе окно,
  предпросмотр).
- **Tauri events** — разные webview-окна нативной сборки.
- **WebSocket** — релей `/overlay-ws` для OBS и других процессов.

**Откуда берётся адрес релея.** Он не угадывается из адреса страницы. У окна
приложения свой origin (`http://tauri.localhost` на Windows, `tauri://localhost`
на Linux/macOS), и релея там нет — редактор спрашивает адрес у встроенного сервера
(`overlay_server_url`) и подключается к `ws://127.0.0.1:17800/overlay-ws`.
Страница источника OBS живёт на адресе самого сервера, поэтому выводит релей из
своего `location`, а в браузерной разработке — из адреса Vite (его прокси ведёт на
`npm run overlay:bridge`).

Раньше адрес брался из `location` везде, и редактор в приложении стучался в
`ws://tauri.localhost/overlay-ws`: диалог показывал «Оверлей не подключён» и
«мост не отвечает», хотя встроенный сервер работал. Теперь в строке состояния
видно настоящий адрес релея и число подключений к нему: редактор всегда держит
одно, источник OBS добавляет второе.

Если встроенный сервер не поднялся (порт 17800 занят), диалог пишет об этом
прямо: окно оверлея продолжит работать через события Tauri, а источник браузера
кадров не получит. Порт и адрес меняются переменными `YTP_OVERLAY_PORT` и
`YTP_OVERLAY_HOST`.

Параметры страницы `overlay.html`:

| Параметр | Действие |
|---|---|
| `guide=1` | служебная рамка и HUD |
| `transport=broadcast` | только BroadcastChannel |
| `transport=tauri` | только события Tauri |
| `transport=ws` | только WebSocket-мост |
| `bridge=ws://host:port/overlay-ws` | явный адрес моста (важнее всех догадок) |

Кадры дедуплицируются по `seq`, поэтому одновременная работа нескольких транспортов
не приводит к повторной отрисовке или откату назад.

## Ограничения текущего этапа

- **В браузере вкладка редактора должна быть видимой.** `requestAnimationFrame`
  скрытой вкладки тормозится, а движок живёт в редакторе; для эфира в этом режиме
  годится окно-приложение (Chrome/Edge) и «Захват окна». В нативной сборке кадры
  считает планировщик в Rust, поэтому свёрнутое или скрытое окно редактора кадры
  не останавливает, а «Стоп» выключает отрисовку и микрофон.
- Мост нужен только браузерному режиму. В нативном приложении сервер оверлея
  (страница для источника браузера в OBS и релей `/overlay-ws` на
  `127.0.0.1:17800`) поднимается самим приложением, а лаунчер отдельно запускает
  `npm run overlay:bridge` для разработки в браузере.
- В браузерном окне прозрачности нет: фон окна рисует браузер. Альфа-канал есть
  только у окна Tauri и у источника браузера в OBS.
- `click-through` и `always-on-top` действуют только в Tauri; в браузере флаги
  сохраняются, но игнорируются.
- Размер и позиция окна применяются к открытому окну при изменении настроек; позиция
  окна ОС пока не запоминается.
- Формулы в оверлее не выполняются — только отрисовка подготовленных кадров.
