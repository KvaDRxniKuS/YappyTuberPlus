# OBS-оверлей

Прозрачное окно с ригом для OBS. Оверлей **только рисует готовые кадры**: движок,
глобальные переменные и stateful-функции считает редактор. Одна симуляция — один
источник продвижения кадров, поэтому `spring`, `smooth` и `autoblink` не шагают дважды,
а пауза в редакторе совпадает с картинкой в OBS.

Реализация соответствует §13 дизайн-документа: оверлей не вычисляет формулы и не
содержит собственного таймера кадров.

## Быстрый старт

```bash
npm install
npm run build:wasm   # только если есть Rust; иначе используется public/rig_core.wasm
npm run dev
```

1. Откройте Rig Studio → кнопка **Оверлей** на верхней панели (или «Оверлей» в
   строке состояния).
2. Включите **Служебную рамку**, если нужен статус, FPS и границы холста.
3. Нажмите **Открыть оверлей**. В браузере откроется отдельное окно, в Tauri —
   прозрачное окно без рамки поверх остальных.

Оверлей подключается к редактору автоматически: он присылает `hello`, получает сцену,
базовую позу и поток кадров. В диалоге видно число подключённых оверлеев и транспорт.

## Способы захвата в OBS

### Захват окна (основной для Windows-сборки)

1. `npm run tauri dev` (или собранное приложение).
2. Откройте оверлей из диалога.
3. В OBS добавьте источник **Захват окна** → `YappyTuberPlus Overlay`.
4. Включите «Пропускать клики», если окно мешает работе.

Окно создаётся с `transparent: true`, без декораций, тени и значка на панели задач.
Прозрачность обеспечивает Windows/WebView2, поэтому фон в OBS остаётся прозрачным.

### Окно захвата (для Discord, Game Bar и записи экрана)

Если «Захват окна» с прозрачного оверлея не работает (окно скрыто с панели задач,
всегда сверху, без рамки) — используйте **окно захвата**: в диалоге оверлея кнопка
**Открыть окно захвата**.

| | Оверлей | Окно захвата |
|---|---|---|
| Фон | прозрачный / цвет / хромакей | те же настройки |
| Размер | из полей диалога | те же поля |
| Рамка, тень | нет | нет, но окно есть в списке окон |
| Поверх всех окон | да (настройка) | нет |
| Пропуск кликов | да (настройка) | нет: окно можно тянуть и закрыть |
| Цель | источник браузера, игра поверх | «Захват окна» в OBS, Discord, Game Bar |

В нативном окне прозрачность сохраняется: при включённой опции «Прозрачность» (Allow
transparency) в источнике «Захват окна» риг записывается с альфа-каналом — так же, как
работают Spout2 в VTube Studio и PNGTuber. В браузере прозрачных окон не бывает, поэтому
в превью окна захвата подставляется тёмный фон `#0f1215`.

Перетаскивание и закрытие — верхняя полоса окна: она проявляется при наведении и не
мешает записи. Адрес страницы — `overlay.html?capture=1`; отдельной сборки нет, это та же
отрисовка оверлея.

### Источник браузера: встроенный сервер

Источник браузера в OBS работает в отдельном процессе и не видит `BroadcastChannel`
обычного браузера, поэтому нужен локальный релей. В приложении (Tauri) он встроен:
сервер поднимается вместе с окном редактора, отдельный процесс Node не нужен.

| Адрес | Что отдаёт |
|---|---|
| `http://127.0.0.1:17800/overlay.html` | страница оверлея из веб-сборки приложения |
| `ws://127.0.0.1:17800/overlay-ws` | релей сообщений (тот же протокол, что у моста) |
| `http://127.0.0.1:17800/health` | JSON: жив ли сервер, где веб-сборка, сколько клиентов |

В OBS: **Источник браузера** → ссылка из диалога оверлея (кнопка «Ссылка для OBS»).
Ширина и высота — как в настройках окна оверлея, галочка «Прозрачность» даёт альфа-канал
без хромакея.

Настройки сервера — переменные окружения приложения:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `YTP_OVERLAY_PORT` | `17800` | порт; занят — сервер не поднимется, остальные окна работают |
| `YTP_OVERLAY_HOST` | `127.0.0.1` | адрес; `0.0.0.0` нужен только для OBS на другой машине |
| `YTP_OVERLAY_WEB` | ресурсы приложения | папка с `overlay.html` и ассетами сборки |

Веб-сборка попадает в установщик как ресурс (`bundle.resources` в `tauri.conf.json`),
поэтому ссылка работает без Node и без папки проекта. Если сборки рядом не оказалось,
сервер отдаёт страницу-подсказку и продолжает работать как релей.

### Мост для разработки в браузере

В браузере сервера приложения нет, поэтому для проверки источника OBS остаётся мост:

```bash
npm run overlay:bridge   # ws://0.0.0.0:17800/overlay-ws
npm run dev              # Vite проксирует /overlay-ws на мост
```

Мост и встроенный сервер только пересылают JSON между окнами и не считают риг —
поэтому правило «один активный драйвер» действует в обоих случаях.

### Кадры считает приложение, а не окно

Раньше поток кадров продвигало видимое окно редактора: `requestAnimationFrame`
останавливается в свёрнутом окне, и оверлей замирал вместе с ним. Теперь в приложении
кадры считает отдельный поток Rust (`src-tauri/src/schedule.rs`):

- окно присылает входы (`rig_schedule_inputs`) — микрофон, клавиатуру, мышь, события;
- поток тикает движок с частотой пресета и отдаёт кадр событием `rig://frame`;
- окно готовит кадр (`prepareFrame`) и раздаёт его оверлеям по обычному протоколу;
- пауза останавливает поток и сбрасывает время, чтобы `dt` не стал длиной паузы.

В браузере всё как раньше: кадры идут на `requestAnimationFrame`.

## Настройки

Хранятся в пресете (`overlay` в `RigPreset` версии 2), поэтому переезжают вместе с
экспортом JSON. Раскладка редактора, как и раньше, в пресет не попадает.

| Параметр | Значение |
|---|---|
| Ширина, высота | размер окна оверлея, 120–7680 × 120–4320 |
| Вписывание | `contain` (вписать), `cover` (заполнить), `stretch` (растянуть), `pixel` (1:1) |
| Фон | `transparent`, `color`, `chroma` (для хромакея) |
| Поверх всех окон | `alwaysOnTop` в Tauri |
| Пропускать клики | `setIgnoreCursorEvents` в Tauri |
| Служебная рамка | HUD, границы холста, статус и FPS; для эфира выключается |

Настройки окна захвата отдельные **не** хранятся: у него тот же размер, вписывание и фон,
что и у оверлея, поэтому в пресете остаётся одна секция `overlay`.

## Транспорты и параметры URL

Оверлей выбирает транспорты автоматически:

- **BroadcastChannel** — редактор и оверлей в одном браузере (вкладка, второе окно,
  предпросмотр).
- **Tauri events** — разные webview-окна нативной сборки.
- **WebSocket** — мост `/overlay-ws` для OBS и других процессов.

Параметры страницы `overlay.html`:

| Параметр | Действие |
|---|---|
| `guide=1` | служебная рамка и HUD |
| `transport=broadcast` | только BroadcastChannel |
| `transport=tauri` | только события Tauri |
| `transport=ws` | только WebSocket-мост |
| `bridge=ws://host:port/overlay-ws` | явный адрес моста |

Кадры дедуплицируются по `seq`, поэтому одновременная работа нескольких транспортов
не приводит к повторной отрисовке или откату назад.

## Ограничения текущего этапа

- **Вкладка редактора должна быть видимой.** В браузере `requestAnimationFrame`
  скрытой вкладки тормозится, а движок живёт в редакторе. Нативная сборка с
  планировщиком в Rust (этап 6 дизайна) снимет это ограничение; до него для эфира
  используется окно Tauri и «Захват окна».
- Мост — отдельный процесс Node, его нужно запускать вручную; в продукте он станет
  частью Tauri-приложения.
- В браузерном окне прозрачности нет: фон окна рисует браузер. Альфа-канал есть
  только у окна Tauri и у источника браузера в OBS.
- `click-through` и `always-on-top` действуют только в Tauri; в браузере флаги
  сохраняются, но игнорируются.
- Размер и позиция окна применяются к открытому окну при изменении настроек; позиция
  окна ОС пока не запоминается.
- Формулы в оверлее не выполняются — только отрисовка подготовленных кадров.
