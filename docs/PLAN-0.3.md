## 1. Мультивыделение

### Что сейчас

Выделение — одна строка состояния: `selectedId: string | null` в `src/App.tsx`, оттуда же
уходит в `TreePanel`, `Scene` и `Inspector`. Клик всегда заменяет выбор; перетаскивание в сцене
двигает поддерево одного объекта; «удалить»/«дублировать» работают с одним объектом.
Модификаторы (`ctrlKey`, `shiftKey`) в дереве и сцене сейчас не читаются вообще.

### Предлагаемая модель

```ts
selection: string[]      // порядок = порядок добавления
primaryId: string | null // последний выбранный: инспектор, скрипт, пивот, F2
```

`primaryId` всегда входит в `selection`; при снятии выбора `primaryId` переезжает на последний
оставшийся элемент.

| Действие | Структура | Сцена |
|---|---|---|
| ЛКМ | только этот объект | только этот объект |
| Ctrl + ЛКМ | добавить/убрать из выборки | добавить/убрать из выборки |
| Shift + ЛКМ | диапазон по **видимым** строкам от `primaryId` до кликнутой | добавить к выборке (диапазона нет — в сцене нет строк) |
| ЛКМ по пустому месту | — | снять выборку |
| Delete | удалить все выбранные | то же |
| Ctrl + D / «Дублировать» | копии всех корней выборки, копии становятся выборкой | то же |
| Перетаскивание | — | двигаются все корни выборки; дочерние, попавшие в выборку, не двигаются дважды |
| Пивот (P) | — | только `primaryId` |

Подсветка: в дереве — все выбранные строки; в сцене — контур и маркеры у всех, у `primaryId`
дополнительно рамка трансформации (как сейчас) и пивот.

Крайние случаи, которые надо аккуратно закрыть:

- удаление нескольких объектов, один из которых родитель другого — сначала считаем «корни»
  выборки, детей перевешиваем на родителя корня, ссылки `parent` в скриптах переносим;
- дублирование — тоже по корням, иначе получим копии внутри копий;
- перетаскивание — дельта применяется к корням, дети едут через иерархию;
- `Shift` при перетаскивании по-прежнему ограничивает движение осью;
- «Скрыть/Показать» в дереве — по одному объекту, как сейчас (кнопка в строке).

### Инспектор при нескольких выбранных

Три варианта, нужно выбрать (вопрос 1 в конце):

- **A.** Инспектор показывает `primaryId`, сверху плашка «выделено N» — минимум работы;
- **B.** При N > 1 инспектор показывает только сводку: список имён, общие поля (слой,
  видимость), кнопки «удалить»/«дублировать»;
- **C.** Как B, но числовые поля (x, y, размер, прозрачность) редактируют всю выборку
  относительно текущих значений (абсолютная установка + «применить»).

### Файлы

`App.tsx` (состояние, `deleteSelected`, `duplicateSelected`, `onDragObjects`),
`TreePanel.tsx` (клики с модификаторами, подсветка, `aria-selected`),
`Scene.tsx` (`hitTest` + клики, отрисовка множественного выделения),
`Inspector.tsx` (режим «несколько»), `RightPanel.tsx` (заголовок скрипта — `primaryId` + «+N»).

## 2. Инструменты выделения в сцене: рамка и лассо

Сейчас в `SceneTool` три инструмента: `move`, `pivot`, `pan`. Добавляются два:
`marquee` (прямоугольник) и `lasso` (произвольный полигон).

- Тянуть ЛКМ от точки: рамка рисуется поверх сцены, лассо — ломаной по точкам (точка не чаще
  чем раз в 2–3 px, чтобы полигон не распухал).
- **Shift/Ctrl при отпускании** — добавить к текущей выборке вместо замены (Ctrl-клик без
  протяжки по объекту работает как в `move`).
- **Esc** во время протяжки — отмена, выборка не меняется.
- Попадание объекта: по его экранному bounding box (с учётом базовой позы, но без учёта
  анимационного кадра — иначе выделение «прыгает» в зависимости от кадра).
  - рамка: пересечение bbox с прямоугольником;
  - лассо: центр bbox внутри полигона **или** пересечение рёбер полигона с bbox.
  - Пиксельный тест по спрайту (прозрачные края) — дороже и капризнее; в MVP не берём.
- **«Вне зависимости от видимости»**: в выборку попадают объекты со скрытой базовой позой,
  скрытые скриптом/родителем, а также объекты, целиком лежащие за пределами канваса.
  Поэтому при активном инструменте предлагаю рисовать контур скрытых объектов тонким
  пунктиром (иначе непонятно, что попало в выборку) — вопрос 4 в конце.
- Инструменты переключаются горячими клавишами: `V` — выделение/перемещение, `M` — рамка,
  `L` — лассо, `P` — пивот. (Сейчас `V` и `P` уже есть.)

Вопрос 2 в конце: два отдельных инструмента на панели сцены или один «Выделение» с
переключателем рамка/лассо?

## 3. История: Ctrl+Z / Ctrl+Y

### Главная причина, почему сейчас не работает

Обработчик в `App.tsx` смотрит `event.key`:

```ts
else if ((event.ctrlKey || event.metaKey) && event.key.toLowerCase() === "z") { ... }
```

При русской раскладке `Ctrl+Z` приходит с `key === "я"` (а `Ctrl+Y` — `"н"`, `Ctrl+S` — `"ы"`),
поэтому сравнение не срабатывает: сочетание «молчит». На латинской раскладке работает, отсюда
и впечатление «то работает, то нет».

**Исправление:** сравнивать `event.code` — `KeyZ`, `KeyY`, `KeyS`, `KeyV`, `KeyP`, `KeyK`.
`event.code` — физическая клавиша, раскладка на него не влияет. `F2` и стрелки и так по `key`.

### Что ещё надо поправить рядом

- **Имя пресета** (`topbar`) и **лимитер FPS** меняют состояние напрямую через `setPreset`,
  мимо истории — Ctrl+Z их не отменит, а если начать печатать имя и нажать Ctrl+Z, отменится
  предыдущее действие с объектами. Надо либо тоже через `commit`, либо явно исключить.
- **Выделение не восстанавливается** при undo/redo: снимок должен хранить `{ preset, selection }`.
- **Кнопки Undo/Redo в топбаре** берут длину из `useRef` — React не перерисовывается, поэтому
  кнопки остаются неактивными до следующего изменения. Нужен счётчик состояния
  (`canUndo`/`canRedo` в `useState`) или отдельный хук.
- **Ввод в текстовых полях** сейчас пишет шаг на каждую букву — нужен дебаунс 400 мс
  (одно действие = одна пауза в наборе).
- Внутри редактора кода (`CodeMirror`) остаётся его собственная история: глобальный Ctrl+Z
  там не перехватываем (сейчас так и есть — проверка `editing`).

### Предложение

Вынести в `src/hooks/useHistory.ts`: снимки `{ preset, selection }`, метка действия для
будущего «что отменяем», лимит 100 шагов, `commit(next, { label, coalesceKey })`.
`coalesceKey` (например `"name"` или `"field:character.x"`) склеивает быстрые правки одного
поля в один шаг. Все изменения пресета идут только через `commit`.

## 5. Стрелка у «Сохранить»

Сейчас стрелка вызывает `savePresetAs()`: в приложении это нативный диалог, **в браузере —
мгновенное скачивание файла без единого вопроса** (скорее всего именно это вы и увидели в
превью; браузерная ветка — только для разработки, но поведение всё равно неприятное).

Предложение: стрелка открывает небольшое меню, и только потом диалог проводника.

| Пункт меню | Что делает |
|---|---|
| Сохранить как… | диалог «куда и под каким именем»; выбранный файл становится текущим |
| Сохранить копию… | диалог; текущий файл остаётся прежним (удобно сделать вариант рядом) |
| Показать в папке | открыть проводник на папке пресетов (только приложение) |

В браузере те же пункты ведут себя честно: «Сохранить как…» скачивает файл и пишет об этом в
тосте, «Показать в папке» скрыт.

Вопрос 3 в конце: меню из двух пунктов (как выше) или стрелка сразу открывает диалог без меню?

## 6. Сцена дёргается при скрытии/раскрытии панелей

### Причина

`<canvas>` растянут CSS-ом на 100 % контейнера, а его битмап пересоздаётся только внутри
`draw()` в rAF-цикле. Между изменением ширины контейнера (событие ResizeObserver ставит
`dirty = true`) и следующим кадром браузер успевает показать **старую картинку, растянутую под
новый размер** — это и есть «растягивается/сжимается на первых кадрах». Панель «Объекты»
скрывается корректно потому, что там нет канваса.

### Исправление

- ResizeObserver пересчитывает размер битмапа и **рисует синхронно** в своём колбэке, до paint,
  не дожидаясь rAF;
- то же самое — в layout-эффекте при смене флагов свёрнутости (страховка на случай, если RO
  сработает позже);
- `draw()` уже выставляет `canvas.width/height` и `setTransform` до отрисовки — расхождения
  размеров после синхронного ресайза не остаётся, значит и растяжения нет;
- проверить, что высота сцены не зависит от свёрнутости (`Math.min(layout.sceneHeight,
  window.innerHeight - 285)` от панелей не зависит) — если дёргается и по высоте, причина
  другая, посмотрю по вашей записи.

### Проверка

Playwright: после клика «свернуть структуру» **сразу** (без `waitForTimeout`)
`canvas.width === Math.round(clientWidth * dpr)`, и то же после разворачивания. Плюс визуальная
проверка у вас в превью.

Риски: мультивыделение задевает инспектор и панель скрипта (нужна внятная плашка «+N»);

последнее состояние, независимо от позиции в истории.

## Решения по открытым вопросам

1. **Инспектор при мультивыделении — вариант C.** Список выбранных (клик делает объект
   основным, Ctrl+клик убирает), относительный сдвиг X/Y, общие свойства: слой, масштаб,
   поворот, непрозрачность, «показать/скрыть все».
2. **Рамка и лассо — две отдельные кнопки** на панели сцены (`M` и `L`).
3. **Стрелка у «Сохранить» — сразу диалог выбора папки и имени**, без промежуточного меню.
   В браузере диалога нет: стрелка честно сообщает, что выбор папки доступен в приложении,
   и ничего не скачивает.
4. **Скрытые объекты под рамкой/лассо** — выделяются и подсвечиваются пунктирным контуром,
   пока активен инструмент.

### Ограничения, о которых стоит знать

- Рамка и лассо считают попадание по прямоугольнику спрайта, без учёта прозрачных пикселей;
  кадр анимации не учитывается — берётся базовая поза, чтобы выбор не «прыгал».

  друг в друга объекты обрабатываются один раз.
- Стрелки-нудж (сдвиг на 1 px) в этой итерации не добавлялись, хотя DESIGN их описывает.

## Дополнение после первой проверки

Правки по итогам просмотра (коллизия спрайта устраивала, её не трогали):

1. **Глаз больше не переписывает скрипт.** У объекта появился отдельный флаг
   `enabled: boolean` (не из DSL, из скрипта его изменить нельзя). Итоговая видимость =
   `visible × enabled`, выключенный родитель гасит всё поддерево. Глаз в структуре
   переключает только `enabled`, поэтому `visible = blink > 0 ? 1 : 0` и подобные формулы
   остаются как были. Движок про флаг не знает (Rust-ядро не пересобирается без cargo),
   поэтому кадр фильтруется в редакторе: `applyEnabled()` в `src/engine/frame.ts` вызывается
   на каждом кадре из `useRigEngine`, а `neutralFrame()` (режим «Стоп») учитывает флаг сразу.
   В дереве объект со скриптовым `visible = 0` помечается как «· скрипт», чтобы не путать с
   временно скрытым.
2. **Перетаскивание группы.** Клик по любой коллизии внутри выделенной группы больше не
   сбрасывает выборку на конкретный спрайт: проверяется `isSelectedTree`, и двигаются корни
   текущей выборки. Заодно это работает и для обычного мультивыделения.
3. **Свёрнутая группа.** Причина была в финальном проходе по «невизитнутым» объектам дерева:
   дети свёрнутой группы считались сиротами и добавлялись в конец плоским списком. Логика
   вынесена в чистую функцию `treeRows()` (`src/engine/selection.ts`) с пометкой всей ветви
   посещённой; поведение закрыто node-тестом.

Проверки после правок: `tsc` (приложение и тесты), тесты движка, 21 node-спека Playwright,
сборка. Сценарии для браузера дописаны (глаз без правки скрипта, перетаскивание группы).

## Дополнение 2: порядок отрисовки и перестановка строк

1. **Порядок отрисовки.** При одинаковом `layer` поверх теперь тот объект, который выше в
   структуре; потомок всегда поверх своего предка. Движок сортирует по `layer` и порядку
   массива, поэтому итоговый порядок пересобирает редактор (`applyTreeOrder` в
   `src/engine/frame.ts`) — сцена и оверлей получают уже готовый `frame.order`.
2. **Перестановка строк.** Drag за верхнюю или нижнюю четверть строки вставляет объект перед
   целью или после неё (с переносом к её родителю), drag в середину по-прежнему вкладывает
   внутрь группы. Дополнительно `Alt+↑` / `Alt+↓` двигают выделение на строку. Логика вынесена
   в `src/engine/structure.ts` (`structureOrder`, `structurePaths`, `frontness`,
   `reorderObjects`, `reorderNeighbor`) и покрыта node-тестами.
3. **Демо-риг.** Тело стоит в структуре выше головы, поэтому при новом правиле перекрывало бы
   подбородок. Группе головы добавлен слой `inherit + 0.5`; для ранее сохранённых пресетов это
   делает миграция `migrateDemoPreset()`.
4. **Глаз у объекта, скрытого формулой.** Подписи «· скрипт» больше нет: иконка видимости
   получает `{}` по бокам, глаз закрытый и не красный. Красный закрытый глаз остаётся только
   за временным скрытием (`enabled = false`).
