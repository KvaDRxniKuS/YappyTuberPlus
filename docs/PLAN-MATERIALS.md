# План: материал объекта — нормали, шероховатость, металл, окклюзия, свечение

Задача на ночь. Это план, а не код: сначала обсудили и выбрали, теперь по нему
делаем. Решения ниже зафиксированы, спорные места помечены «решить по ходу».

## 1. Что решили

| Вопрос | Решение |
|---|---|
| Модель блика | **GGX** (Cook-Torrance без геометрического члена) |
| Каналы | нормали, **шероховатость**, **металл**, **окклюзия**, **свечение** |
| Хранение карт | **оба**: отдельный файл на канал **или** упакованная карта с выбором канала (`R/G/B/A`) |
| Из скрипта | **да**, параметры в ядре → новое поколение **22** |

Почему GGX, а не Blinn-Phong: пользователь собирает «полноценные текстуры», а
значит карты делаются в 3D-редакторах, где шероховатость — это не степень
затухания, а ширина распределения нормалей. Blinn с картой шероховатости даёт
«мыло» на средних значениях и не даёт металла. GGX стоит на 8 светов дешевле,
чем один лишний проход: вся математика — в уже существующем цикле по светам.

## 2. Данные

### 2.1 Материал объекта

```ts
interface MaterialSpec {
  /** Каналы: константа, файл или «из упакованной карты по каналу». */
  roughness: ChannelSpec;   // 0…1, по умолчанию 0.6
  metallic: ChannelSpec;    // 0…1, по умолчанию 0
  ao: ChannelSpec;          // 0…1, по умолчанию 1
  emissive: EmissiveSpec;   // цвет, сила 0…200 %, карта или нет
  /** Упакованная карта: один файл, каналы выбираются буквами. */
  packed: PackedSpec | null;
  /** Сила блика 0…200 %: общий множитель спекуляра. */
  specular: number;
}

/** Значение канала: константа, файл или канал упакованной карты. */
interface ChannelSpec {
  value: number;                    // константа
  file: string | null;              // `asset:<id>` или путь
  from: "value" | "file" | "packed";
  packedChannel: "r" | "g" | "b" | "a" | null;
}
```

Упаковка по умолчанию — **ORM**: `R` шероховатость, `G` металл, `B` окклюзия
(так пишут glTF и Substance). Пресеты с `MRA`/`RMA` читаются выбором канала,
без нового кода.

`normal` остаётся как есть (`NormalMapSpec`): менять формат карты незачем, она
уже работает и лежит в пресетах.

### 2.2 Свет

```ts
interface LightSpec {
  ...
  /** Высота над холстом, px: без неё блик плоский. */
  height: number;       // по умолчанию 260
  /** Сила блика от этого света 0…200 %. */
  specular: number;     // по умолчанию 100
}
```

Высота влияет **только** на блики: пятно на холсте рисуется как сейчас, поэтому
старые пресеты не меняются.

### 2.3 Окружение сцены

```ts
interface RigPreset {
  environment?: { color: string; level: number };  // по умолчанию level 0
}
```

Металл без окружения чёрный — это не баг, а физика: у металла нет диффузной
части. Уровень 0 по умолчанию означает «вид как сейчас»; в инспекторе у
материала честная подсказка «металлу нужен свет или окружение».

### 2.4 Параметры ядра (поколение 22)

| Параметр | Смысл | Когда действует |
|---|---|---|
| `roughness` | 0…1, `-1` — «не задано» | заменяет константу инспектора |
| `metallic` | 0…1, `-1` — «не задано» | заменяет константу |
| `ao` | 0…1, `-1` — «не задано» | заменяет константу |
| `emissive` | 0…∞, 0 — «не задано» | **прибавляется** к силе свечения |

Асимметрия нарочная: шероховатость и металл — абсолютные свойства, «прибавить
0.2» читалось бы наоборот; свечение почти всегда пульсирует, и складывать его
естественно (`emissive = sin(time * 6) * 0.5 + 0.5`).

`-1` как «не задано» — единственный честный способ отличить «ядро не знает
параметра» от «пользователь поставил 0». В `NEUTRAL_PARAMS` все четыре получают
`-1`/`0`, чтобы старый кадр читался как «материал из инспектора».

## 3. Рендер

Объект **с** материалом считается по новой формуле, **без** материала — по
нынешней (объём от нормалей). Один шейдер, две ветки по `uniform int uMaterial`.
Существующие пресеты не меняются ни на пиксель.

```
L = normalize(lightXY − p, lightHeight)     V = (0, 0, 1)
H = normalize(L + V)
a = max(roughness², 0.002)
D = a² / (π · ((N·H)² · (a² − 1) + 1)²)
F0 = mix(0.04, albedo, metallic)
F = F0 + (1 − F0) · (1 − V·H)⁵
spec = D · F / (4 · max(N·L, 1e-4) · max(N·V, 1e-4)) · max(N·L, 0)
diffuse = albedo · (1 − metallic) · max(N·L, 0)
out = albedo · (ambient + Σ diffuse · mask) · mix(1, ao, 1) + Σ spec · mask · specular
out += emissiveColor · emissiveStrength
```

- `mask` — уже существующее покрытие пятна (форма, мягкость): блик **не вылезает
  за пятно** и не появляется на пустом месте. Это главное, что делает 2D-свет
  светом, а не ореолом.
- Тёмный свет (тень, `polarity −1`) блик не даёт.
- Окклюзия гасит только диффузную часть и окружение, блик не трогает.
- Свечение прибавляется в конце и не зависит от светов: «неон светится и в
  темноте».
- Энергия ограничена: `spec` клампится, чтобы 8 близких светов не выжигали
  объект; предел мягкий, как у нынешнего объёма.

Всё считается в том же слое объекта (`shadeLayer`), поэтому правило «объём не
просвечивает сквозь верхние слои» продолжает работать, а работа ограничена
рамкой объекта.

## 4. Интерфейс

Раздел **«Материал»** во вкладке «Параметры», сразу под «Картой нормалей».

```
Материал                                  [ ] включён
  Шероховатость   [_ползунок 0…1_]  [файл/канал]
  Металл          [_ползунок 0…1_]  [файл/канал]
  Окклюзия        [_ползунок 0…1_]  [файл/канал]
  Свечение        цвет [_] сила [_] [файл]
  Упакованная карта [файл]  R[шерох] G[металл] B[окклюзия] A[—]
  Сила блика      [_ползунок 0…200 %_]
  [Металл] [Пластик] [Кожа] [Матовый] [Неон]        ← готовые наборы
```

- Кнопка «Показать карту» у каждого слота — открыть сам файл (дебаг-режим,
  которым уже пользуются).
- Пропавший файл называется прямо: «Файл карты не найден», как у нормалей.
- Пресеты-наборы ставят только значения материала; окружение и свет они не
  трогают — иначе «нажал Пластик» незаметно менял бы сцену.

## 5. Файлы пресета — то, что мы уже один раз пропустили

Каждая карта материала обязана попасть в **все** места, иначе после переноса
материал молча погаснет:

1. `sourcesOf` в `engine/assets.ts` — иначе карта не грузится при открытии;
2. `inlineAssets` — иначе data URL не встраивается в сохраняемый файл;
3. `extractAssets` — иначе data URL из чужого пресета не становится файлом;
4. `writeSidecar` в `engine/presetFile.ts` — иначе папка `<имя>.assets` уезжает
   без карт.

Список файлов собирается одной функцией `sourcesOf(object)`, чтобы пятое место
не появилось само. На каждый пункт — тест в духе `object-files.spec.ts`.

## 6. Ядро (Rust)

- `Param` +4 варианта: `roughness`, `metallic`, `ao`, `emissive`; `as_str`,
  `parse` (без синонимов), `media_only` не трогаем;
- параметры отдаются **для всех** объектов, значения по умолчанию `-1`/`0`;
- `CORE_GENERATION = 22`;
- `coreFeatures`: новая запись `{ id: "material", label: "материал
  (`roughness`, `metallic`, `ao`, `emissive`)", since: 22, words: [...],
  fields: ["material"] }` — тогда «нужно 22» появляется только когда материал
  действительно используется в скрипте или включён у объекта;
- `ACCEPTS_FROM` не меняем: ядро 21 (и старше) просто не знает параметров, и материал
  работает из инспектора.

> **Ограничение среды.** В песочнице нет `cargo` и `wasm-pack`, поэтому
> `public/rig_core.wasm` здесь не пересобрать. Rust-часть пишется, тесты на неё
> пишутся, но рабочая сборка ядра — у вас (`npm run build:wasm` или
> `install-build-tools.bat`). До этого момента скриптовые параметры просто не
> появляются, и `needs` их не требует — редактор остаётся рабочим.

## 7. Версия и совместимость

- Новых полей в формате пресета нет лишних: `material`, `environment`, поля
  света — **необязательные**, старые файлы читаются как есть. Формат не растёт.
- Ядро: поколение 22, `needs` считается по содержимому (правило задачи 47).
- В `build.json`/`VERSIONS.md` — строка про 22 и про то, что материал работает
  и без него.

## 8. Дебаг и проверка

- Кубик расширяется до полного набора: `cube-albedo.png`, `cube-normal.png`,
  `cube-orm.png` (R шероховатость, G металл, B окклюзия), `cube-emissive.png`,
  и лист-дебаг: металл/пластик/матовое/шероховатое под одним светом.
- Математика шейдера дублируется в `src/render/material.ts` как чистая функция
  (`shadeMaterial`), и **лист-дебаг считается ею же** — тогда картинка в
  примере и кадр в редакторе не разъедутся.
- Тесты-числа: `F0 = 0.04` у диэлектрика; металл окрашивает блик в цвет
  альбедо; шероховатость расширяет блик (пик падает, площадь растёт); окклюзия
  гасит только диффузную часть; свечение не зависит от светов; тёмный свет блика
  не даёт; блик не выходит за пятно.
- Тесты-стыки (на этом мы дважды обожглись): канал из упакованной карты читается
  из нужной буквы; материал без карты работает по константам; старый пресет
  выглядит как раньше (ветка без материала).

## 9. Порядок работ

Каждый шаг заканчивается зелёными `tsc` + тестами и коммитом: если ночь
кончится, дерево остаётся рабочим.

| # | Шаг | Что готово после |
|---|---|---|
| 1 | `MaterialSpec`, `ChannelSpec`, поля света и окружения, нормализация | данные читаются и пишутся, старые файлы не ломаются |
| 2 | `src/render/material.ts`: чистая математика + тесты-числа | формулы проверены без WebGL |
| 3 | Шейдер: ветка материала, `uMaterial`, блики, окклюзия, свечение | объект с материалом выглядит как задумано |
| 4 | Инспектор: раздел «Материал», слоты, каналы, «Показать карту» | можно собрать материал руками |
| 5 | Файлы: `sourcesOf` и три места сохранения + тесты | карты не теряются при переносе |
| 6 | Пример-кубик: полный набор + лист материалов | есть чем проверять глазами |
| 7 | Docs: `DESIGN.md` §11.0/§12.4, `DATA.md`, `README.md`, `CHANGELOG.md` | правила записаны |
| 8 | Ядро: Rust + `coreFeatures` + `NEUTRAL_PARAMS` + тесты | скрипт может крутить материал (сборка wasm — у вас) |
| 9 | Сборка: `vite build`, паспорт, `build:check`, пуш | обновление доедет |

Остановка безопасна после любого шага, кроме 8: там половина работы — это
Rust без собранного wasm, и её нельзя оставлять недоделанной.

**Все девять шагов сделаны** (релиз `1.1.22.4.1.1.1`). Что вышло иначе, чем в
плане, — записано здесь, чтобы план не расходился с кодом:

- **Ядро стало 22, а не 21.** В плане стояло «поколение 21», но 21 уже занято
  видом объекта «свет» (коммит `544203d`), а материал — новое поколение
  контракта, значит 22.
- **Окружение — отражение, а не подсветка.** Сначала окружение умножало цвет
  альбедо, и металл (`albedo × (1 − metallic) = 0`) оставался чёрным при любом
  уровне. Теперь у металла окружение красится `F0`, у диэлектрика даёт 4 %:
  так металл видит «комнату», а физика не ломается.
- **Тёмный свет в материале ничего не добавляет.** Он не даёт ни диффузной
  части, ни блика: тень только гасит то, что даёт шейдер.
- **Значение из скрипта `-1` значит «не задано»** для `roughness`/`metallic`/`ao`
  и складывается для `emissive`: иначе первая же формула перебивала бы
  инспектор, а пульсация заменяла бы цвет свечения.
- **Появился `scripts/material-math.mjs`** — та же математика на node для
  генератора примера. Расхождение с `src/render/material.ts` ловит
  `tests/e2e/material.spec.ts` сеткой точек.

## 10. Чего в этой задаче не будет

- Атласов, мешей, карт смещения и параллакса: деформация и так без них.
- Bloom вокруг свечения: свечение — множитель на уже нарисованное, ореолы
  требуют отдельного прохода размытия. Если понадобится — отдельная задача.
- Управления материалом из «Поведения» ползунками: сначала формулы, потом UI.
- Тени от объектов друг на друга: 2D-сцена, света — пятна.
