# План: состояния, сетка и артмеш

Обсуждается. Это план, а не код. Решения из разговора зафиксированы, спорные
места помечены «решить по ходу».

Цель — приблизить риг к Live2D Cubism: у объекта есть **состояния**, привязанные к
значениям **параметров** (ползунки `manual`, входы трекеров, любые переменные —
вход, глобальная или локальная), а форма задаётся **сеткой**, которую двигают
ключи. Источник истины остаётся один: объект и его параметры; вкладка состояний
только прописывает значения — как это уже делает «Поведение».

## 1. Что решили

| Вопрос | Решение |
|---|---|
| Механизм состояний | **один**: позы с весами. «Сетка ключей» — редактор, который сам считает веса из 1–2 параметров (§3) |
| Значение ключа | **реальное значение параметра** (`−1`, `0`, `+1`, `30°`), а не нормировка 0…1 — нормировка только внутри счёта (§4.1) |
| Ключей на ось | **два** по умолчанию; больше — таймлайном, структура одна и та же (§4.4) |
| Осей на слой | 1–2 (сетка), больше — только списком поз |
| Слоёв на объект | **без предела** |
| Где хранится | блок в скрипте объекта (`# states {…}`): истина — скрипт, как у «Поведения» |
| Интерфейс | вкладка «Состояния»: таймлайн ключей + сетка; выбор ключа кликом |
| `mode: "replace"` | **не делаем**: абсолют выражается формулой автора, отдельный режим не нужен (§3.4) |
| Деформация | **сетка объекта заменяет `warp`**: `warp` — это сетка 2×2 |
| Сетка деформера | по умолчанию 2×2, максимум **32×32** |
| Артмеш | **произвольная триангуляция по трём точкам**, как в Cubism; отдельный редактор; полигон работает и как обрезка |
| Иерархия | деформер деформирует детей; вложенность **без предела** — деформеры накладываются по цепочке (§8) |
| Галка «деформируется родителем» | есть: выключена — по родителю едет только пивот ребёнка |
| Инструменты | кисть (радиус, жёсткость) и ручное перетаскивание; кисть двигает **свободно в плоскости** |
| Симметрия | пивот / центр сетки / центр сцены / вручную; ось хранится **в пресете** |
| Ключи двигают точки | **да**: поза и смещения точек деформера в одном ключе |
| Параметры | **любое имя**: вход, глобальная или локальная переменная объекта (§5) |
| Видимость | состояние может только **гасить** |
| Рендер | **WebGL2 для всей сцены**, текст — сразу |
| Совместимость | старые пресеты не поддерживаем, если это даёт лучший результат |

## 2. Словарь

- **Параметр** — имя, значение которого двигает состояние: `manual.value`,
  `tracker.head_rx`, `mic.speak`, глобальная `mood`, локальная `eye_target`.
- **Поза** — набор дельт полей объекта и, если нужно, смещений точек деформера.
- **Вес** — число 0…1, «насколько поза включена».
- **Ключ** — поза внутри слоя-сетки, привязанная к значению параметра.
- **Слой** — группа поз, которые смешиваются между собой по своим весам. Слои
  складываются, порядок не важен.
- **Деформер** — прямоугольная сетка, которая двигает точки артмеша.
- **Артмеш** — треугольники, которыми режется картинка.

## 3. Один механизм: позы с весами

### 3.1 Почему не два

При двух ключах на ось сетка **и есть** позы с весами:

- одна ось: веса `1 − t` и `t`, результат `(1 − t)·P₀ + t·P₁`;
- две оси: веса `(1 − t₁)(1 − t₂)`, `(1 − t₁)t₂`, `t₁(1 − t₂)`, `t₁t₂` — четыре
  позы, сумма весов всегда 1.

Сетка — частный случай списка поз: тот, где веса считаются из параметров
автоматически. Обратное неверно: пять эмоций с произвольными весами в сетку не
уложить. Поэтому механизм один, а «сетка» — режим редактора.

### 3.2 Что даёт каждый режим

| | Слой-сетка | Слой-позы |
|---|---|---|
| Веса | считаются из параметров | пишет автор выражением |
| Сколько поз | 2 × 2 по умолчанию, больше — таймлайном | сколько нужно |
| Для чего | непрерывные величины: угол головы, взгляд | эмоции, события, приоритеты, переходы |
| Как выглядит | таймлайн параметра + таблица | список «поза · вес · значения» |
| Переход во времени | `smoothstep` по параметру | `smooth(значение, мс)` в весе |

Слой-сетку можно развернуть в позы (веса станут выражениями); обратно — только
если веса совпадают с шаблоном. Данные при этом одни и те же.

### 3.3 Сумма или среднее

Настройка слоя:

| `normalize` | Формула | Когда |
|---|---|---|
| `sum` (по умолчанию) | `Σ wᵢ·Pᵢ` | как в Cubism: параметры складываются, слои не спорят |
| `average` | `Σ wᵢ·Pᵢ / Σ wᵢ` | кроссфейд эмоций: «грусть + злость» — смесь, а не двойной наклон |

У слоя-сетки сумма весов всегда 1, поэтому там оба режима дают одно и то же.
Вопрос «какой по умолчанию» пока отложен.

### 3.4 Чем это отличается от настоящего keyform

| | Keyform (Cubism) | Blendshape |
|---|---|---|
| Значения | **абсолютные**: где вершина и как стоит объект при этом значении | **дельты**: насколько сдвинуть от текущего |
| Несколько параметров | считаются последовательно, каждый следующий видит результат предыдущего | складываются |
| Что умеет | переписать форму целиком | добавить движение к авторскому |

Мы делаем **дельты**: иначе состояния начнут спорить с инспектором, «Поведением» и
авторскими формулами — а это против правила «истина — объект и его параметры».

`mode: "replace"` не вводим: если автору нужен абсолют, он пишет формулу сам —
состояние даёт значение, а формула распоряжается им как угодно (`limit`, `clamp`,
условие, что угодно). Отдельный режим дублировал бы язык.

### 3.5 Как складывается

```
поле = авторское + <поле>_behaviour + <поле>_states
```

Правила соединения — те же, что у каналов `<поле>_behaviour`:

| Поле | Как соединяется |
|---|---|
| `x`, `y`, `rotation`, `skewX`, `skewY` | **сложение** |
| `sizeX`, `sizeY`, `opacity` | `1 + Σ wᵢ·(значениеᵢ − 1)` |
| `visible` | **произведение** `Π (1 − wᵢ·(1 − vᵢ))`: только гасит |

### 3.6 Пример: глаза

Центр взгляда — это авторская поза, а ключи — положения зрачка при значениях
параметра. Параметр `manual.eye_x` живёт в −1…+1 (так удобнее человеку):

| Значение параметра | Ключ | Дельта |
|---|---|---|
| −1 | «влево» | `x = −20` |
| +1 | «вправо» | `x = +20` |

При `eye_x = 0` веса 0.5 / 0.5 дают дельту 0 — зрачок ровно в центре. Дельты не
считаются руками: подвинул зрачок в сцене, нажал «Записать позу» — редактор сам
вычел авторскую позу.

Следствия:

- **Асимметрия** (влево 20, вправо 12) требует ключа в центре со своей дельтой —
  это просто ещё одна точка на таймлайне (§4.4), структура не меняется.
- **Слои складываются**: «взгляд» + «прищурился» + «наклон головы» суммируют
  смещения, авторская формула `x = inherit + …` продолжает работать.
- **Правка авторской позы двигает все ключи** вместе с ней: риг остаётся связным.

Состояния — это **свойство объекта**: правка слоя у левого глаза не трогает
правый, и это правильно. Дублировать слой для второго глаза можно копированием,
но это удобство, а не требование модели.

## 4. Ключи и таймлайн

### 4.1 Значение ключа — это значение параметра

Никаких «0 и 1 вместо −1 и +1». Пользователь ставит ключи **в тех значениях,
которые видит в ползунке**: `−1`, `0`, `+1`, `30°`, `100`. Нормировка в 0…1 — это
внутренняя арифметика интерполяции, в интерфейсе её нет.

- В таблице ключей видно `manual.eye_x = −1` и `manual.eye_x = +1`, а не «0» и «1».
- Нейтральное значение параметра не обязано быть нулём: если персонаж стоит с
  головой −5°, ключ ставится на `−5`, и ничего пересчитывать не надо.
- Диапазон ключей задаёт сам пользователь: «от −1 до +1», «от 0 до 100» — это и
  есть «границы, выставляемые вручную» из обсуждения.

### 4.2 Данные

```json
{"kind":"grid",
 "axes":[{"param":"manual.eye_x","keys":[-1,1]},
         {"param":"head_rx","keys":[-30,30]}],
 "smooth":true,
 "poses":[{"at":[-1,-30],"pose":{"y":0}},
          {"at":[1,-30],"pose":{"y":-6}},
          {"at":[-1,30],"pose":{"rotation":4}},
          {"at":[1,30],"pose":{"y":-6,"rotation":-8}}]}
```

- `at` позы — **значения параметров** по каждой оси, а не индексы и не 0/1.
- Внутри ячейки сетки — билинейная интерполяция; `smooth` заменяет линейный ход
  на `smoothstep`, чтобы у ключа не было излома.
- `pose` — дельты к авторской позе. Точки деформера — в том же объекте (`points`).

### 4.3 Генерируемый код

```
# states {"format":1,"layers":[{"kind":"grid", …}]}
t = clamp((manual.eye_x + 1) / 2, 0, 1)
w_0 = 1 - t
w_1 = t
x = inherit + x_behaviour + x_states
```

`<поле>_states` собирается из весов и значений поз. Блок — источник истины;
генератор перезаписывает **только свои** строки (`t*`, `w_*`, `<поле>_states`),
авторские формулы не трогает. Ровно так уже работает «Поведение».

### 4.4 Больше двух ключей — это таймлайн

Ключи оси живут на **таймлайне параметра**, как в Cubism:

```
manual.eye_x   ──●────────────●────────────●──
                −1            0           +1
              [влево]       [центр]     [вправо]
```

- клик по пустому месту таймлайна — добавить ключ в это значение;
- перетаскивание маркера — сдвинуть значение ключа (соседние ключи сортируются);
- правый клик — удалить (удаление крайнего сужает диапазон);
- у ключа в сетке с двумя осями появляется ячейка: 2 ключа × 2 ключа = 4 позы,
  3 × 3 = 9 поз.

Число ключей не ограничено: «два» — только значение по умолчанию, чтобы новый
слой не пугал пустой таблицей.

**Где стоят ключи у нового слоя.** Не угадываем: у входа есть паспорт
(`InputValues.meta` — подпись, `min`, `max`, шаг), поэтому новый таймлайн сразу
получает ключи на границах входа: `manual.value` → 0 и 1, `eye_x` → −1 и +1,
`head_rx` → −30 и +30. Если у входа границ нет (счётчик, флаг), ключи ставятся в
0 и 1 — и их видно, можно перетащить.

### 4.5 Сетка из двух осей

Слой с двумя параметрами — это сетка «ключ × ключ». Ячейка — поза со своим `at`.
Билинейная интерполяция внутри ячейки, поэтому форма не «ломается» при переходе
через ключ.

## 5. Параметры — любые имена

Слой может ссылаться на любое имя скрипта: вход модуля, глобальная переменная,
**локальная переменная объекта**.

Позы считаются сгенерированным кодом — для них правки ядра не нужно, имена
резолвит сам скрипт.

Точки сетки считает рендерер, а он переменных скрипта не видит. Поэтому ядро
научится отдавать наружу значения нужных имён:

- в структуре объекта — список `watch` (какие имена нужны слоям);
- в кадре — `vars` у объекта: `{"eye_target": 3, "mood": 0.4}`.

Побочно это даёт **видимые локальные переменные объектов**: их можно показать в
панели «Входы» и в предупреждениях, не заходя в скрипт.

Пересборка ядра (`app-update`) — на вашей машине: в песочнице нет `cargo`, новый
WASM собрать не смогу.

## 6. Сетка и артмеш

### 6.1 Две разные вещи

| | Артмеш | Деформер |
|---|---|---|
| Что задаёт | **как** режется картинка: треугольники по точкам | **что стало** с этими треугольниками |
| Форма | произвольная триангуляция | прямоугольная сетка `cols × rows` |
| Редактор | свой: точки, треугольники, автосетка | свой: точки сетки, кисть |
| Ключи | не двигают | **двигают** (ключ хранит смещения точек) |

### 6.2 Данные

```ts
interface MeshSpec {
  art: ArtMesh;
  deform: GridSpec | null;
}

interface ArtMesh {
  points: Vec2[];        // в долях картинки
  triangles: number[];   // тройки индексов
  outline?: number[];    // контур для автотриангуляции и показа
  auto?: { cols: number; rows: number } | null; // сетка была сгенерирована
}

interface GridSpec {
  cols: number;          // 2…32
  rows: number;          // 2…32
  points: Vec2[];        // слева-вправо, сверху-вниз
}
```

UV отдельно не нужны: точки лежат на плоскости картинки, текстурная координата
совпадает с положением точки.

`art: 2×2` — сегодняшний `warp` с неподвижными углами. Поле `warp` больше не
пишется: при открытии старого пресета четыре угла переезжают в `art.points`.

### 6.3 Деформер двигает артмеш

Точка артмеша попадает в ячейку деформера и билинейно переносится вместе с её
углами; точки вне сетки прилипают к ближней ячейке. На регулярной сетке результат
совпадает с недеформированным объектом.

Ключи двигают точки **деформера**: артмеш — «как нарезано», деформер — «что с этим
стало». Ключ не зависит от плотности артмеша.

### 6.4 Ключ, двигающий точки

```json
{"at":[1,30],"pose":{"rotation":4},
 "points":{"3":[-0.02,0.01],"4":[0.03,0.0]}}
```

Смещения только тронутых точек; индекс — `j·(cols+1) + i` в сетке деформера.
Ключи живут в том же блоке `# states`; ядро блок не читает, точки считает
редактор и передаёт рендереру.

## 7. Инструменты

### 7.1 Общие для сетки и артмеша

| Инструмент | Что делает |
|---|---|
| Перетаскивание точки | тянет одну точку **свободно в плоскости** (как в Cubism); `Shift` — по осям |
| Кисть | двигает точки в радиусе; жёсткость — линейная, сглаженная (`smoothstep`) или постоянная; сила 0…100 % |
| Сглаживание | лапласиан по выделенным точкам |
| Симметрия | ось: **пивот**, **центр сетки**, **центр сцены**, **вручную**; зеркалит правку кисти и перетаскивания |
| Закрепить | точка не двигается кистью |
| Сброс | регулярная сетка / исходный меш |
| Показ | точки, рёбра, заливка жёсткости кисти |

Жест (протяжка) — **один шаг истории**.

Ось симметрии хранится **в пресете** (а не в профиле): переносится вместе с ригом.

### 7.2 Редактор артмеша

- **Автосетка** `cols × rows` по картинке.
- **Ручной меш**: точки по контуру, разрезать ребро, добавить/удалить точку,
  добавить треугольник, перевернуть диагональ у двух соседних.
- **Автотриангуляция контура** («отрезание уха») как отправная точка.
- Проверка: точки внутри картинки, треугольники не пересекаются, нет дыр.

## 8. Иерархия и вложенность

- Вложенность объектов — **без предела**: папка в папке в папке.
- Деформеры накладываются по цепочке: сначала собственный деформер объекта, потом
  деформер родителя, потом его родителя и так далее.
- Галка **«деформируется родителем»** (по умолчанию включена):

| Состояние | Что происходит |
|---|---|
| включена | точки объекта прогоняются через деформер родителя — форма гнётся |
| выключена | через деформер родителя проходит только **пивот**: объект едет и поворачивается жёстко |

Второй режим — «голова гнётся, а зрачок в глазу не растягивается».

## 9. Рендер и производительность

Canvas 2D на сетку не масштабируется: `warp` рисуется двумя треугольниками через
`clip` + `drawImage`, а 6×6 — это 72 клипа на объект на кадр.

Решение: **один WebGL2-рендер всей сцены**, сразу со всеми видами объектов.

| Что | Как в WebGL2 |
|---|---|
| Спрайт, медиа | текстура + индексный буфер треугольников артмеша |
| Фигура | триангуляция контура (`tracePath` уже даёт путь) |
| Текст | строчка рисуется в канву и уходит текстурой, кэш «строка + стиль» |
| Маска | трафарет (stencil) или `discard` по маске-текстуре |
| Свет, материал, нормали | шейдеры переезжают в тот же проход |

Служебные рамки редактора (сетка, ручки, подписи) остаются на Canvas 2D-канве
сверху — они не часть кадра и в оверлей не едут.

**Связь с бэклогом §4.** В OBS без аппаратного ускорения WebGL2 уходит в
программный растеризатор — новый рендер сделает «свет лагает» заметнее. Поэтому
передача готового кадра (`docs/BACKLOG.md` §4) идёт вместе с этой работой.

## 10. Вкладка «Состояния»

```
┌ Слои ───────────────────────────────────────────────┐
│ [сетка] manual.eye_x × head_rx               [+]    │
│ [позы]  sad, angry, cry                             │
├ Таймлайн ───────────────────────────────────────────┤
│ eye_x  ──●────────────●────────────●──              │
│          −1           0           +1                │
│ head_rx ──●────────────────────────●──              │
│          −30                     +30                │
├ Ключ ───────────────────────────────────────────────┤
│ at eye_x −1, head_rx −30                            │
│ y 0   rotation 0   size 1.00 …       [Записать позу]│
└─────────────────────────────────────────────────────┘
```

- **Таймлайн** — ключи на оси параметра: добавить кликом, подвинуть
  перетаскиванием, удалить правым кликом.
- **Выбор ключа** — клик по маркеру или по ячейке сетки.
- **«Записать позу»** — берёт текущее состояние объекта (положение в сцене и
  подвинутые точки) и пишет **дельты** от авторской позы в выбранный ключ.
- **Проверочный ползунок** на каждой оси двигает ключи в редакторе, не трогая
  настоящий вход.
- Пустой ключ — нулевые дельты: нормальное состояние, а не ошибка.

## 11. Версия и совместимость

| Слот | Что меняется |
|---|---|
| ядро | **+1**: `watch` в структуре, `vars` в кадре — состояния берут локальные переменные, и их видно в панели |
| файл | **8**: `mesh` вместо `warp`; старые пресеты мигрируют при открытии |
| мост | **+1**: `vars` и сетка в кадре — старая страница в OBS нарисовала бы объект недеформированным молча |
| оболочка | **+1**: новый рендер, вкладка «Состояния», редакторы сетки и артмеша |

## 12. Этапы

1. **Ядро и данные.** `watch`/`vars` в ядре (сборка WASM на вашей машине),
   `MeshSpec`, миграция `warp` → 2×2, блок `# states` (разбор и запись).
2. **Рендер WebGL2.** Спрайты, медиа, фигуры, текст, маски, материал и свет в
   одном проходе; проверка по скриншотам.
3. **Редактор сетки и артмеша.** Точки, треугольники, кисть, сглаживание,
   симметрия, сброс, автосетка и ручной меш, галка «деформируется родителем».
4. **Ключи.** Таймлайн, сетка 1–2 осей, «записать позу», генератор кода.
5. **Ключи точек.** Смещения деформера в ключах, `vars` в мосте.
6. **Позы и приоритеты.** Режим «позы», веса выражениями, `sum`/`average`.

## 13. Что осталось решить

1. **`sum` или `average` по умолчанию** — отложено; в плане `sum`.
2. **Копирование слоя на второй глаз** с зеркалированием по X — нужно ли, если
   слои всё равно независимы.
3. **Сколько ключей** показывать на новом таймлайне: два (по краям диапазона
   входа) или три (−1, 0, +1 для параметров, живущих в минусе).
