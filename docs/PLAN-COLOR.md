# План: модуль «Цвет» и «Свет из экрана» (ambient)

Это план, а не код: сначала договариваемся, потом делаем. Ниже — как это ляжет в
то, что уже есть, что придётся добавить и чего в первой версии **не будет**.
Спорные места помечены «решить по ходу» и вынесены в §10.

## 1. Что просили

1. **Модуль «Цвет».** У него есть входы-цвета (RGBA), настройки как у
   RGB-устройств: список цветов, режим, последовательность и прочее. Входов на
   один модуль можно добавить сколько угодно.
2. **Привязка в объектах.** У объектов, у которых есть задаваемые цвета (свет,
   фигуры и прочие), в «Поведении» появляется возможность взять каждый цвет не
   руками, а из входа такого модуля.
3. **Модуль «Освещение сцены» (ambient).** Берёт средний цвет заданных участков
   экрана/окна и отдаёт их как входы: у каждого — своя точка и сила размытия.
   Плюс подключение к OBS, чтобы точки захвата сами двигались вместе с
   источником на сцене OBS.
4. Ambient задуман **через уже существующий источник света**: модуль даёт цвета,
   свет их берёт. Новый вид света не нужен.

## 2. Главное ограничение, из которого растёт вся конструкция

Сейчас в ядро уходят **только числа**:

```text
источник (микрофон / мышь / таймер / сеть)
   → useModuleInputs (AudioFrame, PointerFrame, manual, auto, externalTexts…)
   → composeValues → { "mic.talking": 1, "manual.value": 2, … }
   → ядро (WASM): Param — f32, цвета в ядре нет и не планируется
   → RigFrame (числа) → отрисовка
```

Цвет в этой схеме не помещается: `Param` — это `f32`, а цвета объекта живут не в
ядре, а в пресете строками (`light.colorStart` — `"rgba(255,226,170,0.55)"`,
`shape.fill` — `"rgba(...)"`, `material.emissive.color` — `"#66e0ff"`,
`text.color` — `"#ffffff"`).

**Вывод: цвет не идёт через ядро.** Он идёт рядом: модуль отдаёт числа (RGBA как
четыре числа 0…1), а сборка готового цвета для отрисовки делается в TypeScript на
кадре. Поколение ядра **не меняется** (остаётся 23), WASM пересобирать не нужно.

Это не обходной путь, а то же решение, что уже принято для текста: `TextChannel`
собирается в редакторе из модулей и передаётся в отрисовку отдельным каналом, а
ядро про текст ничего не знает.

## 3. Модуль «Цвет»

### 3.1 Шаблон

`public/modules/color.json`, `kind: "color"`. Входы — **каналы цвета**, их список
живёт в настройках экземпляра (как клавиши у «Keyboard» и состояния у «Manual»),
потому что «сколько угодно входов» шаблоном не описать.

```jsonc
{
  "id": "color",
  "title": "Цвет",
  "kind": "color",
  "format": 1,
  "inputs": [],
  "fields": [],
  "defaults": {
    "channels": [
      {
        "name": "c1", "label": "Основной",
        "mode": "cycle",
        "colors": [
          { "color": "#ff4d6d", "hold": 1 },
          { "color": "#8b5cf6", "hold": 1 },
          { "color": "#22d3ee", "hold": 1 }
        ],
        "speed": 100,      // 0…200 %: секунд на круг
        "phase": 0,        // 0…100 %: сдвиг по времени
        "brightness": 100, // 0…200 %: общий уровень
        "smooth": 40,      // 0…100 %: сглаживание перехода
        "react": null      // { "module": "mic", "input": "speak" } — яркость от входа
      }
    ]
  }
}
```

### 3.2 Входы канала

Один канал — это **пять** числовых входов:

| Вход | Значение |
|---|---|
| `<канал>_r`, `_g`, `_b` | 0…1, готовый цвет в sRGB (как hex в пресете) |
| `<канал>_a` | 0…1, прозрачность (у «статичного» — из цвета палитры) |
| `<канал>_level` | 0…1, яркость канала с учётом `react` |

Почему четыре числа, а не одно: в ядро и модули проходят только числа, и в
скрипте `color_1.c1_r` — законная переменная, а `color_1.c1` — нет. Зато
привязка выбирает **канал целиком**, и человек про `_r/_g/_b` не думает.

### 3.3 Режимы

Как у RGB-устройств, но с честной математикой (все формулы — чистые функции в
`src/modules/color.ts`, чтобы их проверяли тесты, а не глаз):

| Режим | Что делает |
|---|---|
| `static` | один цвет из палитры (первый), без изменений |
| `breathe` | плавно к следующему цвету и обратно, скорость — `speed` |
| `cycle` | круг по палитре, переходы линейные |
| `sequence` | строго по очереди, с `hold` (секунды) на каждый цвет, без смешивания |
| `wave` | радуга по HSV: оттенок идёт по кругу, насыщенность и яркость — из палитры |
| `random` | новый цвет из палитры каждые `hold` секунд, переход сглажен |
| `react` | цвет стоит, яркость (`_level`) ведёт вход `react` (громкость, пульс) |

`hold` и `speed` — разные вещи и не дублируют друг друга: `hold` — сколько стоит
один цвет в `sequence`/`random`, `speed` — как быстро идёт круг в `cycle`/
`breathe`/`wave`.

### 3.4 Панель модуля

- Список каналов: имя для скрипта, подпись, удаление, «Добавить канал».
- В канале: режим, палитра (строки «цвет + `hold`»), ползунки `speed`, `phase`,
  `brightness`, `smooth`, выбор входа для `react`.
- **Живой образец**: прямоугольник текущего цвета рядом с названием канала —
  иначе настраивать палитру вслепую.
- Значения каналов видны во вкладке «Входы» как обычные ползунки (только чтение).

## 4. Привязка цвета в объектах

### 4.1 Данные

Новое необязательное поле объекта:

```ts
/** Откуда брать цвет: `null` — свой цвет из настроек. */
interface ColorLink {
  module: string;   // имя модуля в пресете: color_1, ambient_1
  channel: string;  // имя канала/точки: c1, spot_1
}

interface RigObject {
  colors?: {
    fill?: ColorLink;        // фигура: заливка
    stroke?: ColorLink;      // фигура: обводка
    lightStart?: ColorLink;  // свет: цвет у центра
    lightEnd?: ColorLink;    // свет: цвет у края
    emissive?: ColorLink;    // материал: цвет свечения
    text?: ColorLink;        // текст: цвет
    textStroke?: ColorLink;  // текст: обводка
  };
}
```

Свои цвета (`light.colorStart`, `shape.fill` …) **остаются на месте** и работают
как запасной вариант: нет модуля, нет входа, модуль выключен — рисуется своё.

### 4.2 Что именно подменяется

- **RGB** всегда берётся из канала.
- **Альфа по умолчанию остаётся своя.** У света это принципиально: край пятна
  (`colorEnd`) прозрачный, на нём держится мягкая граница. Если подменить альфу
  целиком, свет превратится в жёсткий круг. Поэтому у привязки есть галка
  «взять и прозрачность» — по умолчанию выключена.
- Цвет из канала — в sRGB 0…1, ровно как hex в пресете; материал сам переводит
  его в линейные числа, как делает сейчас с `#rrggbb`.

### 4.3 Интерфейс

Вкладка **«Поведение»**, новая секция **«Цвет»** — она показывается только у
объектов, у которых есть задаваемые цвета:

| Строка | Слева | Справа |
|---|---|---|
| Заливка | цвет-кружок + «свой цвет» | список: `Color 1 → Основной`, `Ambient 1 → Точка 1`, «свой цвет» |
| Обводка | … | … |
| Свет: центр / край | … | … |
| Свечение | … | … |

- В списке только модули с цветовыми каналами и только их каналы — руками имя
  входа не вводится.
- Нет ни одного такого модуля → строка есть, а справа подсказка «добавьте модуль
  «Цвет» во вкладке «Модули»» (как сейчас с мышью и микрофоном).
- Модуль пропал из пресета → предупреждение вверху секции и работа своим цветом,
  без тишины.

### 4.4 Как цвет попадает в кадр

```text
moduleInputs.inputs  { "color_1.c1_r": 0.31, … }
   ▼  colorChannel(preset, inputs)        src/render/color.ts
{ [objectId]: { fill: {r,g,b}, lightStart: {r,g,b}, … } }
   ▼  DrawRigOptions.colors               src/render/rigCanvas.ts
свет / фигура / текст / материал рисуются с подменённым цветом
```

- Пересчёт — мемоизированный: пока входы и привязки не менялись, объект получает
  тот же объект цвета (без новых строк на каждый кадр).
- **Оверлей**: страница в OBS живёт отдельно и получает только пресет и числа.
  Значит, готовые цвета едут в сообщении кадра (`colors` — необязательное поле,
  протокол остаётся 1: старый оверлей поле просто не читает). Без этого в OBS
  цвет застынет, а в редакторе будет живой — худший из возможных вариантов.
- Пропавший модуль **на стороне оверлея** тоже даёт свой цвет, а не чёрный.

### 4.5 Совместимость

- Появились новые поля в пресете (`object.colors`, настройки модулей) → **формат
  файла 6**. Старые файлы читаются: цветов нет — всё как раньше.
- Ядро — **23 без изменений**, `ACCEPTS_FROM` не трогаем, WASM пересобирать не
  нужно: цвета не в ядре.
- Мост оверлея — **1**: поле в сообщении необязательное.
- Модули — **1**: новый `kind` — это новый вид модуля, но старый редактор
  покажет его как «Manual» (без потери данных), поэтому номер не поднимаем,
  а в `docs/VERSIONS.md` пишем честно: «неизвестный kind → Manual».

## 5. Модуль «Освещение сцены» (ambient)

### 5.1 Откуда берутся пиксели

Три источника, разные по цене и доступности:

| Источник | Где работает | Стоимость | Роль |
|---|---|---|---|
| **Своя сцена** | редактор, оверлей, браузер | почти ноль: у нас уже есть холст | база: «свет подстраивается под сцену» |
| **Источник OBS** (`GetSourceScreenshot`) | где угодно, где доступен obs-websocket (127.0.0.1:4455) | OBS перерисовывает источник на каждый замер | главный вариант для «свет из игры/окна» |
| Системный захват окна | только приложение (Tauri, Windows API) | высокая, нужны права | не в этой задаче (§7) |

Браузер **не может** читать чужие окна: `getDisplayMedia` требует выбора окна
руками и на каждый запуск, а рисование чужого окна в свой холст запрещено.
Поэтому «экран» в вебе — это либо своя сцена, либо картинка от OBS.

### 5.2 Точки выборки

```jsonc
"defaults": {
  "connection": { "host": "127.0.0.1", "port": 4455, "password": "" },
  "rate": 10,                     // замеров в секунду, 1…30
  "points": [
    {
      "name": "spot_1", "label": "Слева",
      "source": { "kind": "obs", "scene": "Игра", "item": "Захват игры" },
      "area": { "x": 0.1, "y": 0.1, "size": 0.05 },   // доли источника
      "blur": 8,                                      // радиус усреднения, px источника
      "follow": true,                                 // точка едет за источником
      "smooth": 30                                    // 0…100 %: сглаживание во времени
    }
  ]
}
```

- `source.kind`: `scene` (своя сцена — координаты в долях холста) или `obs`.
- **`follow`** и есть та автоматика, о которой речь: у OBS-источника берётся
  трансформация (`GetSceneItemTransform`: `positionX/Y`, `width/height`,
  `cropLeft/Top`), переводится в координаты кадра OBS (`GetVideoSettings`:
  `baseWidth/Height`), и точка выборки на скриншоте считается от неё. Двинули
  источник в OBS — точка поехала вместе с ним, ничего в редакторе не правим.
  Событие `SceneItemTransformChanged` снимает ожидание следующего опроса.
- `area` — прямоугольник, из которого берётся среднее; `blur` — дополнительное
  усреднение по краям (по сути радиус того же ящика), чтобы цвет не мигал на
  резких границах.
- `smooth` — сглаживание между замерами (атака/спад, как у громкости): без него
  цвет дёргается на каждом движении.

### 5.3 Входы

С точки — то же самое, что у канала цвета: `<точка>_r/_g/_b/_a` и `<точка>_level`
(яркость как `max(r,g,b)`), плюс ничего больше. Дальше — та же привязка, что в §4:
свет берёт цвет из `ambient_1.spot_1`, и это ровно то, чего просили: «через
источник света, который у нас уже есть».

### 5.4 Стоимость и такт

- Один замер на источник на такт, а не на точку: из одного скриншота берутся все
  точки, которые смотрят на этот источник.
- Размер скриншота просим маленьким (например 128 px по длинной стороне) — для
  среднего цвета больше не нужно.
- Такт по умолчанию **10 Гц**, настройка 1…30; при `rate` ниже 10 цвет между
  замерами интерполируется, поэтому картинка не «шагает».
- Нет соединения, OBS закрыт, источник переименован → в карточке честная строка
  ошибки, значения замирают на последнем цвете (не чёрный экран).

### 5.5 Подключение к OBS

- obs-websocket **v5** (OBS 28+), по умолчанию `ws://127.0.0.1:4455`.
- Рукопожатие: `Hello` (версия, `rpcVersion`, `challenge`/`salt`) → `Identify` с
  `authentication = base64(sha256(base64(sha256(пароль + salt)) + challenge))`.
- Что читаем: `GetVersion`, `GetVideoSettings`, `GetSceneItemList`,
  `GetSceneItemId`, `GetSceneItemTransform`, `GetSourceScreenshot`.
- События: `SceneItemTransformChanged`, `CurrentProgramSceneChanged`,
  `SceneItemListReindexed` (переименовали/добавили — список в панели обновляется).
- Пароль хранится в настройках модуля (как Client ID у Twitch) и **не** попадает
  в лог. Кнопка «Проверить» показывает версию OBS и найденные сцены.
- Список сцен и источников для выпадающих списков берётся из OBS, а не пишется
  руками: имя с пробелами и кириллицей — норма.

## 6. Данные и файлы

- Настройки модулей — в пресете (как у всех): `channels`, `points`,
  `connection`, `rate`.
- Привязки цветов — в объекте: `object.colors`.
- Скриншоты **не хранятся**: они нужны на один замер и сразу забываются.
- Пароль OBS пишется в пресет — это надо сказать в документации прямо: пресет
  с паролем нельзя выкладывать. (Альтернатива — хранить его в localStorage
  приложения, а в пресете только имя соединения; решить по ходу, §10.)

## 7. Чего в этой задаче не будет

- **Чтения чужих окон из браузера** — невозможно, и притворяться не будем.
- **Системного захвата экрана в Tauri** — отдельная задача (Windows API,
  права, производительность).
- **Цвета как значения в скрипте** (`fill.color = red`): DSL числовой, цвет в нём
  не появится. В скрипт доступны `_r/_g/_b/_a/_level` — этого хватает, чтобы
  гнать яркость от звука, но не «присвоить цвет».
- **HSL/HSV в интерфейсе** — работаем в sRGB-палитре; `wave` крутит оттенок сам.
- **HDR и цветовой профиль**: скриншот OBS приходит в sRGB, HDR-источники дают
  блёклый цвет. Пишем в «Частые ошибки», не лечим.

## 8. Порядок работ

| Этап | Что | Проверка |
|---|---|---|
| **1** | Данные и разрешение цвета: `ColorLink`, `colorChannel()`, подмена в свете/фигуре/тексте/материале, поле `colors` в сообщении оверлея | тесты: подмена RGB, своя альфа по умолчанию, пропавший модуль → свой цвет, оверлей получает цвета |
| **2** | Модуль «Цвет»: `kind: "color"`, шаблон, панель с каналами и палитрой, режимы (§3.3) | тесты формул режимов; тест «входы канала = 5 чисел»; тест панели по разметке |
| **3** | Секция «Цвет» в «Поведении» + списки модулей/каналов | тест: список содержит только цветовые каналы; нет модуля → подсказка |
| **4** | Ambient от **своей сцены**: сэмплер холста, точки, размытие, сглаживание | тест: средний цвет области на нарисованном прямоугольнике; такт |
| **5** | OBS: подключение, список сцен/источников, скриншот источника, точки | тест рукопожатия (считаем хеш по эталону), тест «нет OBS → понятная ошибка» |
| **6** | `follow`: точки следуют за трансформацией источника + события | тест арифметики «трансформация → область на скриншоте» |

Этапы 1–3 дают то, что просили про цвета, 4–6 — про ambient. Версию поднимаем
один раз в конце этапа 1 (формат 6) и один раз в конце этапа 2 (документация
модуля).

## 10. Решено (ответы на вопросы)

| Вопрос | Решение |
|---|---|
| Режимы | **все семь**, включая `react` (яркость от входа другого модуля) |
| Ambient | **оба источника сразу**: своя сцена и источники OBS |
| Где привязка | **только вкладка «Поведение»**, секция «Цвет» |
| Пароль OBS | **в настройках приложения**, в пресете — только имя соединения |
| Свой `kind` в шаблоне | оставляем `kind`: `type` уже занят ссылкой на шаблон (`module.type`) |
| Системный захват окна | **не нужен**: хватает своей сцены и источников OBS |

## 11. Ещё не решено

- Нужно ли привязывать цвет к **времени года/пресетам** (смена палитры наградой
  Twitch) — можно потом, через модуль «Пресеты», отдельной задачей.
- Нужен ли `wave` не по HSV, а «волна по палитре» (разные цвета в разных точках
  объекта) — в первой версии `wave` крутит оттенок целиком.
