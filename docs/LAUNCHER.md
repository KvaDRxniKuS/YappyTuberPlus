# Быстрый запуск

Один файл, который сам скачивает крайние обновления, ставит зависимости и открывает
редактор. Ничего вводить в консоль не нужно.

## Пульсометр: отдельный ярлык

Внешние источники (пульс, игра, бот) живут отдельно от редактора: их поднимают
двойным кликом, когда нужен именно этот источник.

| Файл | Что делает |
|---|---|
| **`pulse-bridge.bat`** (Windows) / `pulse-bridge.sh` | мост пульсометра: отдаёт `ws://127.0.0.1:17801/inputs` и `http://127.0.0.1:17801/state` |
| `pulse-bridge.bat --hr 90` | ровный пульс вместо тренажёра |
| `pulse-bridge.bat --port 18000` | другой порт (не забудьте поменять адрес в модуле) |

Зависимостей у моста нет — только Node.js: сервер WebSocket собран на голом
`node:http`, поэтому `npm install` для него не нужен. Без железа он работает
тренажёром, так что интеграцию видно сразу: модуль «Пульсометр» из палитры уже
смотрит на этот адрес.

## Windows

1. Скачайте папку проекта (или только `start-yappytuber.bat`) — например, кнопкой
   **Code → Download ZIP** на GitHub, затем распакуйте.
2. Двойной клик по **`start-yappytuber.bat`**.

Что произойдёт при первом запуске:

1. Проверка Git и Node.js 20+. Если их нет — предложит установить через `winget`
   (Git и Node.js LTS), иначе покажет ссылки для ручной установки.
2. Клонирование ветки с последними изменениями в папку `YappyTuberPlus` рядом с файлом.
   Если папка уже существует и в ней лежит проект, скачанный ZIP-архивом (без `.git`),
   скрипт не отказывается от обновления, а **включает его на месте**: `git init`,
   `origin`, ветка и приведение отслеживаемых файлов к текущей версии.
3. `npm ci` — установка зависимостей.
4. Сборка WASM-ядра, если установлен Rust с target `wasm32-unknown-unknown`; иначе
   используется уже собранный `public/rig_core.wasm`, и об этом будет строка в окне.
5. Запуск Vite и открытие `http://localhost:5173/` в браузере.
6. Отдельное свёрнутое окно `YappyTuberPlus OBS bridge` — мост для источника браузера
   в OBS (можно отключить флагом `--no-bridge`).
7. Отдельное свёрнутое окно `YappyTuberPlus update agent` — агент, который заменяет
   файлы папки сборки, когда в репозитории появилась новая версия (флаг `--no-update`).

При следующих запусках шаг 1 и клонирование пропускаются: файл просто подтягивает
обновления, ставит новые зависимости при необходимости и запускает редактор.

Остановка — `Ctrl+C` в окне консоли или закрытие окна.

### Параметры

Параметры передаются в ярлыке или из командной строки:

```bat
start-yappytuber.bat --no-open      :: не открывать браузер
start-yappytuber.bat --no-bridge    :: без моста для OBS
start-yappytuber.bat --no-serve     :: только обновить и собрать
start-yappytuber.bat --no-update    :: без локального агента обновлений
start-yappytuber.bat --app          :: приложение: окно Tauri, без Rust — окно браузера
start-yappytuber.bat --tauri        :: нативное окно Tauri вместо браузера
start-yappytuber.bat --port 5199    :: другой порт
start-yappytuber.bat --dir D:\Rig   :: папка проекта
start-yappytuber.bat --branch main  :: другая ветка
```

При `--tauri` Vite поднимает сам Tauri, поэтому `--port` в этом режиме игнорируется.

`--app` — то же приложение, но с откатом: если Rust (`cargo`) установлен, запускается
нативное окно Tauri; если нет — редактор открывается окном-приложением Chrome/Edge
(`--app=...`, без вкладок, адресной строки и меню); если и их нет — в обычном браузере.
Окно-приложение удобно для «Захвата окна»: в кадр не попадает интерфейс браузера.

Если нужен запуск вообще без консоли и без Node.js — соберите приложение
(`npm run tauri build`) и ставьте установщик: см. [`BUILD.md`](BUILD.md).

Для сборки есть два отдельных файла:

- **`install-build-tools.bat`** — ставит Node.js, Rust, Visual Studio Build Tools (C++)
  и WebView2, если их нет (нужны права администратора и интернет);
- **`build-yappytuber.bat`** — собирает `.exe` и установщик. При успехе окно закрывается
  само и открывает папку с результатом; остаётся открытым только при ошибке.
  Флаги: `--no-bundle` (только `.exe`), `--fast` (без пересборки WASM), `--no-open`.

Проверить готовую папку сборки (`dist` или ту, что вы раздаёте) можно двойным
кликом по **`check-build.bat`** (Linux/macOS — `./check-build.sh`): он спросит
папку, сверит её паспорт `build.json` с репозиторием и скажет, какие слои
разошлись. Ничего вводить не обязательно — Enter проверяет `dist`. При успехе
окно закрывается само, при расхождении остаётся с объяснением.

Третий вариант — вообще ничего не ставить: один раз добавьте workflow из
[`BUILD.md`](BUILD.md), затем вкладка **Actions** → **Сборка Windows** →
**Run workflow** на GitHub, готовый установщик появится в артефактах.

## Linux / macOS

```bash
chmod +x start-yappytuber.sh
./start-yappytuber.sh
```

Параметры те же (`--no-open`, `--no-bridge`, `--no-serve`, `--no-update`, `--app`,
`--tauri`, `--port`, `--branch`, `--dir`). Для `--app` ищутся `google-chrome`, `chromium`, `microsoft-edge`,
`brave-browser` и Chrome в `/Applications`; иначе открывается обычный браузер через
`xdg-open`, `open` или `cmd.exe`.

## Что делает автообновление

Работа с git собрана в одном месте — `scripts/sync-repo.mjs`. Лаунчеры его
вызывают, поэтому Windows и Linux ведут себя одинаково, а логику можно проверить
тестом:

```bash
node scripts/sync-repo.mjs --branch arena/… --fallback main
node scripts/sync-repo.mjs --dry-run     # показать план, ничего не меняя
```

- `git fetch` и выбор ветки: берётся та, где последний коммит новее — сессионная
  ветка разработки или `main`. Поэтому файл продолжит работать и после слияния
  ветки в `main`.
- Папка без `.git` (распакованный ZIP) автоматически превращается в git-копию:
  `git init` → `origin` → нужная ветка → `reset --hard` на её текущее состояние.
- **Папка сборки — не правка кода.** `dist` лежит в репозитории как источник
  обновлений, поэтому своя собранная папка выглядит для git как изменённые файлы.
  Лаунчер её не прячет и не выбрасывает: копирует во временную папку, обновляет
  ветку и возвращает сборку на место. После запуска вы снова видите **свою**
  сборку, а не версию из репозитория.
- **Правки в исходниках** сохраняются в `git stash` (`yappytuber auto-backup`) —
  только они, папка сборки туда не попадает. Вернуть: `git stash pop`. Если stash
  не удался, обновление отменяется: лучше остаться на старой версии, чем стереть
  правки.
- Новые файлы, которых нет в репозитории (заметки, скриншоты, свои ассеты в новых
  папках), не трогаются вообще.
- Если GitHub недоступен или репозиторий приватный и вход не выполнен, скрипт
  предупреждает и **запускает уже имеющиеся файлы** без обновления — окно не
  закрывается с ошибкой.
- Если ветка разошлась с удалённой, выполняется `reset --hard origin/<ветка>`;
  прежнее состояние доступно через `git reflog`.
- `node_modules` переустанавливаются только когда их нет; иначе выполняется
  `npm install`, чтобы подхватить новые зависимости.

Если после обновления ваша сборка отличается от версии в репозитории, скрипт
говорит об этом одной строкой и подсказывает два действия:

```text
Своя сборка в dist возвращена на место (в репозитории — версия из обновления).
  опубликовать: publish-build.bat · взять версию репозитория: git checkout -- dist
```

Требования: Git и Node.js 20+. Rust нужен только для пересборки `rig_core.wasm`;
без Rust используется закоммиченный артефакт. Нативная Tauri-сборка (`--tauri`)
дополнительно требует Rust, MSVC Build Tools и WebView2.

## Агент обновлений (порт 17802)

Лаунчер поднимает вместе с редактором маленький локальный агент
(`scripts/update-agent.mjs`, `npm run update:agent`). Он нужен для одного:
**заменить файлы собранной папки**, когда в репозитории появилась новая сборка.
Страница в браузере писать файлы не умеет, агент умеет — и живёт в той же папке.

- `GET http://127.0.0.1:17802/health` → `{ "ok": true, "folder": "…/dist", "version": "1.1.22.5.1.1.1" }`
- `POST /apply` с телом `{ "manifest": "https://raw.githubusercontent.com/…/dist/build.json" }`

Разрешены только паспорта этого репозитория с любой ветки:
`https://raw.githubusercontent.com/KvaDRxniKuS/YappyTuberPlus/<ветка>/dist/build.json`
(и адрес из `UPDATE_MANIFEST`, если он задан). Всё остальное — отказ.

Порядок работы агента: скачать паспорт → проверить, что он с разрешённого адреса →
скачать **все** файлы и сверить каждый с `sha256` из паспорта → только после этого
записать их в папку и обновить `build.json`. Недокачанное обновление не попадает
на диск: либо всё, либо ничего.

Что агент не делает: не трогает пресеты и файлы пользователя (они в
`%APPDATA%`/`~/.local/share`), не запускает сборку, не лезет в git. Пишет только
те пути, что перечислены в паспорте, и только внутри папки сборки.

Параметры (переменные окружения):

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `UPDATE_FOLDER` | `dist` | папка, которую можно заменять |
| `UPDATE_AGENT_PORT` | `17802` | порт агента |
| `UPDATE_AGENT_HOST` | `127.0.0.1` | адрес прослушивания |
| `UPDATE_MANIFEST` | — | дополнительный разрешённый адрес паспорта (свой сервер, локальная проверка) |

Выключить агент можно флагом `--no-update` (`start-yappytuber.bat --no-update`).
Тогда обновление папки сделает сам лаунчер при следующем запуске: он тянет
репозиторий и пересобирает папку.

## Свежий скрипт из ветки

Если в папке лежит старый экземпляр (например, из первого архива), замените файл:

```text
https://raw.githubusercontent.com/KvaDRxniKuS/YappyTuberPlus/arena/e287965b-yappytuberplus/start-yappytuber.bat
https://raw.githubusercontent.com/KvaDRxniKuS/YappyTuberPlus/arena/e287965b-yappytuberplus/start-yappytuber.sh
```

Скачайте ссылку «Save as…» рядом с проектом (или прямо в папку проекта) и запустите.
После первого запуска файл уже сам подтягивает обновления, в том числе собственные.

## Если репозиторий приватный

`git clone` и `git fetch` могут один раз попросить вход в GitHub — откроется окно
Git Credential Manager, войдите через браузер и повторите запуск. После этого вход
запоминается, и обновления идут молча.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| «не найден git» / «не найден Node.js» | согласиться на установку через winget или поставить вручную и запустить файл снова |
| «Автообновление недоступно: папка не является git-репозиторием» | это сообщение старой версии скрипта из первого ZIP: положите в папку файл `start-yappytuber.bat` из ветки (ссылка ниже) и запустите снова — он сам включит обновление |
| Просит логин GitHub | войти один раз в окне Git Credential Manager |
| «не удалось склонировать» | проверить доступ к GitHub и права на репозиторий, затем запустить снова |
| Окно закрылось мгновенно | запустить `start-yappytuber.bat` из `cmd`, чтобы увидеть текст ошибки |
| Порт занят | `--port 5199` |
| Браузер не открылся | открыть `http://localhost:5173/` вручную |
| Нужен чистый старт | удалить `node_modules` и запустить файл снова |
