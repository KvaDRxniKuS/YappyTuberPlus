# Версии проекта

Отсчёт начинается с **0.1** — это первая версия, в которой набор возможностей
зафиксирован. Версия — не одна строка, а **кортеж из шести чисел**: у продукта
несколько слоёв, и ломаются они по отдельности. Файл пресета может остаться
прежним, а ядро — научиться новым формулам; оболочка может обновиться, не
тронув ни данных, ни языка.

```
0.1 . 2 . 3 . 1 . 1
 │    │   │   │   └─ оболочка
 │    │   │   └───── мост
 │    │   └───────── формат
 │    └───────────── ядро
 └────────────────── релиз
```

## 1. Слоты

| Слот | Сейчас | Что это | Что ломается при расхождении |
|---|---|---|---|
| **релиз** `0.1` | `0.1` | То, что видит пользователь: 0.1, 0.2, 1.0 | Ничего технически. Это ярлык вехи, а не совместимость |
| **ядро** | `2` | DSL, параметры кадра, семантика `smooth`/`spring`/событий. `crates/rig-core`, `rig_core.wasm` | Старое ядро не понимает новую формулу и **молча считает 0** с диагностикой в консоли. Картинка при этом выглядит «почти правильно» |
| **формат** | `3` | Структура файла пресета (`RigPreset.version`) | Старый редактор не знает новый вид объекта или поле и **теряет их при сохранении** |
| **мост** | `1` | Протокол редактор ↔ оверлей (`OVERLAY_PROTOCOL`) | Кадры не доходят или перестают обновляться: в OBS картинка замирает |
| **оболочка** | `1` | Приложение Tauri: окна, click-through, глобальные клавиши, планировщик, файловые диалоги | Приложение старше файла: не хватает возможностей, которых файл ждёт (например нативного планировщика кадров) |

Числа растут **только вверх** и никогда не переиспользуются. Релиз — два числа,
потому что так его удобнее называть вслух и так его ждёт установщик
(`packagingVersion()` → `0.1.0`, MSI и NSIS принимают только три числа).

## 2. Где эти числа живут

Одна правда на весь код — `src/version.ts`. Дублировать числа в других местах
нельзя: они разъедутся молча.

| Число | Источник | Кто сверяет |
|---|---|---|
| релиз, мост, оболочка, ожидаемое ядро | `src/version.ts` (`VERSION`) | редактор |
| фактическое ядро | `crates/rig-core/src/lib.rs` (`CORE_GENERATION`), отдаётся запросом `{ "op": "version" }` | `useRigEngine`, статусная строка |
| формат | `src/version.ts` (`PRESET_FORMAT`) → поле `version` в пресете | `normalizePreset` при чтении |
| мост на проводе | `src/overlay/protocol.ts` (`OVERLAY_PROTOCOL`) → поля `protocol` в `hello`/`announce` | оверлей и редактор |
| сборка, записавшая файл | поле `built` в пресете, ставится при сохранении (`withBuildStamp`) | редактор при открытии |

### Почему у ядра отдельное число, а не «версия продукта»

Ядро — единственный слой, который **не обновляется вместе с редактором**: WASM
собирается отдельно (`npm run build:wasm`), и пользователь вполне может держать
редактор новее. Ошибка при этом тихая: неизвестное имя возвращает `0` и пишет
диагностику, а не падает. Поэтому:

- редактор один раз спрашивает у ядра его поколение;
- если ядро не ответило (не знает самого запроса) — оно заведомо старое;
- в статусной строке появляется `ядро` с подсказкой, и один раз выходит
  сообщение «пересоберите ядро».

Так выглядит расхождение в интерфейсе:

| Состояние | Статус | Что делать |
|---|---|---|
| `core == VERSION.core` | молчит | ничего |
| `core < VERSION.core` или ответа нет | `ядро` + сообщение один раз | `npm run build:wasm` (или bat-файл сборки) |
| `core > VERSION.core` | `ядро` + подсказка | пересобрать редактор: возможности ядра не используются |

## 3. Когда поднимать число

Правило одно: **растёт слот, в котором появилось то, чего прежняя сборка не
понимает.** Добавление, которое старый код просто проигнорирует без потери для
пользователя, номер не меняет.

| Изменение | Ядро | Формат | Мост | Оболочка |
|---|---|---|---|---|
| Новая функция DSL, новый параметр кадра | **+1** | — | — | — |
| Изменена семантика существующей функции (другое поведение при тех же числах) | **+1** | — | — | — |
| Новый вид объекта, новое обязательное поле пресета | +1 (если вид считается в кадре) | **+1** | — | — |
| Новое необязательное поле с безопасным значением по умолчанию | — | — | — | — |
| Новое сообщение протокола, без которого всё работает | — | — | — | — |
| Изменён смысл существующего сообщения или номера кадра | — | — | **+1** | — |
| Новое окно, клавиша, нативный планировщик | — | — | — | **+1** |
| Только интерфейс редактора (панели, подсказки, горячие клавиши) | — | — | — | — |
| Исправление без изменения наблюдаемого поведения | — | — | — | — |

Что считается «потерей для пользователя» на практике:

- **потеря данных** — поле или вид объекта, который старый редактор выкинет при
  сохранении (так было со `light` и `normal`) → формат;
- **тихий ноль** — формула, которую старое ядро посчитает как `0` (так будет с
  любым новым параметром) → ядро;
- **замерший оверлей** — смена формы кадра или `seq` → мост.

## 4. Что делать при расхождении

| Ситуация | Поведение |
|---|---|
| Файл старше сборки (формат 2 против 3) | **Читаем**: `normalizePreset` принимает прошлые поколения, недостающее получает значения по умолчанию, версия в памяти сразу становится текущей. Отдельной миграции нет, пока данные совместимы |
| Файл новее сборки | **Не открываем**: `normalizePreset` возвращает `null`. Иначе редактор потерял бы незнакомые настройки при первом же сохранении. Если такой файл всё же попал в состояние (пришёл извне), в статусе горит `пресет новее` с перечнем отставших слотов |
| Ядро старше редактора | Сцена работает, в статусе `ядро`, один раз сообщение. Новые формулы вернут 0 — это видно по подсказке, а не по «сломанной» картинке |
| Ядро новее редактора | Ничего не ломается: редактор просто не пользуется новым. Подсказка советует обновить редактор |
| Оверлей другой сборки | Оверлей присылает `protocol` в `hello`, редактор — в `announce`. При расхождении в статусе горит `оверлей старой сборки`, а подсказка просит перезагрузить страницу источника в OBS: страница кэшируется браузером OBS, и обновление — единственное лечение |

Старые поколения формата перечислены в `PRESET_FORMATS_READABLE`. Когда
совместимости не останется (данные придётся перестраивать, а не дозаполнять),
старое число уходит из списка **вместе с подъёмом формата** — это и есть
момент, когда читать файлы прошлой версии редактор перестаёт.

## 5. Установщик и файлы сборки

| Место | Значение | Почему так |
|---|---|---|
| `package.json` | `0.1.0` | `packagingVersion()`: релиз плюс `.0` |
| `src-tauri/tauri.conf.json` | `0.1.0` | Tauri и MSI/NSIS принимают только три числа |
| `src-tauri/Cargo.toml`, `crates/rig-core/Cargo.toml` | `0.1.0` | версия крейта, к совместимости отношения не имеет |
| статусная строка редактора | `0.1.2.3.1.1` | полный кортеж, подсказка расписывает слоты |
| пресет, поле `built` | `0.1.2.3.1.1` | по нему видно, чем файл записан |

Полный кортеж в установщик не идёт намеренно: три числа — предел форматов MSI и
NSIS, а поколения нужны только редактору и файлу.

## 6. Чек-лист перед выпуском

1. Решить, какие слоты выросли, и поднять **только их**.
2. `src/version.ts` — `VERSION` (и `PRESET_FORMAT`, если менялся формат).
3. Если менялось ядро — `CORE_GENERATION` в `crates/rig-core/src/lib.rs` и
   пересборка `public/rig_core.wasm` (`npm run build:wasm`).
4. Если менялся протокол — `OVERLAY_PROTOCOL` в `src/overlay/protocol.ts`.
5. `package.json`, `src-tauri/tauri.conf.json`, оба `Cargo.toml` — релиз
   (`packagingVersion`).
6. Запись в `CHANGELOG.md` с новой версией в заголовке.
7. `npx tsc --noEmit`, `npx playwright test`, `npm run build`.
8. Проверить в статусной строке: версия та, что ожидалась, `ядро` не горит,
   `пресет новее` не горит.

## 7. Открытые вопросы (обсуждаются)

Ниже — то, что сознательно **не** решено, чтобы не зашивать правило раньше
времени. Пока решения нет, действует правило §3.

1. **Слот «модули».** У модулей есть свой контракт: поля шаблона, имена входов,
   события наград. Сейчас он живёт внутри формата. Нужен ли отдельный номер?
   Аргумент за: модуль можно обновить, не трогая пресет, и старый модуль может
   не отдать новый вход. Аргумент против: лишний слот, который почти всегда
   растёт вместе с форматом.
2. **Слот «ассеты».** Хранилище файлов (IndexedDB + папка `<имя>.assets` +
   `index.json`) имеет свою версию `version: 1`. Пока менялось только
   добавлением, но папка переживает пресет — расхождение возможно.
3. **Релиз против поколений.** Сейчас релиз — ярлык, который может не меняться
   при росте поколений. Альтернатива — выводить релиз из поколений
   автоматически (`0.1` = первое поколение ядра). Тогда «0.1.2.3.1.1» станет
   избыточным.
4. **Обновление из приложения.** Когда появится автообновление, номер оболочки
   начнёт сравниваться с сервером обновлений, а не только с файлом. Понадобится
   правило «минимальная оболочка для формата».
5. **Что делать с будущим форматом, если данных нет.** Сейчас такой файл просто
   не открывается. Можно открывать «только для чтения»: показать, что поняли, и
   запретить сохранение поверх. Это удобнее, но требует отдельного состояния
   документа.

## 8. История

| Версия | Дата | Что произошло |
|---|---|---|
| `0.1.2.3.1.1` | 2026-10-27 | Отсчёт начат. Зафиксирован набор возможностей (см. `CHANGELOG.md`): свет, карты нормалей, следование за мышью, оверлей с общим счётчиком кадров, версия ядра в пресете |

До 0.1 версии не считались: набор возможностей менялся свободно, а совместимость
обеспечивалась миграциями на месте (например `version: 2` читается по сей день).
