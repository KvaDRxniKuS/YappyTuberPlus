# Паспорт версии

Версия проекта — **набор чисел**, а не одна строка. Продукт состоит из слоёв, и
ломаются они по отдельности: файл пресета может остаться прежним, а ядро —
научиться новым формулам; оболочка может обновиться, не тронув ни данных, ни
языка. Одна строка `1.0.0` об этом ничего не говорит.

## 1. Как читать

Для человека версия пишется подписями:

```
1.0 · ядро 21 · файл 3 · мост 1 · модули 1 · оболочка 1
```

Машинная запись — те же числа через точку, в том же порядке (её пишут в файл
пресета и копируют из строки состояния):

```
1.0.21.3.1.1.1
 │ │  │  │  │  │  └─ оболочка
 │ │  │  │  │  └──── модули
 │ │  │  │  └─────── мост
 │ │  │  └────────── файл
 │ │  └───────────── ядро
 └─┴─────────────── релиз
```

| Слот | Сейчас | Что означает | Что именно ломается при расхождении |
|---|---|---|---|
| **релиз** | `1.0` | Веха продукта: то, что видит пользователь и что уходит в установщик | Ничего технически. Это ярлык: `1.0` — первая версия, которая «просто работает» |
| **ядро** | `21` | Поколение контракта `rig-core`: функции DSL, параметры кадра, виды объектов, семантика кадра | Старое ядро не понимает новую формулу и **молча возвращает 0** с диагностикой в консоли. Картинка при этом выглядит «почти правильно» |
| **файл** | `3` | Поколение формата пресета (`version`) и папки файлов рядом с ним (`<имя>.assets`, `index.json`) | Старый редактор не знает новый вид объекта или поле и **теряет их при сохранении** |
| **мост** | `1` | Протокол редактор ↔ оверлей (`OVERLAY_PROTOCOL`) | Оверлей другой сборки не получает кадры: в OBS картинка замирает |
| **модули** | `1` | Контракт шаблонов из папки `modules`: виды модулей, поля настроек, входы | Незнакомый вид модуля тихо становится «Manual», его поля настроек не показываются |
| **оболочка** | `1` | Приложение Tauri: окна, клик-сквозь, клавиши, планировщик кадров, файловые команды | Сборка старше пресета не умеет часть того, что он ждёт (например, нативный планировщик) |

Релиз — два числа, потому что так его называют вслух и так его ждёт установщик:
`packagingVersion()` → `1.0.0`, MSI и NSIS принимают только три числа.

Полная версия видна в строке состояния: `1.0 · ядро 21`. Подсказка расписывает
все слоты, клик копирует машинную запись.

## 2. Где эти числа живут

Одна правда на весь код — `src/version.ts`. Дублировать номера в других местах
нельзя: они разъедутся молча.

| Число | Источник | Кто сверяет |
|---|---|---|
| релиз, файл, мост, модули, оболочка, ожидаемое ядро | `src/version.ts` (`VERSION`) | редактор |
| фактическое ядро | `crates/rig-core/src/lib.rs` (`CORE_GENERATION`), отдаётся запросом `{ "op": "version" }` | `useRigEngine`, строка состояния |
| формат файла | поле `version` в пресете | `normalizePreset` при чтении |
| мост на проводе | поле `protocol` в `hello`/`announce` | оверлей и редактор |
| контракт модуля | поле `format` в `public/modules/*.json` | библиотека модулей |
| сборка, записавшая файл | поле `built` в пресете, ставится при сохранении | редактор при открытии |

Почему ядро считается отдельно: **это единственный слой, который не обновляется
вместе с редактором**. `rig_core.wasm` собирается командой `npm run build:wasm`,
и пользователь вполне может держать редактор новее. Ошибка при этом тихая:
неизвестное имя возвращает `0` и пишет диагностику, а не падает. Поэтому
редактор спрашивает поколение ядра и говорит об этом вслух.

| Состояние ядра | В строке состояния | Что делать |
|---|---|---|
| совпадает с редактором | молчит | ничего |
| старше (или не ответило) | `ядро` + сообщение один раз | `npm run build:wasm` |
| новее редактора | `ядро` + подсказка | обновить редактор: возможности ядра не используются |

## 3. Когда какое число растёт

Правило одно: **растёт слот, в котором появилось то, чего прежняя сборка не
понимает.** Добавление, которое старый код просто проигнорирует без потери для
пользователя, номер не меняет.

| Изменение | ядро | файл | мост | модули | оболочка |
|---|---|---|---|---|---|
| Новая функция DSL, новый параметр кадра | **+1** | — | — | — | — |
| Изменена семантика существующей функции (другое поведение при тех же числах) | **+1** | — | — | — | — |
| Язык стал строже: то, что раньше принималось, теперь ошибка | **+1** | — | — | — | — |
| Новый вид объекта, новое обязательное поле пресета | +1 (если вид считается в кадре) | **+1** | — | — | — |
| Новое необязательное поле с безопасным значением по умолчанию | — | — | — | — | — |
| Новое сообщение протокола, без которого всё работает | — | — | — | — | — |
| Изменён смысл существующего сообщения или нумерации кадров | — | — | **+1** | — | — |
| Новый вид модуля, новое поле настроек модуля | — | — | — | **+1** | — |
| Новое окно, клавиша, нативный планировщик | — | — | — | — | **+1** |
| Только интерфейс редактора (панели, подсказки, горячие клавиши) | — | — | — | — | — |
| Исправление без изменения наблюдаемого поведения | — | — | — | — | — |

Что считается потерей для пользователя на практике:

- **потеря данных** — поле или вид объекта, который старый редактор выкинет при
  сохранении (так было со `light` и `normal`) → **файл**;
- **тихий ноль** — формула, которую старое ядро посчитает как `0` → **ядро**;
- **замерший оверлей** — смена формы кадра или `seq` → **мост**;
- **молча другой модуль** — незнакомый вид стал «Manual» → **модули**.

## 5. Что делать при расхождении

| Ситуация | Поведение |
|---|---|
| Файл старше сборки (формат 2 против 3) | **Читаем**: `normalizePreset` принимает прошлые поколения, недостающее получает значения по умолчанию, версия в памяти сразу становится текущей. Отдельная миграция не нужна, пока данные совместимы |
| Файл новее сборки | **Не открываем**: `normalizePreset` возвращает `null`. Иначе редактор потерял бы незнакомые настройки при первом же сохранении. Если такой файл всё же оказался в состоянии, в строке состояния горит `пресет новее` с перечнем отставших слотов |
| Ядро старше редактора | Сцена работает, в строке состояния `ядро`, один раз выходит сообщение. Новые формулы вернут 0 — это видно по подсказке, а не по «сломанной» картинке |
| Ядро новее редактора | Ничего не ломается: редактор просто не пользуется новым. Подсказка советует обновить редактор |
| Оверлей другой сборки | Оверлей присылает `protocol` в `hello`, редактор — в `announce`. При расхождении в строке состояния горит `оверлей старой сборки`: страница источника в OBS кэшируется, её нужно перезагрузить |
| Модули новее редактора | В строке состояния горит `модули`; незнакомый вид модуля считается «Manual», о чём и написано в подсказке |

Старые поколения формата перечислены в `PRESET_FORMATS_READABLE`. Когда
совместимости не останется (данные придётся перестраивать, а не дозаполнять),
старое число уходит из списка **вместе с подъёмом формата** — это и есть
момент, когда читать файлы прошлой версии редактор перестаёт.

## 6. Установщик и файлы сборки

| Место | Значение | Почему так |
|---|---|---|
| `package.json` | `1.0.0` | `packagingVersion()`: релиз плюс `.0` |
| `src-tauri/tauri.conf.json` | `1.0.0` | Tauri и MSI/NSIS принимают только три числа |
| `src-tauri/Cargo.toml`, `crates/rig-core/Cargo.toml` | `1.0.0` | версия крейта, к совместимости отношения не имеет |
| строка состояния редактора | `1.0` + `ядро 21` | релиз и главное поколение видны сразу |
| подсказка/копирование | `1.0.21.3.1.1.1` | полный паспорт: пишется в файл и копируется |
| пресет, поле `built` | `1.0.21.3.1.1.1` | по нему видно, чем файл записан |

## 7. Чек-лист перед выпуском

1. Решить, какие слоты выросли, и поднять **только их**.
2. `src/version.ts` — `VERSION` (и `PRESET_FORMAT` / `MODULE_FORMAT`, если
   менялся файл или контракт модулей).
3. Если менялось ядро — новая строка в таблице §4, `CORE_GENERATION` в
   `crates/rig-core/src/lib.rs`, пересборка `public/rig_core.wasm`
   (`npm run build:wasm`).
4. Если менялся протокол — `OVERLAY_PROTOCOL` в `src/overlay/protocol.ts`.
5. `npm run version:report` — таблица, редактор и ядро на одном числе.
6. `package.json`, `src-tauri/tauri.conf.json`, оба `Cargo.toml` — релиз
   (`packagingVersion`).
7. Запись в `CHANGELOG.md` с паспортом версии в заголовке.
8. `npx tsc --noEmit`, `npx playwright test`, `npm run build`.
9. Проверить в строке состояния: версия та, что ожидалась; `ядро`,
   `модули` и `пресет новее` не горят.

## 8. Открытые вопросы (обсуждаются)

Пока решения нет, действует правило §3.

1. **Слот «склад файлов».** `index.json` папки `<имя>.assets` имеет своё
   `version: 1`, сейчас он живёт внутри слота «файл». Нужен ли отдельный номер:
   папка переживает пресет, и расхождение возможно само по себе.
2. **Релиз против поколений.** Сейчас релиз — ярлык, который может не меняться
   при росте поколений. Альтернатива: выводить релиз из поколений (например,
   `1.0` — это «ядро 21 и файл 3»), тогда паспорт был бы короче на два числа.
3. **Обновление из приложения.** Когда появится автообновление, `оболочка`
   начнёт сравниваться с сервером, а не только с файлом. Понадобится правило
   «минимальная оболочка для формата».
4. **Будущий формат: открывать «только для чтения»** вместо отказа? Сейчас
   отказ; чтение удобнее, но требует отдельного состояния документа.
5. **Поколение ядра в пресете.** Сейчас в файле пишется вся сборка (`built`).
   Можно писать отдельно минимум ядра, при котором файл ещё имеет смысл, — тогда
   старый редактор смог бы открыть файл «как есть», не теряя незнакомое.

## 9. История релизов

| Паспорт | Дата | Что произошло |
|---|---|---|
| `1.0.21.3.1.1.1` | 2026-10-27 | Отсчёт начат с 1.0: набор возможностей зафиксирован — свет, карты нормалей, следование и доворот за мышью, сквозной номер кадра в оверлее, версия ядра в пресете. Состав версии — `CHANGELOG.md` |

день). Нумерация ядра при этом восстанавливается по истории git — таблица §4
как раз для этого.
