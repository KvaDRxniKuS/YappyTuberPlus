# Разработка модулей: как устроено и как добавить свой

Документ для тех, кто пишет **свои модули** (шаблоны и новые виды входов) — разработчикам и
нейросетям-ассистентам. Пользовательская часть — [`MODULES.md`](MODULES.md); дизайн ядра —
[`DESIGN.md`](DESIGN.md); сетевые и внешние источники — раздел 9 (что есть сейчас и что нужно).

Главное правило проекта: **источник истины — код**. JSON описывает входы и настройки, но
ничего не считает; математику выбирает поле `kind`, а реализация `kind` живёт в `src/modules/`.
Поэтому сегодня есть два уровня расширения:

| Уровень | Что делает автор | Нужно ли трогать код |
|---|---|---|
| **Шаблон** (данные) | новый JSON в `public/modules/`, ссылка в `index.json` | нет |
| **Вид входа** (новый `kind`) | новый файл в `src/modules/` + регистрация в 5 местах | да |

---

## 1. Шаблон модуля: полная схема

Файл `public/modules/<id>.json`, где `<id>` — латиница в нижнем регистре, цифры и `_`
(`/^[a-z][a-z0-9_]*$/`). Имя файла обязано совпадать с `id`.

```json
{
  "id": "loudness",
  "title": "Loudness",
  "description": "Громкость микрофона: RMS, пик, децибелы и флаг речи.",
  "kind": "loudness",
  "audio": true,
  "inputs": [
    { "name": "speak", "label": "Речь", "kind": "level", "min": 0, "max": 1, "step": 0.01,
      "hint": "RMS со сглаживанием: основной вход для анимации рта" },
    { "name": "db", "label": "Уровень", "kind": "db", "min": -80, "max": 0 }
  ],
  "fields": [
    { "key": "deviceId", "label": "Устройство", "type": "device", "default": "default" },
    { "key": "gate", "label": "Порог речи", "type": "number", "min": -80, "max": 0, "step": 1,
      "default": -50, "suffix": "дБ" }
  ],
  "defaults": { "gate": -50, "speakAttack": 40, "speakRelease": 140 }
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | идентификатор шаблона; он же тип экземпляра (`module.type`) |
| `title` | нет | заголовок карточки и палитры (по умолчанию `id`) |
| `description` | нет | строка под заголовком в раскрытой карточке |
| `kind` | да по смыслу | реализация в коде: `loudness`, `manual`, `autoblink`, `viseme`, `keyboard`, `key`, `mouse` |
| `audio` | нет | `true` — модулю нужен микрофон (показывается переключатель «Микрофон / Ползунок») |
| `inputs` | да | входы экземпляра: они и есть переменные скрипта `<имя модуля>.<имя входа>` |
| `fields` | нет | поля настроек карточки |
| `defaults` | нет | стартовые значения настроек (и единственное место для списков: виземы, состояния, клавиши, кнопки) |

### 1.1 `inputs[]`

| Ключ | Тип | Правила |
|---|---|---|
| `name` | строка | обязательный, латиница: имя переменной в скрипте |
| `label` | строка | подпись в панели (по умолчанию `name`) |
| `kind` | `level` \| `db` \| `flag` | `level` — 0…1 по умолчанию; `db` — децибелы, ноль = тишина (−60), полоска считается по −80…0; `flag` — 0/1 с кнопками |
| `min`, `max` | числа | границы; у `db` по умолчанию −80…0, у остальных 0…1 |
| `step` | число | шаг ползунка, по умолчанию 0.01 |
| `hint` | строка | всплывающая подсказка; у визем показывает число вариантов записи |

В `kind: "manual"` и `kind: "autoblink"` границы ползунка берутся **из настроек экземпляра**
(`config.min/max/step`), у остальных — из описания входа. Это сделано в `inputRange()`.

### 1.2 `fields[]`

| Ключ | Значения | Смысл |
|---|---|---|
| `key` | строка | ключ в `module.config` |
| `label` | строка | подпись |
| `type` | `number` \| `flag` \| `select` \| `device` | контрол в карточке |
| `min`, `max`, `step`, `suffix` | числа/строка | для `number` (и подпись единиц: `дБ`, `мс`, `×`) |
| `options` | `[{ "value", "label" }]` | для `select` |
| `default` | число/строка/логическое | значение по умолчанию |
| `showWhen` | `{ "другоеПоле": значение }` | показывать поле только при таких значениях |
| `hint` | строка | подсказка |

Нормализация значений — `normalizeConfig()` в `src/engine/preset.ts`: числа обрезаются по
`min/max`, флаги приводятся к `boolean`, `select`/`device` к строке. **Незнакомые ключи
сохраняются как есть**, поэтому своё поле не пропадёт при загрузке.

### 1.3 `defaults` — и место, где живут списки

`defaults` — база для `module.config` нового экземпляра (`moduleDefaults()`). Списки
(виземы, состояния enum, клавиши, кнопки мыши) описываются **только здесь** и потом живут в
настройках экземпляра: у двух экземпляров одного шаблона они независимы (при копировании
массивов `moduleDefaults()` делает поверхностную копию каждого элемента).

```json
"defaults": {
  "states": [
    { "name": "idle", "label": "Покой" },
    { "name": "walk", "label": "Идёт" }
  ]
}
```

## 2. Как шаблон попадает в приложение

1. `public/modules/index.json` перечисляет файлы: `{ "modules": ["loudness", "viseme", …] }`.
   Файл, которого нет в индексе, **не читается**.
2. `refreshLibrary()` (`src/modules/registry.ts`) читает индекс и каждый шаблон с
   `cache: "no-cache"`, затем `normalizeDefinition()` проверяет и приводит данные.
3. Битый файл не ломает библиотеку: он просто пропускается, а панель показывает статус.
4. Порядок карточек задаёт `ORDER` в `registry.ts` (сначала источники сигнала, потом ручные);
   всё неизвестное сортируется после по алфавиту.
5. В dev-режиме достаточно обновить вкладку — `public/` отдаётся как есть; в собранном
   приложении папка `modules` лежит рядом с веб-сборкой.

**Ловушка:** неизвестный `kind` молча превращается в `manual` (`normalizeDefinition`, список
`known`). Модуль появится, но вести себя будет как ручной ползунок. Если добавляете новый вид
входа — сначала зарегистрируйте `kind`, потом шаблон.

## 3. Как значения доходят до кадра

```text
источник (микрофон / ползунок / таймер / клавиатура / мышь)
   │  useModuleInputs: AudioFrame{}, manual{}, auto{}, PointerFrame
   ▼
instanceInputs(module)        описание входов экземпляра (может зависеть от настроек)
   ▼
composeValues(modules, src)   плоский словарь { "mic.talking": 1, "manual.value": 2, … }
   ▼
inputs.values → engine tick   в ядро уходят ТОЛЬКО числа
   ▼
RigFrame.objects[id] / globals → формулы и события скрипта
```

Ключевые свойства:

- **выключенный вход не попадает в словарь вовсе** — скрипт, читающий его, честно получает
  «неизвестное имя `x`; использован 0»;
- приоритет источника задаёт `module.source` (`live`/`manual`) и `kind`;
- значения — только числа; строки, массивы и объекты в ядро не передаются (для текста в
  будущем нужен отдельный канал, см. §9);
- состояние (моргание, удержание клавиши) считает фронтенд, ядро остаётся чистым.

## 4. Экземплярные списки

Три списка уже сделаны по одному образцу (`visemes`, `keys`/`buttons`, `states`) — если
добавляете свой, повторите шаги:

1. Тип в `src/types.ts` (например `EnumState`) и ключ в `ModuleConfig`.
2. Нормализация в `src/engine/preset.ts`: функция `normalizeXxx()` + ветка в `normalizeModules()`
   (имя входа через `sanitize…`/`unique…`, чтобы получилась латиница без повторов).
3. Входы экземпляра: ветка в `instanceInputs()` (`src/modules/values.ts`).
4. Значения: ветка в `composeValues()`.
5. Редактор списка: отдельный компонент в `src/components/` и условие в `ModulesPanel`
   (примеры: `VisemeEditor`, `KeyboardKeysEditor`, `EnumStatesEditor`).
6. `defaults` в JSON шаблона — стартовый список.

Правило имён: подпись может быть любой (кириллица, `ö`), имя входа — всегда латиница,
цифры и `_`, потому что оно попадает в выражение скрипта.

## 5. Как добавить новый вид входа (`kind`)

Всё, что нужно, на примере вымышленного `heartrate`:

1. **`src/types.ts`** — добавить в `ModuleKind`:
   `export type ModuleKind = … | "heartrate";`
2. **`src/modules/registry.ts`** — добавить в `known` внутри `normalizeDefinition()`
   (иначе шаблон станет `manual`).
3. **`src/modules/<name>.ts`** — реализация: как получить число. Пример «сырого» источника
   (для сетевых см. §9):
   ```ts
   export class HeartRateSource {
     private value = 0;
     start(): void { /* подписка, таймер, сокет… */ }
     stop(): void { /* отписка: модуль выключили */ }
     read(): number { return this.value; }
   }
   ```
4. **`src/modules/values.ts`**:
   - `instanceInputs()` — какие входы у экземпляра (если они зависят от настроек);
   - `composeValues()` — откуда берётся значение: новый источник в `ModuleSources` или
     таймер, как у `autoblink`;
   - если входы «живые» (устройство/сеть), добавьте `kind` в `isPointerKind()`-подобную
     проверку, чтобы панель не рисовала ползунок.
5. **`src/hooks/useModuleInputs.ts`** — поднять источник: создать при появлении включённого
   модуля, отписаться при выключении/удалении (`liveKey` и `autoKey` показывают, как
   перезапускать только при смене настроек, а не каждый кадр).
6. **`src/components/ModulesPanel.tsx` / `InputsPanel.tsx`** — если нужен свой редактор:
   условие по `definition.kind`, как у визем.
7. **`public/modules/<id>.json`** + запись в `index.json`.
8. **Документация**: строка в таблицу «Встроенные шаблоны» (`MODULES.md`) и, если поведение
   неочевидное, абзац здесь.
9. **Проверки**: `./node_modules/.bin/tsc --noEmit`, `npm run test:engine`, `npm run build`.

### 5.1 Шаблон каркаса источника, который придётся повторить

Любой внешний источник (сеть, устройство, файл) должен жить по одним правилам:

- **старт по требованию**: только пока есть включённый модуль этого вида;
- **стоп при выключении**: `useEffect`-очистка, иначе сокет/порт останется висеть;
- **значения 30–120 раз в секунду, не чаще**: одно состояние React на тик, а не на пакет;
- **ошибка не ломает сцену**: входы нулевые, причина — в карточке модуля (`props.error`);
- **никаких секретов в пресете**: токены — в профиле WebView (`docs/DATA.md`), не в JSON;
- **переподключение с бэкоффом**, без сообщений в консоль на каждую попытку.

## 6. Грабли, на которые уже наступали

| Грабля | Правило |
|---|---|
| шаблон не появился | файла нет в `index.json`, `id` не совпал с именем файла, `id` с заглавными буквами |
| модуль ведёт себя как ползунок | `kind` не зарегистрирован в `known` — молчаливый откат в `manual` |
| поле настроек пропало | ключа нет в `fields`; `defaults` без `fields` не создаёт контрол |
| настройки «слетели» после сброса | это и есть сброс экземпляра к шаблону (кнопка в карточке модуля) |
| вход есть, а события не работают | вход выключен флажком; выключенный вход не попадает в кадр |
| числа «прыгают» | источник шлёт значения чаще тика; складывайте в ref и отдавайте раз в тик |
| имя входа с кириллицей | имя обязано быть латиницей: подпись отдельно, имя отдельно |
| второй экземпляр меняет первый | массив из `defaults` нужно копировать (это делает `moduleDefaults()`) |

## 7. Проверка своего модуля

```bash
./node_modules/.bin/tsc --noEmit   # типы
npm run test:engine                # ядро живо, DSL не сломан
npm run build                      # сборка веб-части
npm run dev                        # живая проверка: вкладка «Модули» → шаблон в палитре
```

Что проверить руками: карточка появилась в палитре; входы видны во «Входах» и совпадают с
именами в скрипте; выключение входа убирает имя из кадра (ошибка «неизвестное имя»); сброс
настроек возвращает шаблон; второй экземпляр не влияет на первый; после перезапуска настройки
на месте.

---

## 8. Именование в скрипте

`<имя модуля>.<имя входа>` — точка: `mic.talking`, `pose.walk`, `board.space`. Имя модуля
санитизируется (`sanitizeModuleName`): латиница, цифры, `_`, не длиннее 24 символов,
уникально (`mic`, `mic_2`). Переименование модуля **не** переписывает скрипты — это осознанно:
скрипт показывает ошибку «неизвестное имя», а не меняется молча.

## 9. Внешние источники: `kind: "external"`

Самый быстрый способ завести интеграцию: не писать `kind`, а взять готовый шаблон
`public/modules/external.json`. У него один `kind` на все сервисы — всё остальное
задаётся таблицей отображения в настройках экземпляра, то есть в пресете.

### 9.1 Что умеет сегодня

| Транспорт | Состояние | Комментарий |
|---|---|---|
| `ws` (WebSocket) | **работает** | Не подчиняется CORS: одинаково в браузере и в нативном окне |
| `http`, `osc` | зарезервированы | Честно показывают статус «пока недоступно», нулевые входы; ждут Rust-транспорта |

Карточка модуля показывает живой статус: «подключаюсь», «подключён» (со счётчиком
пакетов), «нет связи», «пока недоступно». Обрыв — это нулевые значения, а не
залипшее последнее число.

### 9.2 Настройки экземпляра

`config.source` целиком лежит в пресете, поэтому мост переезжает вместе с ригом:

```json
{
  "transport": "ws",
  "url": "ws://127.0.0.1:17801/inputs",
  "subscribe": "{\"type\":\"subscribe\",\"feed\":\"pulse\"}",
  "reconnect": true,
  "mapping": [
    { "input": "hr",    "path": "$.heart_rate", "label": "Пульс",  "kind": "level", "min": 0, "max": 200, "scale": 1, "offset": 0, "holdMs": 0 },
    { "input": "beat",  "path": "$.beat",       "label": "Удар",   "kind": "flag",  "min": 0, "max": 1,   "scale": 1, "offset": 0, "holdMs": 180 },
    { "input": "cheer", "path": "$.event.bits", "label": "Bits",   "kind": "level", "min": 0, "max": 5000, "scale": 0.001, "offset": 0, "holdMs": 2500 }
  ]
}
```

| Поле | Смысл |
|---|---|
| `transport` | `ws` / `http` / `osc` |
| `url` | Адрес источника; пусто — модуль не запускается и говорит об этом |
| `subscribe` | Строка, которую надо отправить сразу после открытия (подписка, авторизация) |
| `reconnect` | Переподключаться с задержкой 1 → 2 → 4 → 8 с; по умолчанию да |
| `mapping[].input` | Имя входа: в скрипте это `<модуль>.<input>`, только `[a-z0-9_]` |
| `mapping[].path` | Путь в сообщении: `$.value`, `$.data.bpm`, `$.items[0].n` |
| `mapping[].label` | Подпись в «Входах»; пусто — берётся имя входа |
| `mapping[].kind` | `level` (значение), `db` (децибелы), `flag` (0/1) |
| `mapping[].min` / `max` | Границы: значение обрезается по ним |
| `mapping[].scale` / `offset` | Порядок: **сначала множитель, потом смещение**, потом границы |
| `mapping[].holdMs` | Импульс: ненулевое значение держится столько миллисекунд и гаснет само |

Порядок преобразования один и тот же у всех строк — это и есть «детальная
настройка на каждый вход»: подпись, границы, множитель, смещение, удержание.

### 9.3 Конвейер

```
сообщение (строка JSON)
  → JSON.parse (не разобралось — пакет пропущен, состояние не портится)
  → readPath($.a.b[0]) для каждой строки
  → toNumber: число, boolean → 0/1, «12.5» → 12.5, остальное отбрасывается
  → × scale, + offset, обрезка по min/max
  → удержание импульса (holdMs)
  → внешнее значение входа, если вход включён
```

Хост источников один на приложение (`src/modules/sources.ts`): два модуля с
одинаковым адресом делят одно соединение, выключение модуля закрывает сокет.
Пакеты складываются в хосте, а окно забирает снимок раз в 33 мс — поток
120 пакетов/с не превращается в 120 перерисовок React.

### 9.4 Минимальный мост на стороне устройства

Пульсомер, игра или своя железка должны просто отдавать JSON через WebSocket:

```js
// node bridge.js — отдаёт пульс раз в секунду и «удар» по факту
import { WebSocketServer } from "ws";
const server = new WebSocketServer({ port: 17801 });
server.on("connection", (socket) => {
  const timer = setInterval(() => {
    socket.send(JSON.stringify({ heart_rate: 60 + Math.round(Math.random() * 30), beat: 1 }));
  }, 1000);
  socket.on("close", () => clearInterval(timer));
});
```

Адрес в модуле: `ws://127.0.0.1:17801/inputs`, строки `hr → $.heart_rate`,
`beat → $.beat` с `holdMs 180`.

### 9.5 Чего ещё нет

- **HTTP-опрос и токены** — нужен Rust-транспорт и хранение секретов в профиле окна,
  а не в пресете.
- **OSC (UDP), VMC, serial, Bluetooth** — из вебвью доступа нет вовсе, только Rust
  (образец — хук `rdev` с событием `yappy://pointer`).
- **Тексты** (сообщение чата, имя зрителя) — в ядро уходят только числа; для строк
  нужен отдельный канал.

Порядок работ по этому блоку: **каркас (сделан) → Rust-транспорт → Twitch →
пульс/HTTP**. Подробный план по Twitch и устройствам — [`BACKLOG.md`](BACKLOG.md).
