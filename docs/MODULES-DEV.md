# Разработка модулей: как устроено и как добавить свой

Документ для тех, кто пишет **свои модули** (шаблоны и новые виды входов) — разработчикам и
нейросетям-ассистентам. Пользовательская часть — [`MODULES.md`](MODULES.md); дизайн ядра —
[`DESIGN.md`](DESIGN.md); сетевые и внешние источники — раздел 9 (что есть сейчас и что нужно).

Главное правило проекта: **источник истины — код**. JSON описывает входы и настройки, но
ничего не считает; математику выбирает поле `kind`, а реализация `kind` живёт в `src/modules/`.
Поэтому сегодня есть два уровня расширения:

| Уровень | Что делает автор | Нужно ли трогать код |
|---|---|---|
| **Шаблон** (данные) | новый JSON в `public/modules/`, ссылка в `index.json` | нет |
| **Вид входа** (новый `kind`) | новый файл в `src/modules/` + регистрация в 5 местах | да |

---

## 1. Шаблон модуля: полная схема

Файл `public/modules/<id>.json`, где `<id>` — латиница в нижнем регистре, цифры и `_`
(`/^[a-z][a-z0-9_]*$/`). Имя файла обязано совпадать с `id`.

```json
{
  "id": "loudness",
  "title": "Loudness",
  "description": "Громкость микрофона: RMS, пик, децибелы и флаг речи.",
  "kind": "loudness",
  "audio": true,
  "inputs": [
    { "name": "speak", "label": "Речь", "kind": "level", "min": 0, "max": 1, "step": 0.01,
      "hint": "RMS со сглаживанием: основной вход для анимации рта" },
    { "name": "db", "label": "Уровень", "kind": "db", "min": -80, "max": 0 }
  ],
  "fields": [
    { "key": "deviceId", "label": "Устройство", "type": "device", "default": "default" },
    { "key": "gate", "label": "Порог речи", "type": "number", "min": -80, "max": 0, "step": 1,
      "default": -50, "suffix": "дБ" }
  ],
  "defaults": { "gate": -50, "speakAttack": 40, "speakRelease": 140 }
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | идентификатор шаблона; он же тип экземпляра (`module.type`) |
| `title` | нет | заголовок карточки и палитры (по умолчанию `id`) |
| `description` | нет | строка под заголовком в раскрытой карточке |
| `kind` | да по смыслу | реализация в коде: `loudness`, `manual`, `autoblink`, `viseme`, `keyboard`, `key`, `mouse` |
| `audio` | нет | `true` — модулю нужен микрофон (показывается переключатель «Микрофон / Ползунок») |
| `inputs` | да | входы экземпляра: они и есть переменные скрипта `<имя модуля>.<имя входа>` |
| `fields` | нет | поля настроек карточки |
| `defaults` | нет | стартовые значения настроек (и единственное место для списков: виземы, состояния, клавиши, кнопки) |

### 1.1 `inputs[]`

| Ключ | Тип | Правила |
|---|---|---|
| `name` | строка | обязательный, латиница: имя переменной в скрипте |
| `label` | строка | подпись в панели (по умолчанию `name`) |
| `kind` | `level` \| `db` \| `flag` | `level` — 0…1 по умолчанию; `db` — децибелы, ноль = тишина (−60), полоска считается по −80…0; `flag` — 0/1 с кнопками |
| `min`, `max` | числа | границы; у `db` по умолчанию −80…0, у остальных 0…1 |
| `step` | число | шаг ползунка, по умолчанию 0.01 |
| `hint` | строка | всплывающая подсказка; у визем показывает число вариантов записи |

В `kind: "manual"` и `kind: "autoblink"` границы ползунка берутся **из настроек экземпляра**
(`config.min/max/step`), у остальных — из описания входа. Это сделано в `inputRange()`.

### 1.2 `fields[]`

| Ключ | Значения | Смысл |
|---|---|---|
| `key` | строка | ключ в `module.config` |
| `label` | строка | подпись |
| `type` | `number` \| `flag` \| `select` \| `device` | контрол в карточке |
| `min`, `max`, `step`, `suffix` | числа/строка | для `number` (и подпись единиц: `дБ`, `мс`, `×`) |
| `options` | `[{ "value", "label" }]` | для `select` |
| `default` | число/строка/логическое | значение по умолчанию |
| `showWhen` | `{ "другоеПоле": значение }` | показывать поле только при таких значениях |
| `hint` | строка | подсказка |

Нормализация значений — `normalizeConfig()` в `src/engine/preset.ts`: числа обрезаются по
`min/max`, флаги приводятся к `boolean`, `select`/`device` к строке. **Незнакомые ключи
сохраняются как есть**, поэтому своё поле не пропадёт при загрузке.

### 1.3 `defaults` — и место, где живут списки

`defaults` — база для `module.config` нового экземпляра (`moduleDefaults()`). Списки
(виземы, состояния enum, клавиши, кнопки мыши) описываются **только здесь** и потом живут в
настройках экземпляра: у двух экземпляров одного шаблона они независимы (при копировании
массивов `moduleDefaults()` делает поверхностную копию каждого элемента).

```json
"defaults": {
  "states": [
    { "name": "idle", "label": "Покой" },
    { "name": "walk", "label": "Идёт" }
  ]
}
```

## 2. Как шаблон попадает в приложение

1. `public/modules/index.json` перечисляет файлы: `{ "modules": ["loudness", "viseme", …] }`.
   Файл, которого нет в индексе, **не читается**.
2. `refreshLibrary()` (`src/modules/registry.ts`) читает индекс и каждый шаблон с
   `cache: "no-cache"`, затем `normalizeDefinition()` проверяет и приводит данные.
3. Битый файл не ломает библиотеку: он просто пропускается, а панель показывает статус.
4. Порядок карточек задаёт `ORDER` в `registry.ts` (сначала источники сигнала, потом ручные);
   всё неизвестное сортируется после по алфавиту.
5. В dev-режиме достаточно обновить вкладку — `public/` отдаётся как есть; в собранном
   приложении папка `modules` лежит рядом с веб-сборкой.

**Ловушка:** неизвестный `kind` молча превращается в `manual` (`normalizeDefinition`, список
`known`). Модуль появится, но вести себя будет как ручной ползунок. Если добавляете новый вид
входа — сначала зарегистрируйте `kind`, потом шаблон.

## 3. Как значения доходят до кадра

```text
источник (микрофон / ползунок / таймер / клавиатура / мышь)
   │  useModuleInputs: AudioFrame{}, manual{}, auto{}, PointerFrame
   ▼
instanceInputs(module)        описание входов экземпляра (может зависеть от настроек)
   ▼
composeValues(modules, src)   плоский словарь { "mic.talking": 1, "manual.value": 2, … }
   ▼
inputs.values → engine tick   в ядро уходят ТОЛЬКО числа
   ▼
RigFrame.objects[id] / globals → формулы и события скрипта
```

Ключевые свойства:

- **выключенный вход не попадает в словарь вовсе** — скрипт, читающий его, честно получает
  «неизвестное имя `x`; использован 0»;
- приоритет источника задаёт `module.source` (`live`/`manual`) и `kind`;
- значения — только числа; строки, массивы и объекты в ядро не передаются (для текста в
  будущем нужен отдельный канал, см. §9);
- состояние (моргание, удержание клавиши) считает фронтенд, ядро остаётся чистым.

## 4. Экземплярные списки

Три списка уже сделаны по одному образцу (`visemes`, `keys`/`buttons`, `states`) — если
добавляете свой, повторите шаги:

1. Тип в `src/types.ts` (например `EnumState`) и ключ в `ModuleConfig`.
2. Нормализация в `src/engine/preset.ts`: функция `normalizeXxx()` + ветка в `normalizeModules()`
   (имя входа через `sanitize…`/`unique…`, чтобы получилась латиница без повторов).
3. Входы экземпляра: ветка в `instanceInputs()` (`src/modules/values.ts`).
4. Значения: ветка в `composeValues()`.
5. Редактор списка: отдельный компонент в `src/components/` и условие в `ModulesPanel`
   (примеры: `VisemeEditor`, `KeyboardKeysEditor`, `EnumStatesEditor`).
6. `defaults` в JSON шаблона — стартовый список.

Правило имён: подпись может быть любой (кириллица, `ö`), имя входа — всегда латиница,
цифры и `_`, потому что оно попадает в выражение скрипта.

## 5. Как добавить новый вид входа (`kind`)

Всё, что нужно, на примере вымышленного `heartrate`:

1. **`src/types.ts`** — добавить в `ModuleKind`:
   `export type ModuleKind = … | "heartrate";`
2. **`src/modules/registry.ts`** — добавить в `known` внутри `normalizeDefinition()`
   (иначе шаблон станет `manual`).
3. **`src/modules/<name>.ts`** — реализация: как получить число. Пример «сырого» источника
   (для сетевых см. §9):
   ```ts
   export class HeartRateSource {
     private value = 0;
     start(): void { /* подписка, таймер, сокет… */ }
     stop(): void { /* отписка: модуль выключили */ }
     read(): number { return this.value; }
   }
   ```
4. **`src/modules/values.ts`**:
   - `instanceInputs()` — какие входы у экземпляра (если они зависят от настроек);
   - `composeValues()` — откуда берётся значение: новый источник в `ModuleSources` или
     таймер, как у `autoblink`;
   - если входы «живые» (устройство/сеть), добавьте `kind` в `isPointerKind()`-подобную
     проверку, чтобы панель не рисовала ползунок.
5. **`src/hooks/useModuleInputs.ts`** — поднять источник: создать при появлении включённого
   модуля, отписаться при выключении/удалении (`liveKey` и `autoKey` показывают, как
   перезапускать только при смене настроек, а не каждый кадр).
6. **`src/components/ModulesPanel.tsx` / `InputsPanel.tsx`** — если нужен свой редактор:
   условие по `definition.kind`, как у визем.
7. **`public/modules/<id>.json`** + запись в `index.json`.
8. **Документация**: строка в таблицу «Встроенные шаблоны» (`MODULES.md`) и, если поведение
   неочевидное, абзац здесь.
9. **Проверки**: `./node_modules/.bin/tsc --noEmit`, `npm run test:engine`, `npm run build`.

### 5.1 Шаблон каркаса источника, который придётся повторить

Любой внешний источник (сеть, устройство, файл) должен жить по одним правилам:

- **старт по требованию**: только пока есть включённый модуль этого вида;
- **стоп при выключении**: `useEffect`-очистка, иначе сокет/порт останется висеть;
- **значения 30–120 раз в секунду, не чаще**: одно состояние React на тик, а не на пакет;
- **ошибка не ломает сцену**: входы нулевые, причина — в карточке модуля (`props.error`);
- **никаких секретов в пресете**: токены — в профиле WebView (`docs/DATA.md`), не в JSON;
- **переподключение с бэкоффом**, без сообщений в консоль на каждую попытку.

## 6. Грабли, на которые уже наступали

| Грабля | Правило |
|---|---|
| шаблон не появился | файла нет в `index.json`, `id` не совпал с именем файла, `id` с заглавными буквами |
| модуль ведёт себя как ползунок | `kind` не зарегистрирован в `known` — молчаливый откат в `manual` |
| поле настроек пропало | ключа нет в `fields`; `defaults` без `fields` не создаёт контрол |
| настройки «слетели» после сброса | это и есть сброс экземпляра к шаблону (кнопка в карточке модуля) |
| вход есть, а события не работают | вход выключен флажком; выключенный вход не попадает в кадр |
| числа «прыгают» | источник шлёт значения чаще тика; складывайте в ref и отдавайте раз в тик |
| имя входа с кириллицей | имя обязано быть латиницей: подпись отдельно, имя отдельно |
| второй экземпляр меняет первый | массив из `defaults` нужно копировать (это делает `moduleDefaults()`) |
| ссылка в карточке увела всё окно | внешние адреса открывать через `openExternal` (`invoke("open_external")`), а не голым `<a href>` |

## 7. Проверка своего модуля

```bash
./node_modules/.bin/tsc --noEmit   # типы
npm run test:engine                # ядро живо, DSL не сломан
npm run build                      # сборка веб-части
npm run dev                        # живая проверка: вкладка «Модули» → шаблон в палитре
```

Что проверить руками: карточка появилась в палитре; входы видны во «Входах» и совпадают с
именами в скрипте; выключение входа убирает имя из кадра (ошибка «неизвестное имя»); сброс
настроек возвращает шаблон; второй экземпляр не влияет на первый; после перезапуска настройки
на месте.

## 8. Именование в скрипте

`<имя модуля>.<имя входа>` — точка: `mic.talking`, `pose.walk`, `board.space`. Имя модуля
санитизируется (`sanitizeModuleName`): латиница, цифры, `_`, не длиннее 24 символов,
уникально (`mic`, `mic_2`). Переименование модуля **не** переписывает скрипты — это осознанно:
скрипт показывает ошибку «неизвестное имя», а не меняется молча.

## 9. Внешние источники: `kind: "external"`

Самый быстрый способ завести интеграцию: не писать `kind`, а взять готовый шаблон
`public/modules/external.json`. У него один `kind` на все сервисы — всё остальное
задаётся таблицей отображения в настройках экземпляра, то есть в пресете.

### 9.1 Что умеет сегодня

| Транспорт | Где работает | Комментарий |
|---|---|---|
| `ws` (WebSocket) | окно и браузер | Не подчиняется CORS: одинаково в браузере и в нативном окне |
| `http` (опрос) | **только приложение** | Запросы идут из Rust мимо CORS; пауза опроса — `intervalMs` |
| `sse` (поток событий) | **только приложение** | Каждое событие `data:` — один пакет; обрыв = переподключение через 2 с |
| `osc` (UDP) | **только приложение** | Из вебвью UDP недоступен вовсе: слушает Rust |
| `twitch` | **только приложение** | OAuth по коду, подписки EventSub и поток событий канала |

В браузере нативные транспорты не молчат, а честно пишут «только в приложении»:
`fetch` там упёрся бы в CORS, а до UDP из окна не добраться.

Карточка модуля показывает живой статус: «подключаюсь», «подключён» (со счётчиком
пакетов), «нет связи», «пока недоступно». Обрыв — это нулевые значения, а не
залипшее последнее число.

### 9.2 Настройки экземпляра

`config.source` целиком лежит в пресете, поэтому мост переезжает вместе с ригом:

```json
{
  "transport": "ws",
  "url": "ws://127.0.0.1:17801/inputs",
  "intervalMs": 1000,
  "subscribe": "{\"type\":\"subscribe\",\"feed\":\"pulse\"}",
  "reconnect": true,
  "mapping": [
    { "input": "hr",    "path": "$.heart_rate", "label": "Пульс", "kind": "level", "min": 0, "max": 200,  "holdMs": 0 },
    { "input": "beat",  "path": "$.beat",       "label": "Удар",  "kind": "flag",  "min": 0, "max": 1,    "holdMs": 180 },
    { "input": "cheer", "path": "$.event.bits", "label": "Bits",  "kind": "level", "min": 0, "max": 5000, "holdMs": 2500 }
  ]
}
```

| Поле | Смысл |
|---|---|
| `transport` | `ws` / `http` / `sse` / `osc` / `twitch` |
| `url` | Адрес источника; пусто — модуль не запускается и говорит об этом |
| `subscribe` | Строка, которую надо отправить сразу после открытия (`ws`): подписка или авторизация |
| `intervalMs` | Пауза между опросами (`http`), 100…600000 мс, по умолчанию 1000 |
| `reconnect` | Переподключаться с задержкой 1 → 2 → 4 → 8 с (`ws`); по умолчанию да |
| `mapping[].input` | Имя входа: в скрипте это `<модуль>.<input>`, только `[a-z0-9_]` |
| `mapping[].path` | Путь в сообщении: `$.value`, `$.data.bpm`, `$.items[0].n`; для OSC — `$["/avatar/parameters/HR"]` |
| `mapping[].label` | Подпись в «Входах»; пусто — берётся имя входа |
| `mapping[].kind` | `level` (значение), `db` (децибелы), `flag` (0/1) |
| `mapping[].min` / `max` | Границы: значение обрезается по ним |
| `mapping[].holdMs` | «Держать»: ненулевое значение живёт столько миллисекунд и гаснет само; явный ноль снимает удержание сразу |
| `mapping[].when` | Условие `{ "path": …, "equals": … }` (или `contains`): строка срабатывает, только если поле совпало |
| `mapping[].fallback` | Значение, если поля нет или оно не число: «событие пришло» = 1 |
| `mapping[].count` | Счётчик: каждый подходящий пакет прибавляет единицу (чат) |
| `mapping[].when.ignoreCase` | Сравнивать без учёта регистра: `!Dance` = `!dance` |
| `text` | Откуда брать текст чата: `{ "path": …, "authorPath": …, "input": …, "history": …, "showAuthor": … }` |
| `text.input` | Вход, к которому относится текст (у Twitch `chat`): скрипт читает `twitch.chat.message(-1)`. По умолчанию — строка со счётчиком `count` |
| `text.history` | Сколько последних строк помнить: 1…100, по умолчанию 12. Столько же видно в панели и доступно в скрипте |
| `text.showAuthor` | Показывать автора рядом с текстом в панели «Входы» (по умолчанию да) |
| `mapping[].event` | Событие Twitch, к которому относится строка: по нему включаются подписки |
| `clientId` | Twitch: Client ID приложения (не секрет, едет с пресетом) |
| `channel` | Twitch: логин канала, за событиями которого следим |

Настройка на каждый вход — это подпись, границы, шаг и удержание. Множителей и
смещений в таблице нет: источник отдаёт число в своих единицах, вход принимает его
как есть, а привести к другой шкале (доля, проценты) — одна строка скрипта:
`twitch.cheer / 100`, `pulse.hr - 60`.

**Зачем `holdMs`.** Пакет источника — мгновение, а не уровень. «Пришла награда»
приходит один раз, и цена 500 есть только в этом пакете; через кадр вход уже
читается как 0. Без удержания `on twitch.reward.down` не сработал бы никогда
(фронт живёт один кадр), а без удержания и без сброса вход залип бы на 500
навсегда. `holdMs` решает обе беды: значение держится N мс (у Twitch — 3 с у
награды, 2,5 с у bits, 4 с у фоллова), потом возвращается в ноль. У постоянных
величин — пульса, яркости, громкости — там ноль: сбрасывать нечего.

Паспорт входа (`label`, `min`, `max`, `step`, `kind`) — не украшение: редактор
отдаёт его ядру, и скрипт читает те же границы, что видит панель:
`twitch.reward.max`, `mic.db.min`, `twitch.chat.label`. Поэтому «процент от
предела» не надо дублировать числом в каждом скрипте.

### 9.3 Конвейер

```
сообщение (строка JSON)
  → JSON.parse (не разобралось — пакет пропущен, состояние не портится)
  → readPath($.a.b[0]) для каждой строки
  → toNumber: число, boolean → 0/1, «12.5» → 12.5, остальное отбрасывается
  → обрезка по min/max
  → удержание значения (holdMs)
  → внешнее значение входа, если вход включён
```

Хост источников один на приложение (`src/modules/sources.ts`): два модуля с
одинаковым адресом делят одно соединение, выключение модуля закрывает сокет.
Пакеты складываются в хосте, а окно забирает снимок раз в 33 мс — поток
120 пакетов/с не превращается в 120 перерисовок React.

### 9.4 Как устроены нативные транспорты

`http`, `sse` и `osc` поднимает `src-tauri/src/sources.rs`. Окно просит:

```ts
invoke("source_start", { config: { name: "bridge", transport: "sse", url: "http://127.0.0.1:17802/events", intervalMs: 1000 } });
invoke("source_stop", { name: "bridge" });        // выключение модуля или смена адреса
invoke("source_stop_all", {});                    // закрытие приложения
```

Обратно приходят два события `yappy://source`:

```json
{ "kind": "state", "name": "bridge", "state": "live", "message": null }
{ "kind": "text",  "name": "bridge", "text": "{\"heart_rate\":72}" }
```

Важно: **Rust не знает таблицу отображения**. Он приносит сырой текст, а правила
применяет окно — поэтому один и тот же пресет одинаково работает через любой
транспорт, а правила живут в одном месте.

Особенности, которые уже учтены:

- **HTTP** — таймаут 10 с на ответ, 5 с на соединение, пауза между опросами не
  меньше 100 мс. Не-2xx ответ — это статус «нет связи» с кодом, а не тишина.
- **SSE** — общий таймаут не ставится (поток живёт часами), строки `data:`
  склеиваются до пустой строки, `
` отбрасывается; после обрыва — переподключение
  через 2 с, пока модуль включён.
- **OSC** — слушается UDP-порт из адреса (`udp://0.0.0.0:9000`, `osc://:9000` или
  просто `9000`). Понимаются сообщения и бандлы, теги `i`, `f`, `d`, `h`, `T`, `F`;
  адрес становится ключом объекта: `{ "/avatar/parameters/HR": 72 }`, поэтому в
  таблице пишется `$["/avatar/parameters/HR"]`. Строки (`s`) в числа не
  превращаются: тексты в ядро не проходят. Пакет без чисел пропускается.
- **Остановка** — не убийство задачи: источник проверяет флаг и выходит сам,
  чтобы не оставить открытый сокет. Повторный `source_start` с тем же именем
  сначала останавливает прежний, поэтому правка адреса не оставляет два соединения.

Проверка Rust-части без запуска приложения:

```bash
cd src-tauri && cargo test sources   # разбор OSC: сообщение, бандл, теги, порт из URL
```

### 9.5 Twitch

Модуль Twitch — это тот же `kind: "external"` с транспортом `twitch`: входы, границы
и удержание настраиваются обычной таблицей, а вход в аккаунт и подписки берёт на себя
код. Готовый шаблон — `public/modules/twitch.json` (награды, bits, фолловы).

**Что нужно один раз.** Приложение Twitch типа **Public** (без Client Secret) из
`dev.twitch.tv/console/apps`: `Client ID` копируется кнопкой **Manage**, в OAuth
Redirect URLs достаточно `http://localhost`. Тип выбирается при создании и не меняется,
поэтому «Confidential» здесь не подходит: он требует секрет, которому не место ни в
пресете, ни в приложении.

Адрес консоли есть и в интерфейсе: под полем **Client ID** в карточке стоит ссылка
(константа `TWITCH_APPS` в `src/modules/twitch.ts`). Ссылка открывается **системным
браузером**, а не внутри вебвью — иначе окно студии уехало бы на twitch.tv:

```ts
import { openExternal } from "../engine/links";
void openExternal(TWITCH_APPS);   // app: invoke("open_external"); браузер: новая вкладка
```

`openExternal` принимает только `http`/`https` и только символы обычного URL
(без `&`, кавычек и переводов строк): строка уходит в системную команду Rust.
Тот же путь используют ссылка активации `twitch.tv/activate` и любые будущие
ссылки в карточках модулей — обычный `<a href>` без обработчика в приложении
уводит вебвью с приложения, поэтому так не делать.

**Вход по коду (device flow).** Кнопка «Войти в Twitch» в карточке:

1. окно просит у Twitch код (`POST https://id.twitch.tv/oauth2/device`) и показывает
   его вместе со ссылкой `twitch.tv/activate`;
2. код вводится на сайте Twitch, окно раз в несколько секунд спрашивает токен
   (`authorization_pending` — это норма, `slow_down` — увеличиваем паузу);
3. токен сохраняется **в профиле окна** (`localStorage`, ключ `yappy.twitch.<clientId>`),
   в пресет он не попадает и в репозиторий тоже;
4. за минуту до истечения токен обновляется сам (`refresh_token`).

Client ID и имя канала — обычные поля модуля: Client ID не секрет, поэтому пресет
открывается на другой машине без настройки приложения.

**События и права.** Список событий — в `src/modules/twitch.ts` (`TWITCH_EVENTS`).
Галочка в карточке добавляет строку в таблицу отображения, а права доступа
собираются из выбранных событий:

| Событие | Вход по умолчанию | Право |
|---|---|---|
| `channel.chat.message` | `chat` — счётчик сообщений | `user:read:chat` |
| `channel.channel_points_custom_reward_redemption.add` | `reward` — стоимость награды | `channel:read:redemptions` |
| `channel.cheer` | `cheer` — bits | `bits:read` |
| `channel.follow` | `follow` — 1 на несколько секунд | `moderator:read:followers` |
| `channel.subscribe` | `subscribe` — подписка | `channel:read:subscriptions` |
| `channel.subscription.gift` | `gift` — сколько подарили | `channel:read:subscriptions` |
| `channel.raid` | `raid` — зрителей в рейде | не требуется |
| `channel.hype_train.end` | `hype` — уровень | `channel:read:hype_train` |

**Почему у строк есть `when`.** Одно событие — одно сообщение, но таблица общая:
без условия правило с `fallback` срабатывало бы на любом пакете, и «фоллов»
появлялся бы от каждой награды. Поэтому строки шаблона проверяют
`$.metadata.subscription_type`. Ручные строки можно оставить без условия — тогда
они читают поле из любого сообщения.

**Чат, команды и награды по именам.**

- **Чат** — счётчик `chat`: каждое сообщение прибавляет единицу (это `count` в
  правиле, значение берётся не из поля). Текст сообщения и имя зрителя показываются
  во вкладке «Входы» под входами модуля и в журнале. В формулы текст не попадает:
  движок входов числовой, и это осознанно — иначе в выражениях появились бы строки.
- **Команда** `!dance` — одно поле ввода в карточке, и появляется вход `cmd_dance`
  (`флаг на 3 с`). Условие — «содержит `!dance`», регистр не важен: `!Dance` тоже
  сработает. Русские команды (`!танец`) работают: имя входа транслитерируется в
  `cmd_tanec`.
- **Награда по имени** — вводится название ровно как в Twitch («Смена аватара»),
  появляется вход `redeem_smena_avatara` (флаг на 5 с). Условие — равенство
  `$.payload.event.reward.title`.

Почему имя входа не может быть просто названием: входы попадают в скрипт, где
допустимы `[a-z0-9_]`. Поэтому кириллица транслитерируется, пробелы становятся
`_`, а вход всегда начинается с латиницы. Две награды с разными названиями дадут
разные входы.

**Условия подписок.** Twitch строг к составу `condition`: лишнее поле отклоняет
подписку так же, как недостающее. У событий в `TWITCH_EVENTS` есть поле `extra`:

| `extra` | Что добавляется | Зачем |
|---|---|---|
| `user` | `user_id` | чат: чей чат читаем |
| `moderator` | `moderator_user_id` | фоллов версии 2: кто получает события |
| `from` | `from_broadcaster_user_id` | рейд: с какого канала ждём (идёт на наш канал) |

Все три берутся из `GET /helix/users` без параметров — это владелец токена, то есть вы.

**Ответ 400 `SubscriptionCondition.broadcaster_user_id`.** Это значит, что в условии
оказался пустой id канала: Twitch получил `broadcaster_user_id: ""` и отклонил
подписку. Причины по частоте:

1. вход выполнен **другим аккаунтом** (не тем, чей канал в настройках) — кнопка
   «Проверить» теперь прямо пишет: «канал найден, но вход выполнен как …»;
2. канал записан не логином (адрес `twitch.tv/имя`, `@имя`, кириллица, пробелы) —
   нужен именно логин латиницей;
3. запущена старая сборка без проверки id.

Теперь приложение проверяет id до запроса и пишет понятной строкой, а в текст ошибки
подставляется само условие — по нему видно, какое поле пустое.

**Как это устроено внутри.** `src/modules/twitch.ts`: канал открывает
`wss://eventsub.wss.twitch.tv/ws`, ждёт `session_welcome` (в нём `session_id`),
создаёт подписки `POST /helix/eventsub/subscriptions`, дальше отдаёт уведомления
как есть — их разбирает таблица. На `session_reconnect` переезжает на новый адрес,
на обрыв переподключается с задержкой 1 → 2 → 4 → 8 с (до 30 с), на `revocation`
показывает причину. Запросы идут через `source_request` в Rust: из окна их заблокировал
бы CORS.

Чат в модуль не входит: в ядро уходят только числа, а сообщения чата — текст.

### 9.6 Пульсометр: готовый мост без железа

Пульсомеры говорят на BLE, USB-serial или своём протоколе, а приложение понимает
WebSocket, HTTP, SSE и OSC. Мост переводит одно в другое — и он уже в репозитории:

```bat
pulse-bridge.bat                 :: Windows, двойной клик
./pulse-bridge.sh                :: Linux/macOS
pulse-bridge.bat --hr 90         :: ровные 90 ударов вместо тренажёра
pulse-bridge.bat --port 18000    :: другой порт
```

Мост (`scripts/pulse-bridge.mjs`) не требует `npm install`: сервер WebSocket собран
на голом `node:http`. Отдаёт два адреса сразу:

| Адрес | Для чего |
|---|---|
| `ws://127.0.0.1:17801/inputs` | поток `{"heart_rate":72,"beat":0|1}` |
| `http://127.0.0.1:17801/state` | тот же снимок одним ответом — для транспорта `http` |

В палитре есть готовый модуль **Пульсометр**: он уже смотрит на этот адрес, входы
`hr` (0…220) и `beat` (флаг с удержанием 200 мс). Без железа всё видно сразу:
подключите мост, добавьте модуль — `hr` гуляет, `beat` моргает.

Чтобы отдать свой пульс, напишите такой же маленький мост: единственное требование —
JSON с числами. Свой протокол удобнее переводить в OSC (VRChat, TouchDesigner и
многие HR-приложения уже умеют его отдавать): транспорт `osc` слушает UDP, а адрес
виден в таблице как `$["/avatar/parameters/HR"]`.

### 9.7 Отладка: журнал и проверка

Когда мост молчит, вопрос всегда один: «кто виноват — адрес, мост или моя таблица?».
Карточка внешнего источника отвечает на него без консоли.

**Кнопка «Проверить»** рядом со статусом:

| Транспорт | Что делает проверка |
|---|---|
| `ws` | открывает отдельный сокет и сразу закрывает; ждёт не дольше 3 с |
| `http`, `sse` | GET через Rust с таймаутом 5 с: код ответа, размер и начало тела |
| `osc` | пробует занять UDP-порт: свободен или занят (и кем-то уже слушается) |
| `twitch` | Client ID → канал → токен → `GET /helix/users`: находит канал и показывает его ID |

Проверка ничего не меняет в работе источника: соединение открывается отдельное, а
настройки не перезапускаются.

**Журнал** (раскрывается под статусом) хранит последние 20 строк на источник:

```
12:03:41  пакет    hr=72, beat=1
12:03:39  пакет    hr=72
12:03:35  warn     не JSON: <html><body>404 not found</body></html>
12:03:30  warn     поля не найдены: $.heart_rate
12:03:20  error    соединение закрыто, переподключаюсь
```

Три вида строк отвечают на три разных вопроса:

- **пакет** — данные дошли и правило сработало: видно, какие входы получили числа;
- **warn** — данные дошли, но не разобрались: «не JSON» (адрес отдал HTML или это не
  тот транспорт) или «поля не найдены» (в таблице указан путь, которого в сообщении
  нет — рядом печатается сам путь);
- **error** — сломалось соединение или сам канал: те же тексты, что в статусе.

Повторы подряд в пределах секунды схлопываются, поэтому поток 120 пакетов в секунду
не заливает список: журнал показывает изменения, а не поток. Число пакетов в статусе
при этом растёт — по нему видно, что канал живой.

### 9.8 Чего ещё нет

- **Serial / Bluetooth** (пульсометры, Arduino) — общий путь тот же (Rust), но
  конкретного транспорта пока нет.
- **Тексты** — канал уже есть (см. 9.9): строка идёт в текстовый объект, а не в формулы.
- **Заголовки запроса** для `http`/`sse` — пока только адрес. Запрос с токеном уже
  умеет `source_request` (им пользуется Twitch), но в таблицу источника заголовки не
  выведены: секреты не должны попадать в пресет.

Порядок работ по этому блоку: **каркас → Rust-транспорт → Twitch → пульс/HTTP-мосты** —
все четыре шага сделаны, чат с командами и наградами тоже. Дальше — Serial/Bluetooth.
Подробности — [`BACKLOG.md`](BACKLOG.md).

### 9.9 Текст модуля в текстовый объект

Числа идут в формулы, строки — отдельным каналом: `text` в настройках источника.

```json
"text": {
  "path": "$.payload.event.message.text",
  "authorPath": "$.payload.event.chatter_user_name"
}
```

Как это работает:

1. Каждый подходящий пакет дописывает строку в журнал модуля (`TEXT_LIMIT = 12`):
   `{ at, text, author }`. Старые строки вытесняются.
2. Редактор держит «последнее сообщение каждого модуля» и подставляет его в шаблон
   текстового объекта.
3. Готовая строка кладётся в кадр (`frame.texts`), поэтому оверлею не нужны ни модули,
   ни сеть: он рисует то, что прислал редактор.

Подстановки в шаблоне текстового объекта: `{модуль.message}` и `{модуль.user}`
(`text`/`author` — те же поля). Например, для экземпляра модуля с именем `twitch`:

```text
{twitch.chat.user}: {twitch.chat.message}
```

Середина пути ни на что не влияет — `twitch.chat.message` читается как «модуль `twitch`,
поле `message`». Если сообщений ещё не было, подстановка даёт пустую строку.

Модулю не нужно ничего знать про текст: достаточно объявить `text` в `defaults.source`.
Свои строки из скрипта задаёт команда `text("…")` — она заменяет шаблон целиком, а
`text("")` возвращает шаблон. Подробности команд — в [`DESIGN.md`](DESIGN.md) §8.1.
