## 1. Модуль интеграции Twitch

Статус: **основа сделана** (`b6d9895` + этот заход). Что уже работает: вход по коду
(device flow), токен в профиле окна, подписки EventSub и поток событий, события
«награда за баллы», bits, фоллов, подписка, подаренные подписки, рейд, Hype Train —
каждое со своим входом. Модуль — это `kind: "external"` с транспортом `twitch`
(шаблон `public/modules/twitch.json`), настройка — обычная таблица отображения.

Добавлено следом: **чат** (счётчик `chat`, текст в «Входах», в формулы не идёт),
**команды** (`!dance` → `cmd_dance`, регистр не важен, кириллица транслитерируется),
**награды по именам** (`redeem_smena_avatara` вместо одной стоимости).

Что осталось из задуманного: «догон» пропущенных сообщений по `message_id` (сейчас
пропущенное во время обрыва просто теряется) и показ текста награды (`user_input`)
в панели.

### Что должно работать

| Событие канала | Что даёт модуль | Как используется в скрипте |
|---|---|---|
| Награда за баллы канала (redemption) | вход-импульс на каждую награду + текст ввода | `event reward_x() { twitch.redeem_<награда>.up }` |
| Сообщение в чате | вход `chat` (счётчик) и текст сообщения | `event message() { twitch.chat.change }` |
| Команда `!команда` | флаг на каждую настроенную команду | `event dance() { twitch.command_dance.up }` |
| Bits / cheered | вход `bits` (сумма за сессию) и импульс | `y = smooth(twitch.bits > 0, 120)` |
| Подписка, рейд, «подарок» | входы-импульсы `sub`, `gift`, `raid` | `rotation = spring(twitch.raid * 20, 4, 0.3)` |

Все входы — обычные числа 0/1 или счётчики: движок и DSL менять не нужно. Импульс держится
один кадр (или настраиваемое время удержания), поэтому `down`/`up`/`hold` работают как у мыши.

### Как это устроено

- Отдельный `kind: "twitch"` в `public/modules/twitch.json` + реализация в `src/modules/twitch.ts`.
  Список наград и команд — в настройках экземпляра (как виземы, клавиши и состояния enum:
  «список живёт в экземпляре, а не в шаблоне»).
- Подключение — **EventSub WebSocket** (не опрос API): подписки на
  `channel.channel_points_custom_reward_redemption.add`, `channel.chat.message`,
  `channel.cheer`, `channel.subscribe`, `channel.raid`; переподключение с бэкоффом и
  «догон» пропущенного по `message_id`.
- Авторизация — устройство-код или вставка токена в диалоге модуля. **Токен не пишется в
  пресет и не попадает в репозиторий**: только в профиль WebView (см. `docs/DATA.md`),
  отзыв — кнопкой «Отключить». Client ID — в настройках приложения.
- Сетевые ошибки не ломают сцену: модуль показывает состояние (подключён / ждёт / нет сети)
  в карточке, входы при этом просто нулевые.

### Ограничения и договорённости

- Никаких секретов в JSON пресета и в репозитории; в шаблоне модуля — только поля.
- События идут через тот же движок входов: один поток событий на приложение, несколько
  модулей не дублируют подписки (релей внутри приложения, как у оверлея).
- Тексты (сообщение, имя зрителя, текст награды) — только для показа в панели и в
  «значениях кадра»; в формулы они не попадают (DSL числовой).
- Стоп-кадр не рвёт соединение: после «Стоп» события копятся, но персонаж не двигается.
- Порядок работ: (1) ~~каркас модуля и входы-импульсы без сети~~ — **сделан**:
  `kind: "external"` (`src/modules/external.ts`), хост соединений (`src/modules/sources.ts`),
  редактор источника в карточке модуля, `holdMs`-импульсы и статус соединения;
  (2) ~~Rust-транспорт~~ — **сделан**: `src-tauri/src/sources.rs`, команды
  `source_start`/`source_stop`/`source_stop_all` и событие `yappy://source`;
  HTTP-опрос, SSE-поток и OSC по UDP (сообщения и бандлы) без CORS и без привязки
  к фокусу окна, (3) EventSub + OAuth, (4) награды и команды, (5) панель состояния и логи.

### Что решить перед началом

- Публичный Client ID приложения или «свой client id в настройках» (у Twitch нет
  публичных ключей без регистрации приложения).
- Нужны ли «действия» из награды (звук, смена аватара) — сейчас просили только события.
- Хранить ли историю событий (последние 20) для отладки.

## 1.1 Медиа и текстовые объекты

Статус: **сделано**. Медиа — отдельный объект сцены (`kind: "media"`) с параметрами спрайта и
данными воспроизведения; команды `play/resume/pause/stop/seek/rate/volume` живут в блоках
событий, а параметры `play/speed/volume` — обычные формулы. Правило повтора — поле инспектора
(`restart`/`fade`/`overlay`/`finish`).

Текст — объект `kind: "text"` с шаблоном и подстановками `{модуль.message}` / `{модуль.user}`;
готовая строка уходит в кадр (`frame.texts`), поэтому оверлей рисует её без доступа к модулям.

Что осталось на потом:

- **текст награды** (`user_input`) и других полей Twitch — нужен отдельный путь в таблице
  источника, сейчас текст берётся из `text.path`;
- **перемотка анимированных картинок** (GIF/WEBP) — сейчас это обычная картинка, у неё нет
  позиции воспроизведения;
- **потоковые видео-форматы** (HLS/m3u8) — файл должен быть локальным;
- **несколько дорожек одновременно** для видео: сейчас у видео одна дорожка, `overlay`
  фактически означает «начать заново».

## 1.3 Файлы объектов вне пресета

Статус: **сделано**. Байты картинок, GIF, видео и звука лежат в IndexedDB webview
(`yappytuberplus.assets`), в пресете и в автосохранении — ссылка `asset:<id>`
(`src/engine/assets.ts`). При записи пресета ссылки встраиваются обратно в data URL
(файл остаётся самодостаточным), при открытии — распаковываются в хранилище. Оверлей и
окно захвата берут файлы из того же хранилища, а страница источника браузера в OBS
(другой origin) запрашивает их по протоколу `asset-request` → `asset`.

Доведено позже: **ручная уборка** (кнопка «Файлы объектов» в верхней панели: список,
объём, состояние, «Убрать неиспользуемые» с учётом истории отмены) и **дедупликация**
(отпечаток содержимого: SHA-256 до 32 МБ, дальше размер + тип + имя). Паспорта файлов
лежат в отдельном хранилище `meta`, поэтому список не вычитывает байты. Сохранение,
у которого файл не нашёлся, честно сообщает, какие объекты остались без файла.

Доведено ещё раз: **файлы рядом с пресетом на диске**. При сохранении рядом с
`<имя>.yappy.json` появляется папка `<имя>.assets` (`index.json` плюс `<id>.<расширение>`),
в самом JSON остаются короткие ссылки `asset:<id>`. Открытие читает файлы лениво, по одному
(`preset_read_asset`), и сразу кладёт их в IndexedDB, поэтому диск не дёргается на каждой
отрисовке, а видео на сотни мегабайт не грузится целиком. Путь последнего файла запоминается,
так что автосохранение после перезапуска тоже видит папку. Экспорт JSON встраивает файлы
обратно: один самодостаточный файл.

Что осталось на будущее:

- **ленивое чтение больших паспортов**: при первом запуске новой версии хранилища отпечатки
  старых файлов считаются один раз и могут занять пару секунд на очень крупном видео;
- **выбор папки для файлов**: сейчас папка всегда рядом с пресетом; отдельная настройка
  («держать файлы в одном месте для всех пресетов») пока не нужна.

## 1.2 Идеи из LandiTube (разобрано, к реализации не принято)

LandiTube — бесплатный «продвинутый PNGTuber-движок» на SAMMI (OBS-автоматизация).
Своей сцены он не рисует: он генерирует OBS-источники и переключает их. Смотрели
[страницу расширения](https://landie.land/shop/sammi-extensions/landitube/) и
[документацию](https://landie.land/shop/sammi-extensions/landitube/documentation).
Что там есть и что из этого нам подходит:

| Идея LandiTube | Как устроено у них | Что делать нам |
|---|---|---|
| **Эмоции и позы** (idle/talk/yell/blink), бесконечные случайные варианты | папки: модель → эмоция → поза; файл = поза | Частично есть: группы + `visible` + события. Стоит добавить «пресет поведения» на группу и **случайный выбор варианта** (`random` уже есть; нужен выбор одного из N детей). |
| **Переходы (transitions)**, глобальные и динамические, intro/outro | отдельный GIF/PNG, имя с `_in`/`_out`, случайный выбор из нескольких | Ложится на медиа-объекты: `on <эмоция>.change { play("переход_в_злость") }`. Не хватает только «эмоций» как именованных состояний — их даёт `manual` в режиме enum. |
| **Attitudes** — jam/sway/bounce/shake/prance с иерархией «поза → эмоция → модель» и пресетами | `.fenc` (key=value) рядом с папкой, пресеты в бридже | Прямо просится в **«Поведение»**: встроенные пресеты движения (наши синус/шум/пружина) + свои, с наследованием по структуре. Кандидат на следующий шаг. |
| **Слои OBS поверх частей модели** | OBS-сцена-клон на каждую позу, трансформации вручную | У нас сцена своя: внешние OBS-источники как слои — отдельный мост (OBS WebSocket). Большая тема, пока не берём. |
| **Dynamic lighting** (backlight/rimlight от захвата игры) | анализ сцены захвата в OBS | Требует захвата экрана и шейдеров. Идея красивая, но не для PNGTuber-минимума. |
| **`.fenc`-конфиги и drag&drop папки модели с автосборкой** | файлы + key=value рядом | Импорт **папки**: разложить `*.png/gif` по именам (`talk`, `blink`, `_in`) в объекты и пресет поведения. Может стать «импортом модели». |
| **Публичный API наружу**: триггеры `talking/blinking/emotion changed` + команды `change emotion`, `pause/resume` | SAMMI-команды и триггеры | У нас входы идут внутрь; наружу событий нет. Идея: модуль «События сцены» (исходящий WS/HTTP) — talking, blink, emotion, награда. Требует исходящего канала из вебвью (Rust уже умеет сети). |
| Пауза движка, «squish», только голосовой триггер | команды/настройки | Уже есть: пауза/стоп, `squash`, микрофон с порогом. |

Вывод: ближайшие к нам пункты — **пресеты движения (attitudes)**, **переходы через
медиа** и **импорт папки модели**; слои OBS, подсветка и исходящий API — отдельные
проекты. Ничего из этого не начинаем без отдельного решения: текущий шаг — медиа и
текст.
