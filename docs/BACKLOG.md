## 1. Модуль интеграции Twitch

Статус: **записано, не реализовано.** Нужен стримеру, который ведёт персонажа событиями
канала: баллы, сообщения, команды, подписки.

### Что должно работать

| Событие канала | Что даёт модуль | Как используется в скрипте |
|---|---|---|
| Награда за баллы канала (redemption) | вход-импульс на каждую награду + текст ввода | `on twitch.redeem_<награда>.down { … }` |
| Сообщение в чате | вход `chat` (счётчик) и текст сообщения | `on twitch.chat.change { … }` |
| Команда `!команда` | флаг на каждую настроенную команду | `on twitch.command_dance.down { … }` |
| Bits / cheered | вход `bits` (сумма за сессию) и импульс | `y = smooth(twitch.bits > 0, 120)` |
| Подписка, рейд, «подарок» | входы-импульсы `sub`, `gift`, `raid` | `rotation = spring(twitch.raid * 20, 4, 0.3)` |

Все входы — обычные числа 0/1 или счётчики: движок и DSL менять не нужно. Импульс держится
один кадр (или настраиваемое время удержания), поэтому `down`/`up`/`hold` работают как у мыши.

### Как это устроено

- Отдельный `kind: "twitch"` в `public/modules/twitch.json` + реализация в `src/modules/twitch.ts`.
  Список наград и команд — в настройках экземпляра (как виземы, клавиши и состояния enum:
  «список живёт в экземпляре, а не в шаблоне»).
- Подключение — **EventSub WebSocket** (не опрос API): подписки на
  `channel.channel_points_custom_reward_redemption.add`, `channel.chat.message`,
  `channel.cheer`, `channel.subscribe`, `channel.raid`; переподключение с бэкоффом и
  «догон» пропущенного по `message_id`.
- Авторизация — устройство-код или вставка токена в диалоге модуля. **Токен не пишется в
  пресет и не попадает в репозиторий**: только в профиль WebView (см. `docs/DATA.md`),
  отзыв — кнопкой «Отключить». Client ID — в настройках приложения.
- Сетевые ошибки не ломают сцену: модуль показывает состояние (подключён / ждёт / нет сети)
  в карточке, входы при этом просто нулевые.

### Ограничения и договорённости

- Никаких секретов в JSON пресета и в репозитории; в шаблоне модуля — только поля.
- События идут через тот же движок входов: один поток событий на приложение, несколько
  модулей не дублируют подписки (релей внутри приложения, как у оверлея).
- Тексты (сообщение, имя зрителя, текст награды) — только для показа в панели и в
  «значениях кадра»; в формулы они не попадают (DSL числовой).
- Стоп-кадр не рвёт соединение: после «Стоп» события копятся, но персонаж не двигается.
- Порядок работ: (1) ~~каркас модуля и входы-импульсы без сети~~ — **сделан**:
  `kind: "external"` (`src/modules/external.ts`), хост соединений (`src/modules/sources.ts`),
  редактор источника в карточке модуля, `holdMs`-импульсы и статус соединения;
  (2) Rust-транспорт (`http`/`sse`/`osc` — без CORS и без привязки к фокусу окна),
  (3) EventSub + OAuth, (4) награды и команды, (5) панель состояния и логи.

### Что решить перед началом

- Публичный Client ID приложения или «свой client id в настройках» (у Twitch нет
  публичных ключей без регистрации приложения).
- Нужны ли «действия» из награды (звук, смена аватара) — сейчас просили только события.
- Хранить ли историю событий (последние 20) для отладки.
