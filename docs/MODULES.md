# Модули и входы

Все входы рига поставляют **модули**. Зашитых имён вроде `speak` или `viseme_a` больше
нет: у каждого экземпляра модуля есть имя, а его входы в скрипте выглядят как
`<имя>.<вход>` — например `mic.talking` или `mic_left.loudness`.

```
mic.talking          — флаг разговора экземпляра «mic»
mic_left.db          — децибелы левого микрофона
viseme.a             — ручная визема A
manual.blink         — ручное моргание
signal.<имя>         — свободный канал для плагинов
```

## Экземпляры, а не типы

Один и тот же тип можно добавить сколько угодно раз. Каждый экземпляр живёт со своим
источником и настройками, поэтому два `Loudness` спокойно слушают два разных микрофона:

| Имя экземпляра | Тип | Источник | Что даёт |
|---|---|---|---|
| `mic_left` | Loudness | микрофон «USB Audio» | `mic_left.speak`, `mic_left.loudness`, `mic_left.db`, `mic_left.talking` |
| `mic_right` | Loudness | микрофон «Headset» | `mic_right.*` |
| `viseme` | Viseme | ползунки | `viseme.a` … `viseme.u` |
| `manual` | Manual | кнопка | `manual.blink` |

Правила имени: латиница, цифры и `_`, первый символ — буква или `_`. Имя — часть
выражения, поэтому `Микрофон` превратится в `module`, а `Mic Left` — в `mic_left`.
Переименование меняет имена входов: скрипты, где было `mic.talking`, придётся поправить
на новое имя (редактор подсказывает актуальные входы в автодополнении).

## Встроенные модули

| Тип | Входы | Источник | Замечания |
|---|---|---|---|
| **Loudness** | `speak` (сглаженный уровень), `loudness` (пик), `db`, `talking` (0/1) | микрофон или ползунки | усиление 0.1…8, порог речи −80…0 дБ, шумоподавление |
| **Viseme** | `a`, `e`, `i`, `o`, `u` | ползунки | заглушка вместо настоящего липсинка |
| **Manual** | `blink` | кнопка «моргнуть» и переключатель 0/1 | кнопка ставит 1 на 160 мс |

`autoblink(min_ms, max_ms)` остаётся функцией ядра: это автоматика, а не вход. В демо-риге
моргание — `max(autoblink(...), manual.blink)`.

## Вкладки

- **Модули** — список экземпляров: включение, имя, тип, источник, устройство, усиление,
  порог, шумоподавление, дублировать и удалить. Кнопки «Добавить» создают ещё один
  экземпляр любого типа; имя подбирается свободное (`mic`, `mic_2`, …).
- **Входы** — живые значения по каждому включённому модулю с полными именами. Живые
  уровни показываются индикаторами, ручные — ползунками.

Выключенный модуль не попадает в словарь входов вообще: выражения с его именами дают
нули и диагностику «неизвестное имя».

## Микрофоны

- Разрешение спрашивается один раз кнопкой «Включить микрофоны» (в приложении — системный
  запрос WebView2 на `tauri.localhost`, это нормально).
- `AudioContext` создаётся и пробуждается из обработчика клика. Иначе браузер и WebView2
  оставляют его в `suspended`, анализатор возвращает нули и «звука нет» без ошибок.
- Устройство выбирается отдельно для каждого экземпляра. Два модуля с одним устройством
  делят поток — микрофон не открывается дважды.
- По умолчанию обработка браузера выключена (сырой сигнал): на части драйверов
  эхоподавление и шумоподавление глушат вход. Галочка «Шумоподавление» включает её обратно.
- Если речь не ловится, уменьшите порог (например, −55 дБ) или поднимите усиление.

## Хранение и миграция

Модули хранятся в пресете (`modules`), рядом с объектами и глобальными переменными:
вместе с настройками устройств, усиления и порогов. Входы в ядро передаются плоским
словарём `values` (`{"mic.talking": 1, …}`) плюс `signals` для канала `signal.*`.

Старые пресеты открываются без диалога «пропали входы»: при первом открытии имена
переписываются автоматически (`talking` → `mic.talking`, `viseme_a` → `viseme.a`,
`signal.blink` → `manual.blink`), а набор модулей дополняется нужными.

Если при открытии пресета набор модулей отличается от текущего, показывается диалог:

- **Применить** — входы и настройки берутся из пресета (текущий список заменяется целиком);
- **Оставить как есть** — остаётся текущий набор модулей сессии;
- **Отключить все** — пресет открывается без модулей: все входы дают нули, риг рисуется
  по базовой позе и глобальным переменным.

## Сборка ядра

Имена входов резолвит Rust: `values` — произвольный словарь, а `имя.поле` распознаётся как
вход, если такого ключа нет среди обычных полей. После правок в `crates/rig-core`
пересоберите ядро:

```bash
npm run build:wasm        # → public/rig_core.wasm
```

Нативная сборка (`npm run tauri build`) компилирует Rust сама, отдельный шаг не нужен.
