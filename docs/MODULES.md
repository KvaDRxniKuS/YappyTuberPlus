# Модули и входы

Все входы рига поставляют **модули**. Зашитых имён вроде `speak` или `viseme_a` нет:
у каждого экземпляра модуля есть имя, а его входы в скрипте выглядят как
`<имя>.<вход>` — например `mic.talking` или `mic_left.loudness`.

```
mic.talking          — флаг разговора экземпляра «mic»
mic_left.db          — децибелы левого микрофона
auto.blink           — моргание по таймеру
manual.value         — ручной вход
viseme.a             — похожесть звука на «а» (0…1)
keyboard.space       — 1, пока нажата клавиша (модуль Keyboard)
jump.hold            — сколько секунд держится клавиша (модуль Key)
cursor.x             — курсор мыши 0…1 по сцене (модуль Mouse)
viseme.o_umlaut      — своя визема «ö»: имя латиницей, подпись любая
signal.<имя>         — свободный канал для плагинов
```

## Экземпляры, а не типы

Один и тот же шаблон можно добавить сколько угодно раз. Каждый экземпляр живёт со своим
источником и настройками, поэтому два `Loudness` спокойно слушают два разных микрофона:

| Имя экземпляра | Шаблон | Источник | Что даёт |
|---|---|---|---|
| `mic_left` | Loudness | микрофон «USB Audio» | `mic_left.speak`, `mic_left.loudness`, `mic_left.db`, `mic_left.talking` |
| `mic_right` | Loudness | микрофон «Headset» | `mic_right.*` |
| `auto` | AutoBlink | таймер | `auto.blink` |
| `manual` | Manual | ползунок | `manual.value` |
| `viseme` | Viseme | микрофон или ползунок | `viseme.a`, `viseme.o_umlaut` … |
| `board` | Keyboard | клавиши из настроек | `board.space`, `board.q` |
| `jump` | Key | одна клавиша | `jump.down`, `jump.hold`, `jump.hits` |
| `cursor` | Mouse | курсор и кнопки | `cursor.x`, `cursor.dx`, `cursor.left` |

Правила имени: латиница, цифры и `_`, первый символ — буква или `_`. Имя — часть
выражения, поэтому `Микрофон` превратится в `module`, а `Mic Left` — в `mic_left`.
Переименование меняет имена входов: скрипты, где было `mic.talking`, придётся поправить
(редактор подсказывает актуальные входы в автодополнении).

## Библиотека шаблонов: папка `modules`

Шаблон модуля — JSON-файл в `public/modules/`. Список файлов перечислен в
`public/modules/index.json`:

```json
{ "modules": ["loudness", "autoblink", "manual", "viseme"] }
```

Панель модулей читает эту папку при старте (и по кнопке «Добавить модуль» показывает
её содержимое). Поэтому:

- новый шаблон достаточно положить в папку и дописать его id в `index.json` —
  в dev-режиме он появится после перезагрузки страницы, без пересборки;
- в собранном приложении папка лежит рядом (`dist/modules`), файлы можно править;
- на будущее: установка шаблонов из репозитория — тот же формат.

Формат шаблона:

```json
{
  "id": "autoblink",
  "title": "AutoBlink",
  "description": "Моргание по таймеру.",
  "kind": "autoblink",
  "audio": false,
  "inputs": [{ "name": "blink", "label": "Моргание", "kind": "level", "min": 0, "max": 1 }],
  "fields": [
    { "key": "period", "label": "Интервал", "type": "number",
      "min": 500, "max": 20000, "step": 100, "default": 4200, "suffix": "мс" }
  ],
  "defaults": { "period": 4200, "hold": 140, "jitter": 35, "min": 0, "max": 1 }
}
```

- `inputs[].kind` — `level` (0…1), `db` (по умолчанию −60) или `flag` (0/1);
- `fields[]` — настройки экземпляра: `number`, `flag`, `select`, `device`
  (у `device` список берётся из `navigator.mediaDevices`);
- `showWhen` у поля — показывать только при определённых значениях других полей;
- `defaults` — стартовые значения (перекрывают `default` полей).

**Важно:** JSON описывает входы и настройки, а поведение берётся из `kind` и реализовано
в коде (`loudness`, `manual`, `autoblink`, `viseme`). Своя математика в шаблоне —
следующий шаг, сейчас её нет.

### Цвет: палитра, которая идёт по времени

Модуль **«Цвет»** даёт не одно число, а каналы. Канал — это палитра и правило, как по ней
двигаться:

| Режим | Что делает |
|---|---|
| Статичный | один цвет, первый из палитры |
| Дыхание | плавно между первыми двумя цветами и обратно |
| Круг | по всей палитре по кругу, переходы плавные |
| Последовательность | строго по очереди: каждый цвет стоит своё время (`hold`) |
| Волна | оттенок идёт по кругу, насыщенность берётся из палитры |
| Случайный | новый цвет из палитры через равные промежутки |
| Реакция | цвет стоит, яркость ведёт вход другого модуля (речь, мышь, что угодно) |

Скорость — это шаг палитры (100 % ≈ две секунды на переход), сдвиг разводит два канала по
времени, чтобы они не мигали в такт, сглаживание — инерция перехода (0 % мгновенно, 100 %
догоняет примерно за полторы секунды).

```text
color_1.c1_level        # яркость канала 0…1 — обычная переменная
color_1.c1_r            # компоненты цвета, если нужна формула
light.level = color_1.c1_level
```

Куда подставлять: вкладка **«Поведение»** → секция «Цвет». Строки есть только у тех цветов,
которые у объекта действительно есть: заливка и обводка фигуры, начало и край света, цвет и
обводка текста, свечение материала. В строке выбирается «свой цвет» или «модуль → канал», а
галка «α» решает, брать ли прозрачность из канала (без неё остаётся своя).

Если канал переименовали или модуль удалили, строка покажет предупреждение, а объект
останется со своим цветом — сцена не погаснет.

### Свет из экрана: цвет берётся с картинки

Модуль **«Свет из экрана»** отвечает на вопрос «какого цвета вон тот участок картинки» и отдаёт
ответ числами. Дальше им пользуется всё, что умеет брать цвет: свет, фигура, текст, свечение
материала.

| Источник | Откуда пиксели | Когда годится |
|---|---|---|
| Своя сцена | холст редактора, уменьшенная копия без сетки и выделения | всегда: свет подстраивается под собственную сцену |
| Источник OBS | `GetSourceScreenshot` по obs-websocket | чужое окно, игра, браузер — всё, что OBS и так захватывает |

Точка — это квадрат: центр `слева`/`сверху` в долях кадра, размер участка в долях меньшей
стороны, и **размытие** — сколько пикселей уменьшенной копии (128 по длинной стороне) добавить по краям. Размытие не «ищет цвет», оно
расширяет участок: чем оно больше, тем ровнее цвет на резких границах. Поверх этого работает
**сглаживание** во времени (0…100 %), иначе цвет дёргался бы на каждом движении.

Если у точки включено **«Следовать за источником»**, точка задаётся в долях самого элемента, а
её место на кадре считается по трансформации из OBS: `positionX/Y` и `width/height` элемента
делятся на `baseWidth/Height` сцены. Двинули окно в OBS — точка поехала вместе с ним.

**OBS.** Нужен obs-websocket v5 (OBS 28+), по умолчанию `127.0.0.1:4455`. Пароль вводится в
настройках приложения и в пресет не попадает: пресет можно выкладывать. Замеров в секунду —
1…30 (по умолчанию 10); один скриншот обслуживает все точки, которые смотрят на этот источник,
поэтому несколько точек почти ничего не стоят.

```text
ambient_1.spot_1_level     # яркость участка: max(r, g, b) с учётом прозрачности
ambient_1.spot_1_r         # компоненты, если нужна формула
```

Нет OBS — модуль честно пишет об этом в карточке, а значения замирают на последнем цвете:
свет не гаснет и не мигает, пока соединение восстанавливается.

### Manual: режим «Состояния» (enum)

Третий режим ручного модуля — для режимов персонажа: покой, идёт, бежит, поёт. Состояние —
это пара «подпись» и «имя для скрипта», список живёт в настройках экземпляра.

```text
manual.value == walk            # номер выбранного состояния (walk = 1)
manual.value == 0               # то же число напрямую
is(manual.value, walk, run)     # 1, если выбрано любое из двух
manual.walk == 1                # флаг: 1, пока выбрано это состояние
event walk() { manual.walk.up }      # вход в состояние
on walk { … }
event idle() { manual.idle.down }    # выход из состояния
on idle { … }
```

- **Номер состояния — это значение `manual.value`**: 0, 1, 2… в порядке списка. Порядок строк
  в списке и есть порядок номеров, номера видны в редакторе состояний.
- **Имена состояний доступны в скрипте как константы**: `walk`, `run`, а если имя состояния
  есть у двух модулей — ещё и полное `<модуль>_<состояние>` (`mode_walk`). Константу нельзя
  присвоить, она только читается.
- **Флаги** `<модуль>.<состояние>` дают точные переходы: `.up` — вход в состояние, `.down` —
  выход из него. По номеру такое не выразить: «стало walk» и «стало числом 1» — разные вещи.
- Панель «Входы» показывает список состояний выпадающим списком, ниже — флаги; клик по флагу
  выбирает это состояние. В скрипте всё это остаётся обычными числами 0/1.

### `speak` и `loudness` — это не одно и то же

| Вход | Что измеряется | Шкала | Сглаживание |
|---|---|---|---|
| `loudness` | **пик** амплитуды за кадр (~21 мс) | линейная амплитуда × усиление, обрезка в 0…1 | нет, реагирует мгновенно |
| `db` | RMS за кадр | дБ, −80…0 | нет |
| `speak` | RMS за кадр | −52…−18 дБ → 0…1 | есть: **атака** и **спад** |
| `talking` | RMS за кадр | `db > порог речи` | нет (флаг 0/1) |

- `loudness` — «насколько громко прямо сейчас». Пик выше RMS в 3–4 раза, поэтому при
  обычной речи он почти всегда упирается в 1: удобно для резких реакций, плохо для рта.
- `speak` — «насколько открыт рот». Энергия в дБ, пересчитанная в 0…1, плюс сглаживание:
  рот открывается быстро (атака), а закрывается медленно (спад), поэтому не дёргается на
  каждом слоге.
- `db` — сырые децибелы для формул, `talking` — готовый флаг «человек говорит».

Сглаживание задаётся **в миллисекундах**, а не коэффициентами: «Атака» (по умолчанию
70 мс) и «Спад» (220 мс). `0 мс` — мгновенная реакция, `0` в спаде невозможен по смыслу,
но допускается как «закрывать рот сразу». Шаг таймера измеряется по факту, поэтому
скорость не зависит от загрузки машины (в тестах проверяется, что два шага по 35 мс дают
тот же результат, что один шаг 70 мс).

У `Loudness` режим «Ползунок» — отладочный: те же входы ставятся вручную, без звука.
У `AutoBlink` и `Manual` микрофона нет вообще: они всегда «ручные» по источнику.

`autoblink(min_ms, max_ms)` остаётся ещё и функцией ядра для тех, кто пишет скрипты
вручную, но в модели рига моргание приходит из модуля: демо использует `auto.blink`.

## Виземы: похожесть звука, а не ползунки

`Viseme` — единственный шаблон, у которого **входы задаёт экземпляр**, а не JSON: список
звуков живёт в настройках модуля (`config.visemes`) и сохраняется вместе с пресетом.
Поэтому у двух визем-модулей могут быть разные наборы звуков.

Как считается значение входа:

1. АЧХ (FFT 2048) сводится к **32 лог-полосам 80 Гц–8 кГц** (среднее по полосе, чтобы
   верхние полосы с десятками бинов не забирали весь вес).
2. Полосы переводятся в **децибелы**, из них вычитается средний уровень, и только потом
   вектор нормируется по длине. Так снимаются громкость микрофона и общий наклон АЧХ —
   иначе все гласные похожи друг на друга на 0.8–0.9, ведь их объединяет общий спад.
3. Полосы **250–3000 Гц** (форманты, по которым и различаются гласные) весят больше,
   края спектра — меньше (0.3).
4. Полосы **взвешиваются по собственным калибровкам** (whitening): разброс каждой
   полосы считается по всем записанным вариантам всех визем модуля. Где записанные
   звуки отличаются — полоса весит много, где у всех одинаково (наклон АЧХ, гул,
   шум) — ноль. Это не догадка про «правильные» форманты, а данные из ваших записей,
   поэтому метод подстраивается под микрофон и дикцию.
5. Похожесть = `cos²(взвешенный текущий, взвешенный эталон)`, затем **контраст**: значение возводится в степень
   `contrast` (по умолчанию 3×). Чем больше контраст, тем резче выделяется самый близкий
   звук; чем меньше — тем ближе виземы друг к другу.
6. Результат умножается на гейт громкости: он плавно открывается у порога и закрыт в
   тишине, поэтому беззвучный микрофон даёт ровно нули, а не «похоже на всё».

**Почему I/U и A/O/E сбивались в группы.** При сравнении «как есть» косинус меряет и
форму, и общий спад спектра: у всех гласных он одинаковый, поэтому похожесть получалась
высокой у всех сразу, а различались только крупные группы. Центрирование в дБ и веса
полос убирают общий спад, а контраст разводит победителя и остальных.

Калибровка (кнопка-микрофончик в строке значения или плюсик в карточке модуля):

- запись **фиксированные 3 секунды**, кнопки «Стоп» нет;
- во время записи в строке рисуется живой спектр и полоска прогресса;
- сохраняется средний спектр, кадры тише 45 % от самого громкого отбрасываются (паузы
  между слогами не разбавляют эталон);
- пишется в пресет, рядом с модулем. Пока эталона нет, визема всегда 0 — это видно по
  подписи «нет эталона».

**Эталоны при загрузке пресета не теряются.** Записанный звук читается из любой формы:
массив чисел, `Float32Array` (после `JSON` он выглядит как объект `{"0":…,"1":…}`), строка
с числами, прежнее одиночное поле `template`. Если число полос в файле отличается от
текущего (`VISEME_BANDS`), спектр **пересчитывается** линейной интерполяцией до нужного
размера и снова приводится к единичной длине — а не выбрасывается. Поэтому пресет,
сохранённый в браузерной версии другой сборки, открывается в приложении с теми же
эталонами.

**Варианты записи.** У одной виземы может быть сколько угодно эталонов: «о» низким и
высоким голосом — это разный спектр. Плюсик в строке записывает ещё один вариант,
корзина рядом с каждым спектром удаляет конкретный. Значение входа — лучшая похожесть по
всем вариантам, поэтому несколько записей описывают звук надёжнее одной.

Свои звуки («ö» против «о», «ä» против «а»):

- **Добавить визему** — ввести подпись; имя входа получится латиницей (`ö` → `o_umlaut`,
  `ы` → `y`, `о` → `o`), потому что имя попадает в выражение скрипта;
- подпись и имя можно переименовать, визему — удалить (включая базовые `a`, `e`, `i`, `o`, `u`);
- поле имени входа принимает только `a–z`, `0–9` и `_`: `ö` в него просто не набирается,
  подпись при этом остаётся «ö»;
- дубликат имени получает суффикс `_2`, `_3`: два «о» в одном модуле не конфликтуют;
- в скрипте визема читается как `<имя модуля>.<имя виземы>`: `mouth.a`, `mouth.o_umlaut`.

Стартовый набор нового модуля — `a`, `e`, `i`, `o`, `u` **без эталонов**: их надо
записать (или удалить и добавить свои).

**Нормализовать итог** (включено по умолчанию): значения делятся на их сумму, чтобы
морфинг не выходил за границы — `0.8` и `0.8` превращаются в `0.5` и `0.5`. Нули нулями и
остаются; в тишине normalization ничего не «оживляет».

## Клавиатура и мышь

Оба модуля дают обычные входы — их можно выключать по одному, читать в скриптах и
складывать в глобальные переменные.

**Keyboard** — один модуль на группу клавиш: клавиша добавляется нажатием (ловим
следующее `keydown`), имя входа латиницей. `board.space` = 1, пока клавиша держится.
Удобно, когда клавиш несколько и они про одно: управление сценой, отладка.

**Key** — один модуль на одну клавишу, зато с тремя значениями:

| Вход | Что это |
|---|---|
| `down` | 1, пока нажата |
| `hold` | секунды удержания, 0 сразу после отпускания (сбрасывается) |
| `hits` | сколько раз нажали с запуска (автоповтор не считается) |

Полоска `hold` — только отрисовка: значение входа всегда в секундах. Границы ползунка
задаются в шаблоне модуля (`meterFrom`/`meterTo`, по умолчанию 0…2 с) и на само значение
не влияют — `hold` можно читать в скрипте как есть, без пересчёта.

`hits` даёт переключатели без состояния в скрипте: `toggle = hits % 2` (с остатком от
деления) или просто «каждое нажатие — шаг анимации». Кнопка **Стоп** обнуляет счётчики:
после остановки анимации отсчёт начинается заново, а не продолжается с прежнего числа.

Бинд клавиши можно **очистить** (мусорка рядом с полем): пока клавиша не назначена, все
три входа нулевые, а в поле видна подсказка «не задана». `Down`/`hold`/`hits` не
исчезают — на них можно ссылаться в скрипте заранее.

**Mouse** — курсор и кнопки:

| Вход | Что это |
|---|---|
| `x`, `y` | позиция курсора внутри области, 0…1 (0 — левый/верхний край) |
| `px`, `py` | позиция курсора в пикселях внутри области (вне её — отрицательная) |
| `dx`, `dy` | смещение за кадр **в пикселях** |
| `left`, `right`, `middle` | кнопки, 0/1 |
| `wheel` | колесо за кадр: **целые щелчки**, −20…20 (один щелчок = 1) |
| доп. кнопки | `back`, `forward`, `button7`… — по одной на добавленную кнопку |

**Дополнительные кнопки** (4-я, 5-я, боковые) добавляются как клавиши в `keyboard`:
нажать «Добавить кнопку» и нажать саму кнопку мыши — модуль запомнит её. У каждой кнопки
есть подпись (правится) и имя входа (латиница, `[a-z0-9_]`), которое читается в скрипте:
`event press() { mouse.back.up }`. Имя не может повторяться — второй `back` станет `back_2`.
Мусорка удаляет кнопку вместе с её входом.

Поле **Область курсора** — тоже свойство экземпляра: `Монитор` (по умолчанию — весь экран,
с выбором какого именно монитора), `Окно приложения` (только окно YappyTuberPlus) или
`Сцена` (холст пресета). От неё зависят `x`/`y`/`px`/`py`; `dx`/`dy` — всегда пиксели
экрана, ведь это сдвиг самого курсора.

**Что работает в браузере, а что в приложении.** Курсор за пределами окна умеет
читать только нативное окно (Windows, глобальный хук): в браузере `x`/`y`/`px`/`py`
обновляются, пока мышь над окном, и замирают на последнем значении, когда она ушла
на другой монитор или в другую программу. Поэтому «Монитор» без обрезки — это
приложение; в браузере та же настройка работает как «окно» с экранными координатами.

Поле **Инвертировать Y** — по умолчанию `y` растёт вниз (как на экране), с ним — вверх
(как в 3D). Ось X не меняется, `px`/`py` тоже: это пиксели, а не доля области; `dy`
переворачивается вместе с `y`.

**Колесо — только целые щелчки.** Прокрутка копится между кадрами: один щелчок
(около `100` пикселей `deltaY`) — это `1`, а дробный остаток не показывается как
«0,4 щелчка», а переходит в следующий кадр. Поэтому быстрая прокрутка тачпадом не
теряется, а в скрипте никогда не бывает половинок. За один кадр отдаётся не больше
`±20`, чтобы мусор в событиях не сдвинул формулу на сотни.

```text
wheelUp   = mouse.wheel > 0
zoom      = clamp(zoom + mouse.wheel * 0.05, 0.5, 2)
rotation  = rotation + mouse.wheel * 5      # 5° за щелчок
```

Где ловятся события:

- **браузер** — `window` при фокусе окна: `keydown`/`keyup`, `mousemove`, кнопки, `wheel`;
- **нативное окно (Windows)** — глобальный хук `rdev` в Rust: клавиши и мышь ловятся,
  даже когда окно не в фокусе, и при этом **ничего не перехватывается** — клавиша
  продолжает работать в других программах. События приходят как `yappy://pointer`;
- пока фокус в поле ввода (редактор скрипта, имя модуля), клавиши ригу не принадлежат —
  набор текста не дёргает модель;
- потеря фокуса окна отпускает все клавиши: зажатой ничего не остаётся.

Важно: клавиши ловятся по `event.code`, а не по символу, поэтому раскладка не важна:
`KeyA` — это физическая A на любом языке.

## Внешний источник

Модуль «Внешний источник» (`kind: "external"`) превращает сообщения из сети во входы
без единой строки кода: таблица отображения говорит, какое поле JSON становится каким
входом. Один шаблон закрывает мосты пульсомеров, игр, OSC-переходников и ботов.

1. Добавьте модуль, выберите **транспорт** и задайте **адрес** — например
   `ws://127.0.0.1:17801/inputs`.
2. Заполните **таблицу отображения**: `вход`, `поле JSON` (`$.heart_rate`), подпись,
   границы и «длительность» в миллисекундах.
3. Строка таблицы сразу становится входом: в скрипте это `<модуль>.<вход>`.

| Транспорт | Где работает | Адрес |
|---|---|---|
| WebSocket | окно и браузер | `ws://127.0.0.1:17801/inputs` |
| HTTP-опрос | только приложение | `http://127.0.0.1:17802/state`, пауза опроса в поле «Опрос» |
| SSE-поток | только приложение | `http://127.0.0.1:17802/events` |
| OSC (UDP) | только приложение | `udp://0.0.0.0:9000`, поле — `$["/avatar/parameters/HR"]` |
| Twitch | только приложение | не адрес, а сервис: Client ID, канал и галочки событий |

Нативные транспорты живут в Rust, поэтому не зависят ни от CORS, ни от того, какое
окно в фокусе. В браузере они честно показывают «только в приложении».

Число из источника приходит как есть: баллы — баллами, bits — bits, пульс —
ударами в минуту. Привести его к другой шкале (доля, проценты) — дело скрипта:
`twitch.cheer / 100`. Единственное преобразование в таблице — границы `мин`/`макс`.

Колонка **«длительность»** — сколько миллисекунд вход помнит пришедшее число,
потом ноль. Она нужна событиям: «пришла награда» — это один пакет с ценой, а не
постоянный уровень. Без длительности вход либо мигнул бы на один кадр (и `on
twitch.reward.down` не успел бы сработать), либо залип на последнем числе до
следующего пакета. Для постоянных величин (пульс, яркость) там ноль: значение
живёт до следующего пакета и гаснет только при обрыве связи.

Сверху карточки видно состояние соединения: «подключаюсь», «подключён» (со счётчиком
пакетов), «нет связи». Рядом — кнопка **«Проверить»** (дозвонились ли до адреса) и
**журнал** последних 20 строк: что пришло, что не разобралось и почему. Обрыв даёт нули, а не залипшее последнее значение. Повторный
запуск с новым адресом сначала останавливает прежнее соединение — двух источников с
одним именем не бывает.

Подробности формата и пример моста — [`MODULES-DEV.md`](MODULES-DEV.md), §9.

## Пульсометр

Готовый модуль из палитры: входы `hr` (ударов в минуту) и `beat` (флаг с удержанием
200 мс). Чтобы он ожил, запустите мост двойным кликом:

```bat
pulse-bridge.bat        :: Windows
./pulse-bridge.sh       :: Linux/macOS
```

Мост отдаёт `ws://127.0.0.1:17801/inputs` и `http://127.0.0.1:17801/state`; без
железа он работает тренажёром — пульс гуляет 60…110, удары идут по частоте. Для
ровного пульса: `pulse-bridge.bat --hr 90`. Зависимостей нет: кроме Node.js ничего
ставить не нужно.

Свой пульс из BLE/serial переводится в тот же JSON маленьким скриптом, а если
устройство умеет OSC (VRChat и HR-приложения) — включайте транспорт OSC и пишите
поле как `$["/avatar/parameters/HR"]`.

## Twitch

Отдельного вида модуля у Twitch нет: это тот же «Внешний источник» с транспортом
Twitch, поэтому награды и bits настраиваются такой же таблицей. Готовый шаблон лежит
в палитре — **Twitch** — и уже умеет три вещи:

| Вход | Что это | Сколько живёт |
|---|---|---|
| `chat` | счётчик сообщений чата | растёт |
| `reward` | сколько баллов стоил искуплённый предмет | 3 с |
| `cheer` | сколько bits прислали | 2,5 с |
| `follow` | 1 после нового фоллова | 4 с |

Порядок:

1. Вставьте **Client ID** приложения Twitch — где его взять, пошагово ниже.
   Рядом с полем в карточке есть ссылка **«dev.twitch.tv/console/apps»**: клик
   открывает консоль разработчика в браузере (в приложении — в системе, а не в
   окне студии, поэтому рабочее окно никуда не денется). Это не секрет, поэтому
   Client ID едет вместе с пресетом.
2. Укажите **канал** — логин из адреса `twitch.tv/имя`.
3. Нажмите **Войти в Twitch**: приложение покажет код и ссылку активации. Код вводится
   на сайте Twitch, окно само дожмёт вход.
4. Отметьте галочками нужные **события** — они сразу появляются во «Входах».
5. Если нужны команды и награды — заведите их списком в той же карточке.

**Команды чата.** Пишете `dance` — появляется вход `cmd_dance`: единица на 3 секунды
после `!dance`. Регистр не важен (`!Dance` тоже), русские команды работают
(`!танец` → `cmd_tanec`).

**Награды по именам.** Пишете название награды как в Twitch — «Смена аватара» —
появляется `redeem_smena_avatara`: единица на 5 секунд, когда эту награду искупили.
Это позволяет различать награды между собой, а не смотреть только на стоимость.

**Текст сообщений** виден в «Входах» (блок «Последние сообщения») и в журнале
источника. Память чата настраивается двумя числами в карточке модуля:
«Хранить» — сколько последних строк (по умолчанию 12) и «Хранить, с» — сколько
секунд живёт сообщение (по умолчанию 300, `0` — только по количеству). В тихом
чате старые строки пропадают сами, а не висят до следующего сообщения. Там же
переключатель «Автор в панели».

В скрипте тот же чат читается строкой, со смещением по истории:

```text
event message() { twitch.chat.change }                       // новое сообщение
on message {
  text = twitch.chat.user + ": " + twitch.chat.message       // последнее сообщение
}
text = twitch.chat.message(-1)       // предыдущее
text = twitch.chat.user(-1)          // его автор
```

Пределы входа тоже читаются: `twitch.reward.max`, `twitch.chat.min`,
`twitch.chat.label`. Это позволяет считать долю от границы без второго числа в
скрипте — например, полосу «сколько баллов стоила награда из миллиона».

#### Где взять Client ID

1. Откройте консоль разработчика: **`dev.twitch.tv/console/apps`** (в приложении —
   та же ссылка в карточке модуля, рядом с полем Client ID) → войдите тем
   аккаунтом Twitch, с которого стримите.
2. **Applications** → **Register Your Application**.
3. Заполните:
   - **Name** — любое уникальное имя (например, `YappyTuberPlus`);
   - **OAuth Redirect URL** — `http://localhost` и нажмите **Add** (для входа по коду
     адрес не используется, но консоль его требует);
   - **Category** — любая, например *Application Integration*;
   - **Client Type** — **Public** (см. ниже);
   - галочка «I'm not a robot» → **Create**.
4. В списке **Developer Applications** нажмите **Manage** — сверху будет
   **Client ID**: строка из 30 латинских букв и цифр. Скопируйте её в поле
   **Client ID** в карточке модуля.

**Тип приложения — Public, и это важно.** Вход по коду не требует Client Secret, но
работает без него только у приложений типа **Public**. Тип выбирается при создании и
**не меняется потом**: если выбрать *Confidential*, Twitch будет требовать секрет,
а секрет нельзя класть ни в пресет, ни в приложение. Если уже создали не тот тип —
зарегистрируйте новое приложение.

Client Secret для этого модуля **не нужен**. Не вставляйте его никуда: он не нужен
приложению и не должен попадать в пресет или скриншоты.

**Если Twitch отвечает 400** (`SubscriptionCondition.broadcaster_user_id`): значит,
в условии подписки пустой id канала. Проверьте две вещи — канал записан логином
(`yappy`, без адреса и `@`) и **вход выполнен аккаунтом этого канала**. Кнопка
**«Проверить»** скажет прямо: «канал найден, но вход выполнен как «другой_логин»».

Токен хранится в профиле окна и в пресет не попадает; кнопка **Выйти** его забывает.
Права доступа приложение просит ровно те, что нужны выбранным событиям. Если Twitch
отказал в праве, это видно в статусе карточки («нет права …»), а не молчанием.

В скрипте — как обычные входы: `twitch.reward`, `twitch.cheer`, `twitch.follow`, а текст
чата — `twitch.chat.message`. Активность входа считается по отметкам событий:
`twitch.reward.sum(10) >= 80` — сумма бит наград за 10 секунд, `twitch.chat.count(5) > 10` —
сколько сообщений было за 5 секунд. Подробности (какие события есть, как устроены условия
строк) — в [`MODULES-DEV.md`](MODULES-DEV.md), §9.5.

## Пресеты: одежда и эмоции без кода

Пресет — это вариант образа: летний костюм, зимняя шапка, злая эмоция. Модуль
**«Пресеты»** превращает список подписей в рабочую систему: переменную, константы,
события и условия видимости. Писать в скрипте ничего не нужно.

Порядок действий:

1. Добавьте модуль «Пресеты» в палитре и переименуйте его, если нужно (`presets_1`).
2. В карточке модуля перечислите пресеты. Подпись любая — «Летний костюм»; имя для скрипта
   (`letnii_kostyum`) модуль выведет сам, его можно поправить.
3. Оставьте галочку **«Искать среди наград»**, если пресет должен включаться наградой
   канала. Выберите **модули наград** (обычно `twitch`) и **префиксы** — по умолчанию
   `redeem`. Модуль ищет вход `twitch.redeem_<имяпресета>`: создайте в Twitch-модуле награду
   с таким же именем, и всё свяжется само. Если вход не найден, карточка честно скажет,
   какого имени ждёт.
4. Выберите объект и откройте вкладку **«Поведение»** → раздел **«Пресеты»**. Отметьте
   пресеты, при которых объект виден: режим «только при» или «кроме». Куртка не появится
   летом, а шапка — зимой.

Что появляется в скрипте:

```text
preset == summer                 # имя пресета читается как число (константа)
preset == presets_1_summer       # полное имя, если модулей пресетов несколько
on presets_1.summer.up { … }     # событие «пресет включён» (для ручных сюжетов)
```

Переменная (`preset`) и события создаются модулем: в глобальном скрипте это управляемый
блок, помеченный комментариями `# ── пресеты: … ──`. Значение `-1` значит «пресет не
выбран»: так удобно проверять `preset == -1` до первой награды.

Кружок слева от пресета в карточке — **предпросмотр**: пресет включается в редакторе, чтобы
примерить образ, не искупая награду. В эфир это не уходит.

## События поверх любых входов

Модуль даёт числа, а событие объявляет сам автор сцены: условие — в `event`, действия — в
`on`. Блок живёт и в глобальном скрипте, и в скрипте объекта:

```text
event click() { mouse.left.up }              # нажатие: сигнал вырос
on click { a = !a }

event speak() { mic.talking > 0.2 in 500 }   # речь дольше 0,5 с: длительность — оператор in
on speak { mouth.open = 1 }

on start { a = 0 }                           # первый кадр после запуска и после «Стоп»
```

`on start` — встроенное событие первого кадра. Прошлый кадр доступен как `state.имя`, поэтому
переключатель — одна строка: `a = !a`. Подробнее — в [`EVENTS.md`](EVENTS.md) и в README,
раздел «Скрипты: параметры, чужие объекты, события».

В панели «Входы» у каждого модуля есть кнопка **«действия»**: она показывает готовые блоки
событий для его входов (клик вставляет блок в текущий скрипт). Рядом две иконки:

- **перейти к модулю (↗)** — открывает вкладку **«Модули»** на этом экземпляре: карточка
  раскрывается, прокручивается в видимую часть и коротко подсвечивается (поиск при переходе
  сбрасывается, если он прятал модуль);
- **удалить** — убирает экземпляр модуля из сцены (Ctrl+Z возвращает).

**Сброс настроек экземпляра** живёт в карточке модуля (вкладка «Модули») — иконка ↻ рядом с
«дублировать». Она заново читает `public/modules/<id>.json` и возвращает поля шаблона,
включённость входов, списки состояний, визем, клавиш и кнопок. Действие спрашивает
подтверждение: вместе с полями пропадают записи визем и калибровки, вернуть их нельзя.
Имя, тип, включённость и источник (микрофон/ползунок) остаются.

## Входы можно выключать по одному

У каждого входа в карточке модуля есть тумблер. Выключенный вход:

- не считается (у `Loudness` не попадает в анализ, у ручных — нет ползунка);
- **не уходит в кадр вовсе**. Если скрипт его всё-таки читает, ядро честно покажет
  «неизвестное имя» в панели диагностики — обратной совместимости здесь не делаем.

## Вкладки

- **Модули** — сверху поиск по включённым экземплярам (по имени, шаблону и именам
  входов), ниже карточки: включение тумблером, имя, шаблон, источник, поля настроек
  сеткой «поле — значение» (колонки подстраиваются под ширину панели), входы тумблерами,
  дублировать, свернуть и удалить. Внизу — **«Добавить модуль»**: палитра с поиском по
  библиотеке, Enter добавляет первый найденный шаблон, Esc закрывает.
- **Входы** — живые значения по каждому включённому модулю с полными именами. Уровни
  показываются индикаторами, ручные — ползунками (или кнопками 0/1 в режиме `flag`).
  У визем в строке значения есть микрофончик калибровки и живой спектр во время записи;
  клавиши и мышь видно как индикаторы (0/1 и уровни).
  Заголовок группы сворачивает её строки. Выключенные входы и модули подписаны, но
  неактивны.

## Микрофоны

- Отдельной кнопки «включить микрофон» больше нет: звук поднимается сам, как только в
  модели есть включённый микрофонный модуль (в приложении — системный запрос WebView2 на
  `tauri.localhost`, это нормально).
- `AudioContext` создаётся при старте и «пробуждается» первым же нажатием в приложении:
  иначе браузер и WebView2 оставляют его в `suspended`, анализатор возвращает нули и
  «звука нет» без ошибок.
- Выключение модуля отцепляет только его поток, остальные продолжают работать.
- Устройство выбирается отдельно для каждого экземпляра. Два модуля с одним устройством
  делят поток — микрофон не открывается дважды.
- По умолчанию обработка браузера выключена (сырой сигнал): на части драйверов
  эхоподавление и шумоподавление глушат вход. Галочка «Шумоподавление» включает её обратно.
- Ошибки микрофона показываются в карточке модуля (вкладка «Входы») и в панели модулей.
- Если речь не ловится, уменьшите порог (например, −55 дБ) или поднимите усиление.

## Хранение и миграция

Модули хранятся в пресете (`modules`): имя, шаблон, включённость, источник, настройки и
список выключенных входов. Входы в ядро передаются плоским словарём `values`
(`{"mic.talking": 1, …}`) плюс `signals` для канала `signal.*`.

При открытии пресета имена из старых версий переписываются автоматически:
`talking` → `mic.talking`, `viseme_a` → `viseme.a`, `signal.blink` и `manual.blink` →
`auto.blink`. Если нужного модуля в списке нет, он добавляется.

Если при открытии пресета набор модулей отличается от текущего, показывается диалог:

- **Применить** — входы и настройки берутся из пресета (текущий список заменяется целиком);
- **Оставить как есть** — остаётся текущий набор модулей сессии;
- **Отключить все** — пресет открывается без модулей: все входы дают нули, риг рисуется
  по базовой позе и глобальным переменным.

## Сборка ядра

Имена входов резолвит Rust: `values` — произвольный словарь, а `имя.поле` распознаётся как
вход, если такого ключа нет среди обычных полей. После правок в `crates/rig-core`
пересоберите ядро:

```bash
npm run build:wasm        # → public/rig_core.wasm
```

Нативная сборка (`npm run tauri build`) компилирует Rust сама, отдельный шаг не нужен.
