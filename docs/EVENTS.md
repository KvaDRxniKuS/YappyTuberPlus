# События и время

Здесь описано, как в скрипте объявляются события и как выражается длительность.
Документ заменяет прежние `trigger`, `on модуль.вход.тип` и `hold`/`relax`:
этих форм в языке больше нет.

Смысл переработки: модуль даёт **числа**, а не десяток готовых событий на каждый
вход. Событие пишет пользователь — одно, с тем условием, которое ему нужно.

## 1. Что дают модули

Модуль отдаёт значения входов и паспорт входа (`label`, `min`, `max`, `step`,
`kind`). Никаких «событий модуля» нет: панель настроек не содержит списка
триггеров, а `on mouse.left.down` больше не пишется.

У каждого входа в выражении доступны поля:

| Поле | Значение |
|---|---|
| `<вход>` | число входа в этом кадре |
| `.down` | 1, если значение стало больше нуля в этом кадре, иначе 0 |
| `.up` | 1, если значение стало нулём в этом кадре, иначе 0 |
| `.change` | 1, если значение изменилось с прошлого кадра, иначе 0 |
| `.min` `.max` `.step` `.label` `.kind` | паспорт входа (только чтение) |
| `.count(с)` `.sum(с)` `.avg(с)` | активность за последние `с` секунд (внешние источники) |

`.down`/`.up`/`.change` — **обычные числа 0/1**, а не отдельный вид блока. Порог
у них нулевой: для громкости пишется явное условие (`mic.talking > 0.2`), а не
`.down` — так видно, от чего считается событие.

## 2. Длительность: операторы `in` и `out`

Любое логическое выражение может получить требование по времени. Это постфиксный
оператор, он применяется к тому, что стоит слева, и не зависит от типа условия:

```text
<условие> in <время>    — условие непрерывно истинно уже столько
<условие> out <время>   — условие непрерывно ложно уже столько
```

```text
mic.talking > 0.2 in 100          // речь дольше 100 мс
mic.talking > 0.2 out 600         // тишина дольше 0.6 с
(twitch.chat.count(5) > 10 && mic.db > -30) in 2s
```

Время — число миллисекунд; допустимы суффиксы `ms` и `s`: `in 100`, `in 100ms`,
`in 0.5s`. `in 0` — «условие верно прямо сейчас», без задержки.

Приоритет: `in`/`out` связывают крепче, чем `&&` и `||`, и слабее сравнений.
Поэтому `a > 1 && b > 2 in 100` — это `a > 1 && (b > 2 in 100)`, а чтобы
взять по времени всё условие, ставятся скобки: `(a > 1 && b > 2) in 100`.
Два оператора подряд (`(A in 100) out 50`) — ошибка разбора: это почти всегда
означает не то, что задумано.

Прежние `hold(0.5)` и `relax(0.6)` выражаются так:

| Было | Стало |
|---|---|
| `on mic.talking.hold(0.5)` | `event speak() { mic.talking > 0.2 in 500 }` |
| `on mic.talking.relax(0.6)` | `event silence() { mic.talking > 0.2 out 600 }` |
| `on mouse.left.down` | `event click() { mouse.left.down }` |
| `trigger kick = mouse.left.down` | `event kick() { mouse.left.down }` |

## 3. Объявление события

```text
event имя (переменная = выражение, … ; пауза) {
  условие
}
```

- Скобки с переменными и паузой не обязательны: `event click() { mouse.left.down }`.
- Переменные — обычные имена; выражение справа считается **в условии каждый кадр**
  (это живой алиас: `loud` — то же, что `mic.loudness`, но короче).
- Пауза (`cd`, мс) — через сколько снова сработать, **если условие всё ещё
  истинно**. `0` — каждый кадр, пока условие истинно. Без паузы (`;` нет) — тоже 0.
- Тело — одно логическое выражение. Присваиваний и команд внутри `event` нет:
  действия живут в `on`.

```text
event clap (loud = mic.loudness, db = mic.db ; 5000) {
  twitch.reward.sum(10) >= 80 || twitch.chat.count(5) > 200
}
```

Срабатывание: в кадр, когда условие стало истинным, и дальше — каждые `cd` мс,
пока оно остаётся истинным. Как только условие стало ложным, событие взводится
заново и следующий фронт срабатывает сразу.

## 4. Подписка и вызов

```text
on clap {
  mouth.open = loud > 0.5
  rotation = db
}
```

- `on <имя>` — обработчик. Переменные события (`loud`, `db`) видны внутри как
  **снимок** значений на момент срабатывания: обработчик не должен читать уже
  изменившийся микрофон.
- Один `event` и один `on` на область видимости. Второе объявление того же имени
  в той же области — ошибка, подчёркиваются **обе** строки: и новая, и прежняя.
- `on <имя>` без `event` — ошибка «событие не объявлено».
- `on start { … }` остаётся: это не событие, а первый кадр.

```text
call clap(0.9, -12)
```

- Вызов игнорирует условие и паузу: тело `on clap` выполняется сразу, в этом же
  кадре. Аргументы — по порядку переменных; без аргументов берутся значения по
  умолчанию из объявления.
- Глубина вложенности ограничена 8; при рекурсии — диагностика с именем события.

## 5. Области видимости

- `event`, объявленный в глобальном скрипте, виден всем объектам: объект может
  подписаться (`on clap`) и вызвать (`call clap()`), но не переобъявить.
- `event`, объявленный в скрипте объекта, локален для этого объекта. Глобальный
  скрипт на него подписаться не может — ошибка «событие объявлено в другом
  скрипте».
- Переменные события живут только в его области: в другом событии и в формулах
  объекта их нет.
- Имя переменной события не может совпадать с параметром объекта (`x`, `y`,
  `rotation`, `sizeX`, …) — ошибка с подсветкой обеих строк. Параметры объекта —
  это те же переменные, просто их читает сам объект; перекрывать их молча нельзя.

## 6. Время в ядре

- Часы одни: ядро ведёт `time` в миллисекундах от запуска (сброс по «Стоп»).
- Для каждого узла `in`/`out` и для каждого события хранится состояние:
  момент, с которого условие выполняется, и момент последнего срабатывания.
- Состояние сбрасывается вместе с часами: после «Стоп» и при смене пресета.
- Время не зависит от FPS: считается по часам кадра, а не по числу кадров.

## 7. Подсказки в редакторе

Подсказки синтаксиса живут **в самом редакторе**, а не строкой внизу:

- у курсора всплывает подсказка по текущему месту — тип условия, переменные
  события, допустимые поля входа;
- автодополнение после `event` предлагает имена входов и операторы `in`/`out`;
- после `on` — только объявленные события этой области, после `call` — их
  переменные;
- ошибки разбора подсвечивают диапазон, а не только пишут текст.

Нижняя панель остаётся библиотекой блоков и функций (её перетаскивают в скрипт),
но строки-подсказки «что здесь написать» в ней больше нет.

## 8. Что удаляется

| Удаляется | Почему |
|---|---|
| `on модуль.вход.down` | событие пишется явно: `event click() { mouse.left.down }` |
| `.hold(сек)`, `.relax(сек)` | заменены на `in`/`out` у любого условия |
| `trigger имя = …` | заменён на `event имя() { … }` |
| список событий в карточке модуля | модуль даёт числа, события пишет пользователь |

Совместимости со старыми пресетами нет: скрипт со старым заголовком получает
ошибку с подсказкой новой формы.
